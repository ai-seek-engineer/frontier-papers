## 1. Model Inference

【Title】Lachesis: Lifetime-Aware KV Cache Placement for Agent Serving across HBM and High-Bandwidth Flash

- 一句话总结：Agent 多轮 KV 不该按到达顺序灌进高带宽闪存，应按 harness 决定的生命周期把短命段留在 HBM，减少 HBF 写入。
- 核心贡献（2-3点）：
  - 把 agent KV 寿命拆成时间、结构和 worker 间三条轴，放置策略由 harness 语义驱动，而不是通用 LRU。
  - 写时按寿命选 HBM/HBF，段不再被读就释放；不改模型权重。
  - Trace 仿真：相对 HBM-first，HBF 寿命 1.19–3.13×，对应 3.3–12.2 device-years；满载 7×24 多 agent trace 仍能撑过 5 年质保。
- 工程价值：直接打 agent serving 的容量墙。HBF 读带宽接近 HBM 但写耐久有限，这层放在 harness 和 engine 之间，比再做一层 token eviction 更贴近生产。局限是仿真、依赖 HBF 硬件假设，且要 harness 暴露段生命周期。
- 是否值得读：强烈推荐
- Relevance Score：5
- Link：https://arxiv.org/abs/2610.08378

【Title】DySCo: Dynamic Sharding for Collaborative Edge-Cloud LLM Inference with Depth-Synchronized Batching

- 一句话总结：边云按层切分后，不同切点的请求无法常规 batch；把它们推到最深公共切点再合 suffix，才能吃到云侧 batch。
- 核心贡献（2-3点）：
  - KV 留在本地，dyForward 在已驻留 shard 上跑可配置连续层，避免反复加载权重。
  - Depth-synchronized batching：异构请求先对齐到最深 cut，只 batch 公共 suffix。
  - 平均并发 8 时，吞吐相对 FIFO +275%，相对 exact-match batching +48%，相对 round-robin +79%；测到空闲间隙会给后续 GPU forward 额外加最多约 25 ms/step。
- 工程价值：对边云/拆分推理有用，对纯数据中心 serving 迁移性一般。Artifact 公开。适合做异构切分调度，不是 KV 量化或 speculative decoding 的替代。
- 是否值得读：可选
- Relevance Score：3
- Link：https://arxiv.org/abs/2610.08268

## 2. AI Infra / 分布式训练

【Title】NeMo-DCR: Bit-Exact Delta-Compressed Refit for Scalable Agentic RL at Trillion-Parameter Scale

- 一句话总结：Agentic RL 的训练/rollout 分离后，跨集群 weight sync 是主瓶颈；只传变化且 bit-exact，1T refit 从 87.5 分钟降到约 150 秒。
- 核心贡献（2-3点）：
  - BF16 训练实测约 1% 权重每步改值。用仿射映射把训练 shard 变化投影到 checkpoint 坐标，XOR mask 保 bit-exact，其余走 overwrite。
  - 接收端原地应用，失败重试覆盖半写，joint commit 把策略和 baseline 绑到下一轮 delta。不依赖跨集群 collective。
  - 3%/5% 变化率下，30B–1T 比全量 checkpoint 传输快 12–40×。代码在 NVIDIA NeMo RL PR #2444。
- 工程价值：这是今天最可落地的系统论文。Rollout 集群和训练集群跨 region 时，refit 往往比 step 本身贵。Bit-exact 避开了“近似同步导致 rollout 分布漂”的坑。前提是变化率真的低；大步更新或频繁重初始化会吃掉收益。
- 是否值得读：强烈推荐
- Relevance Score：5
- Link：https://arxiv.org/abs/2610.08430

【Title】TRANSIT: Transparent Scale-in for Multi-Node LLM Training

- 一句话总结：用户态拦截把 CPU DRAM 当 GPU 内存扩展，不改框架/调度/驱动，用更少 GPU 维持多机训练吞吐。
- 核心贡献（2-3点）：
  - 零拷贝 CPU–GPU 路径；对应用透明。
  - 最多 64×H100、dense 和 MoE、多种并行、RoCE。相对 TorchTitan / ZeRO-Offload / ZeRO-Infinity，每卡吞吐最高 +68% / +59% / +42%。
  - GPU 减半仍保住 >90% 每卡吞吐；通信受限场景每卡吞吐最高 +35%，节点间流量最多降 33%。
- 工程价值：适合 GPU 配额被砍、不想改 Megatron/TorchTitan 的场景。不是新并行算法，是 offload 数据通路优化。要核对拦截层和 NCCL/通信重叠是否在你的栈上成立。
- 是否值得读：强烈推荐
- Relevance Score：4
- Link：https://arxiv.org/abs/2610.07593

## 3. LLM Agents

【Title】SquidAgent: Parallelize Wisely, Coordinate Efficiently

- 一句话总结：多 agent 并行经常比单 agent 慢，因为重复探索和事后对齐；用 token 预算而不是墙钟估计决定哪一层该 fork。
- 核心贡献（2-3点）：
  - 并行条件：关键路径 + 重探索 + 对齐开销 < 串行成本。LLM 估时长不准，估输出 token 更稳。
  - Worker 从 orchestrator session 直接 fork，去掉重探索；对齐改成预先生成的共享约定块。
  - NeurIPS 2026。相对 Claude Code 平均吞吐 2.2×、墙钟 2.6×；相对最强多 agent 基线吞吐 2.0×。
- 工程价值：可直接进 agent runtime 的调度器，不改模型。Token 预算比 latency 预测更可工程化。收益依赖任务可并行度和 fork 会话的实现成本；纯串行工具链收益有限。
- 是否值得读：强烈推荐
- Relevance Score：4
- Link：https://arxiv.org/abs/2610.08647

【Title】VETTA: Coordinating Turn- and Token-Level Credit Assignment for Multi-Turn LLM Agents

- 一句话总结：多轮 agent 只有稀疏终局奖励时，把 turn 级和 token 级 advantage 放在同一个轻量 critic 里一起更新。
- 核心贡献（2-3点）：
  - 共享 critic 上两个 value head；turn advantage 加响应内中心化的 token residual，再进 PPO。
  - Critic 只留 actor 初始化 checkpoint 的前几层 Transformer，压 value 侧算力。
  - ALFWorld / WebShop：Qwen2.5-1.5B 相对 PPO 成功率 +37.5% / +22.3%；7B 到 95.5% / 76.0%。有代码。
- 工程价值：对 agent RL 训练循环有用，对在线推理无直接加速。轻量 critic 比再训一个同尺寸 value model 更可部署。基准偏模拟环境，迁移到长工具链要再验证。
- 是否值得读：可选
- Relevance Score：4
- Link：https://arxiv.org/abs/2610.08402

## 4. SFT / Alignment

【Title】Rethinking Cross-Tokenizer On-Policy Distillation: From Alignment Coverage to Supervision Reliability

- 一句话总结：跨 tokenizer 的 on-policy distillation 不必追求全词表对齐；严格 1:1 位置上的小词表监督更可靠，扩 span 监督反而掉点。
- 核心贡献（2-3点）：
  - 三组异构 teacher–student、数学和代码。严格对齐位置已经覆盖学生大部分生成 token，共享词表几乎吃掉两侧概率质量。
  - 只在严格位置做学生选出的 top-16 共享词 reverse KL，精度接近全共享词表 OPD，并超过所测跨 tokenizer 基线。
  - 给不匹配 span 加 log-prob MSE 后梯度方向弱或反向，精度下降。
- 工程价值：蒸馏管线可直接减监督带宽和 teacher 前向成本。不是新对齐算法，是把“对齐覆盖越大越好”证伪。对同 tokenizer OPD 增量有限。
- 是否值得读：可选
- Relevance Score：3
- Link：https://arxiv.org/abs/2610.08448

## 5. Reinforcement Learning

本窗口没有独立、可复现、且不是 agent/系统包装的强 RL 算法论文。VETTA 是最接近的策略优化工作，已放在 Agents。Agentic RL 的系统侧由 NeMo-DCR 覆盖。

邻近但超出 48 小时、仍值得单独跟：NCCL M2N（10/5，256 GPU 上 DeepSeek-V3 weight-sync 5.78s→2.77s，https://arxiv.org/abs/2610.07516）；RelayMoE（10/5，环式 dispatch，同显存下训练吞吐最高 2.02×，https://arxiv.org/abs/2610.07333）。

## 今日最值得读 Top 3

1. NeMo-DCR。Agentic RL 真正贵的是跨集群 refit，不是又一个 GRPO 变体。有 bit-exact 语义、1T 量级数字、NeMo RL PR，可直接对照现有 weight sync。
2. Lachesis。Agent 流量把 KV 从“序列内存”变成“有寿命的对象”。HBF/分层存储要上生产前，放置策略比再压 0.5 bit 更关键。
3. SquidAgent。把多 agent 并行变慢拆成重探索和对齐两项可测成本，调度准则用 token 而不是墙钟，能进 runtime，不绑特定模型。

## 今日趋势

推理优化论文仍多，但 48 小时窗口里高质量增量集中在 agent 负载的系统层，而不是又一种 KV 量化。训练侧同样被 agentic RL 拉动：refit、M-to-N reshard、rollout/训练分离。纯 SFT/RLHF 配方当天偏少；对齐侧更像蒸馏监督可靠性诊断。

## 值得跟进的方向

Agentic RL 的 weight-sync 栈。训练 shard、checkpoint 坐标、serving placement 三者不一致，全量 all-gather + broadcast 已经占 step 时间的显著比例（NCCL M2N 报 DeepSeek-V3 RL step 的 29.4%）。Delta refit 和 layout-aware M2N collective 是互补的，不是互相替代。另一条是 agent KV 的寿命感知分层：harness 比 attention score 更知道这段 cache 还会不会被读。
