## 1. Model Inference / 推理优化

【Title】Weave: Fine-Grained Dynamic SM Scheduling in an MoE Megakernel for Compute-Communication Overlap  
（严格说偏 serving kernel / EP overlap，但直接打 decode/prefill 吞吐）

- 一句话总结：MoE EP 层在 routing 完成后按实际通信/计算量，在 persistent megakernel 里动态切 SM，空间配比 + 时序对齐，消灭固定 SM split 和依赖气泡。
- 核心贡献：
  - 首次把 SM 划分做成 per-layer / per-GPU 运行时决策，而不是静态 overlap 模板。
  - megakernel 内轻量 cost model：通信 worker vs 计算 worker 按吞吐比切分，并做时序调度减 idle。
  - 4×H100、6 个主流 MoE：MoE 层几何均值 **2.89×**，端到端 **1.33×**（对 5 个 SOTA）。
- 工程价值：可直接对照 DeepEP / Megatron-EP / 现有 overlap kernel。固定 SM 切分在路由偏斜时必浪费 NVLink 或算力，这条路径对生产 MoE serving 比再挤一点量化更接近“今天就能改 runtime”。
- 是否值得读：强烈推荐  
- Relevance Score：5  
- Link：https://arxiv.org/abs/2609.21483

【Title】D-Quant: Driftable Entropy Coding for KV Cache Quantization

- 一句话总结：KV 旋转+归一化后近似正态，用熵编码吃非均匀分布；再用 drift 把变长码拧成定长 bitstream，保证 attention kernel 规则访存、可并行反量化。
- 核心贡献：
  - 指出固定位宽在低 bit 时量化级数指数塌缩，且浪费中心质量点。
  - 用 drift 解决熵编码与 GPU kernel 规则 stride 的结构性冲突。
- 工程价值：方向对（带宽/容量双压），但落地取决于 kernel 是否真能和 FlashAttention/PagedAttention 对齐。值得看设计，别假设下周能进 vLLM。
- 是否值得读：可选  
- Relevance Score：4  
- Link：https://arxiv.org/abs/2609.19880

## 2. AI Infra / 分布式 / 系统

【Title】DLB: Distributed Load Balancing at Scale for Generative AI Inference

- 一句话总结：Google 生产级分布式 LB：P2P probing + 在线延迟模型，处理异构硬件/异构模型/多阶段生成；22 个月线上、百万级 QPS。
- 核心贡献：
  - 针对生成式异构服务时间，不用靠过配保 SLO。
  - 路由算法有稳定性/全局性能保证，不只启发式。
  - 生产迁移：中位延迟 **-17%**，p95 **-13%**。
- 工程价值：这是“集群调度”而不是单卡 kernel。对多模型混部、PD 分离、跨机房容量可见性极有参考价值。代码大概率不会开源，读设计决策和失败模式即可。
- 是否值得读：强烈推荐  
- Relevance Score：5  
- Link：https://arxiv.org/abs/2609.21079

【Title】PrefixBench-H100: Characterizing Prefix Reuse and Time-to-First-Token in H100 LLM Serving

- 一句话总结：在单卡 H100 上把 prefix/KV reuse 的有效工作区测清楚：什么时候显著降 TTFT，什么时候 cache 压力把收益吃光。
- 核心贡献：
  - 合成 + chat/RAG 负载，对齐 vLLM / TensorRT-LLM。
  - 结论：cache 有效性对并发和输出长度不敏感；跨 runtime 差异主要在调度层，不在 cache 算法本身。
- 工程价值：不是新算法，但是生产调参地图。做 prefix cache / radix tree 的人应先读这个再改策略。
- 是否值得读：可选  
- Relevance Score：3  
- Link：https://arxiv.org/abs/2609.19657

## 3. LLM Agents（系统设计向）

【Title】AgentKV: Phase-Aware KV Eviction for Agentic LLMs

- 一句话总结：Agent 的 think/act/tool 查询子空间不同，用“最近 token 代表未来 attention”会系统性丢掉下一阶段需要的 key；按 phase 维护 query buffer 再并集打分。
- 核心贡献：
  - 用 principal-angle 证明 phase 查询子空间可分。
  - 持久多轮 serving：压缩 KV 跨 turn 携带 + 在线 compact page。
  - 相对 R-KV / Tri-attention 任务分 +5.3~5.5；相对 full-KV SGLang 输出吞吐最高 **1.80×**。有代码。
- 工程价值：Agent serving 的 KV 策略不能直接复用 chatbot eviction。可挂到 SGLang 路径上验证。
- 是否值得读：强烈推荐  
- Relevance Score：5  
- Link：https://arxiv.org/abs/2609.14872

【Title】UnifiedPlayers: Enhance Tool-Integrated Reasoning in Agentic Reinforcement Learning

- 一句话总结：把任务生成、带 Python tool 的多轮执行、可执行 verifier 做成三个协作 Player，用角色奖励在 GRPO 下联合进化，避免静态 verifier / 自洽强化共同错误。
- 核心贡献：
  - 三个角色持续改变彼此训练数据这一协调问题给了可运行方案。
  - 12 个推理基准相对最强基线：数学 ≥+3.5%，通用 ≥+3.9%。
  - 学到的 verifier 对抗检测 84.2%，奖励方差是自洽基线的 2.03×。
- 工程价值：偏训练系统，不是 serving。对自举 tool-agent 数据管线有参考；复现成本高。
- 是否值得读：可选  
- Relevance Score：3  
- Link：https://arxiv.org/abs/2609.20089

## 4. SFT / Alignment / RLHF & RL

【Title】Dual-Axis Policy Optimization for LLM Agents (BATON)

- 一句话总结：把 agent RL 拆成两条轴：轨迹内如何把环境反馈归因到动作，轨迹间如何给完整轨迹分配优化质量；Bayesian 归因 + Trajectory Mass Normalization。
- 核心贡献：
  - 明确 GRPO/GiGPO 类方法把两件不同的事混在一个 advantage 里。
  - ALFWorld / WebShop / SearchQA 上两轴独立增益，组合最强。
- 工程价值：实现增量小（改 advantage / 归一化），比再堆环境更划算。适合已有 agent RL 训练栈的人直接试。
- 是否值得读：可选  
- Relevance Score：4  
- Link：https://arxiv.org/abs/2609.19830

【Title】Compositional Reasoning in Language Models under Reinforcement Learning Post-Training

- 一句话总结：用依赖图把组合推理分层，发现“拆开练不迁移到组合、组合练能回迁到子技能”的不对称。
- 核心贡献：
  - 组合性三级形式化 + 数据结构任务（奖励确定、结构清楚）。
  - 对 RL post-training 该采什么课表给了可证伪结论，不是又一个分数表。
- 工程价值：不直接加速推理；对 RLVR/agent 数据配比有指导。纯研究向。
- 是否值得读：跳过（除非你在做 reasoning RL 课表）  
- Relevance Score：2  
- Link：https://arxiv.org/abs/2609.19465

## 额外值得点名（未占名额）

- **TierKV**（09-18）：端侧预测式多级 KV（exact / low-rank / flash），prefill 最高 17.6×，RAM-KV -12.5~34%。端侧长上下文有用，云端 serving 次要。https://arxiv.org/abs/2609.21172  
- **Fathom**（09-15/18）：offload 后的 per-query bit-plane 扫描深度，1M token decode GPU time 相对 136-bit sparse scan **1.67×**。Agent 长会话 + CPU KV 很对症。https://arxiv.org/abs/2609.17652  
- **HyperParallel-FSDP**（09-21）：Ascend SuperPod 上拓扑感知 FSDP + Muon layout。国产集群训练栈才需要深读。https://arxiv.org/abs/2609.21594

## 今日最值得读 Top 3

1. **Weave** — MoE serving 的真实瓶颈已经从“会不会 overlap”变成“overlap 如何跟路由动态匹配”。有硬核 kernel + 明确加速数字。  
2. **DLB** — 少见的超大规模生成式推理调度生产论文；单卡优化再卷 10%，集群 LB 可能一次吃掉 13–17% 尾延迟。  
3. **AgentKV** — Agent 工作负载正在把 chatbot 时代的 KV eviction 假设打穿，且有 SGLang 路径和吞吐数字。

## 今日趋势观察

- **Inference / KV 仍然是主场**：量化、offload、sparse scan、prefix reuse、phase-aware eviction 同时出现；主线是“长上下文 + agent 多阶段”而不是 chatbot 短对话。  
- **Infra 从单卡 kernel 上收到集群调度**（DLB）和 **MoE megakernel 动态 SM**（Weave）两端。  
- **Agent 论文明显变“系统化”**：KV 生命周期、跨 turn 压缩、自举 verifier，不再只是 prompt 编排。  
- Alignment/SFT 本日工程增量弱，RL 多集中在 agent credit assignment。

## 值得跟进的潜在方向

1. **Phase-/session-aware KV**（AgentKV + Fathom + UNISON 一类）：把 agent loop 的 wait/tool/think 显式写进 cache 策略，而不是复用 recency。  
2. **Routing-aware 动态 overlap**（Weave）：固定 SM split 应被视为技术债。  
3. **熵编码 KV + 定长 kernel 接口**（D-Quant）：算法有空间，缺的是和生产 attention kernel 的真正融合。  
4. **生成式异构服务时间的分布式 LB**：开源栈（vLLM/SGLang 网关）离 Google DLB 的延迟模型还差一整层。
