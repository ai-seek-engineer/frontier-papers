## 1. Inference / KV

### 【Title】QuantMLA: Function-Aligned Dual-Path Quantization for Low-Bit MLA KV Caching
- 一句话总结：针对 DeepSeek 系 MLA 的 content / RoPE 双路 KV，按误差传播分别量化，首次做到双路 INT4（content 可压到 INT2）。
- 核心贡献（2-3点）：
  - 建模双路量化误差：RoPE 路径误差会被放大，content 路径是 matching+aggregation 耦合误差。
  - 路径专用、可离线融合进权重的变换空间，在线零 overhead。
  - 原生低 bit MLA kernel：unpack + dequant 融进 attention。
- 工程价值：直接打 MLA serving 的 cache 墙。128K 物理 cache **3.59×** 压缩；cache-pressure 负载相对 BF16 **5.17×** job 吞吐。DeepSeek-V3/GLM 类 MLA 部署应优先看 kernel 与 layout，而不是再套通用 KVQuant。
- 是否值得读：强烈推荐
- Relevance Score：5
- Link：https://arxiv.org/abs/2609.36760  
  代码：acceptance 后放（目前无可跑仓库）

### 【Title】KV-Kaizen: Learning Context-Adaptive Cache Compression Choices
- 一句话总结：不 evict token，而是用一个 selector 在 prefill 前按 context 选每层的 depth-share / bit-width / latent-rank 组合。
- 核心贡献（2-3点）：
  - 三轴组合（层间共享 cache、降精度、截断低秩 latent），全局 budget、局部自适应。
  - selector 只跑一次，开销在 prefill 前。
  - 14B 上可与 eviction 组合到 decode cache **32×** 更小；7B+ 上 **4×** 压缩无精度掉点；同 cache 体积下，大模型压缩 > 小模型不压缩。
- 工程价值：比“统一 4bit / 统一 evict”更贴近真实混合负载。落地难点是 serving 引擎要支持**异构 per-layer cache layout**（多数 vLLM/SGLang 还不支持动态 rank/share）。适合当作下一阶段 cache policy 的设计输入。
- 是否值得读：强烈推荐
- Relevance Score：5
- Link：https://arxiv.org/abs/2609.37988

## 2. AI Infra / Serving

### 【Title】SPLASH: Switching Parallel Layouts of Attention with Seamless Handoff for LLM Serving
- 一句话总结：请求还在跑时切换 attention 并行布局（TP / DP-attn / CP / 新提出的 DOP），切换开销中位 < 0.51% step。
- 核心贡献（2-3点）：
  - 观察：少 KV head 时，“cache 住哪”和“weight 怎么切”可解耦。
  - Decoupled Ownership Parallelism：weight 按 TP 切、每条请求 cache 单 owner，KV 容量比 DP-attn 高 **27–60%**。
  - 后台搬状态 + batch 边界 handoff；transition-aware scheduler 跟负载走。
- 工程价值：这是今天最“能进生产引擎”的系统文。推理/agent/RL rollout 的 batch 形态会在一次 job 内从“很多短请求”变成“少数超长请求”，固定 layout 是结构性错配。B200 + GLM-5.3：**1.3–1.73×** e2e 吞吐；H200 DeepSeek-V3.2、DCU 上也复现同一套 regime。
- 是否值得读：强烈推荐
- Relevance Score：5
- Link：https://arxiv.org/abs/2609.37626  
  代码：https://github.com/ict-agent/SPLASH-sglang

### 【Title】You Cannot Pick a Provider From the Price List: Market-Aware Routing for Open-Weight LLM Inference
- 一句话总结：开源权重推理市场里，选模型之后还要选 provider；价目表推不出质量/延迟/可用性。
- 核心贡献（2-3点）：
  - 多波次实测：同模型跨 provider 的质量、延迟、可用性、价格解耦；贵的更快，但不保证质量。
  - 任务选择性退化：某部署知识题正常、多步推理崩盘。
  - 简单 measured-map：在质量等价且健康的 provider 里选最便宜的。
- 工程价值：对自建网关/多云路由立刻有用。不要再只做 model-level router；要加 provider health + 任务类型探针。不是 kernel 级优化，但是 serving 控制面的真实缺口。
- 是否值得读：可选
- Relevance Score：3
- Link：https://arxiv.org/abs/2609.37902

## 3. LLM Agents（系统设计）

### 【Title】Thinking Before Thinking: Scaling Agentic Inference Through Meta-Reasoning
- 一句话总结：把长程 agent 的“下一步做什么 / 是否重开 / 何时停”做成显式 controller，worker 只干活。
- 核心贡献（2-3点）：
  - controller 维护压缩 run-state，而不是回放全程历史。
  - ProgramBench：GPT-5.5 **71.5% vs Codex 58.0%**；Opus 4.8 **67.2% vs Claude Code 65.5%**。
  - 其它长程/证明基准相对 Direct Control 平均 +3.6~4.2；小 budget 时 overhead 会伤。
- 工程价值：不是新模型，是 inference harness。对内部 coding agent：把调度从 prompt 堆砌改成“状态压缩 + 预算评估 + dispatch”。artifact-graph 显示 reuse 更高。值得当系统设计参考，不值得当训练论文精读。
- 是否值得读：可选（做 agent 平台则强烈推荐）
- Relevance Score：4
- Link：https://arxiv.org/abs/2609.38147

## 4. SFT / Alignment / RLHF & RL

### 【Title】RLTL;DR: Self-improvement by Internalizing Self-generated Feedback
- 一句话总结：Pass@128=0 的难题上，失败后让模型写一句 TL;DR insight，并把 task→insight 内化进权重；eval 时不需要 insight。
- 核心贡献（2-3点）：
  - GRPO 在过滤后的 tool/coding 集上卡在 Pass@1 ≈ 0–1%；本方法训练时 14–31%，**eval 无 insight 仍 12–13%**。
  - 消融：只 SFT (task, insight) 就能接近完整 RLTL;DR。
  - 关键不是“多采样成功轨迹”，而是把失败信号压成可反传的短 insight。
- 工程价值：对 RLVR 数据飞轮有直接含义——难题上成功轨迹稀疏时，别死等 Pass@k，改沉淀失败摘要。实现成本低（附录给了 judge prompt 与复现步骤）。Apple 出品，代码未放。
- 是否值得读：强烈推荐（做 post-training）
- Relevance Score：4
- Link：https://arxiv.org/abs/2609.37633

### 【Title】DistFlow: A Fully Distributed RL Framework for Scalable and Efficient LLM Post-Training
- 一句话总结：LLM RL 从单节点调度改成多 controller + 去中心 Data Coordinator，512 GPU 近线性，吞吐最高 **2.63×** SOTA。
- 核心贡献（2-3点）：
  - 解开 control dispatch 与 data path。
  - 本地 cache + 负载均衡 + 双缓冲抗 straggler。
  - DAG task scheduler，细粒度异步执行。
- 工程价值：这是 post-training infra，不是算法。如果你在扩 GRPO/PPO 到百卡以上，中心 master 已经是瓶颈，这篇比再调 advantage 估计更有用。PMLR ICML’26 版本，9/29 露出。
- 是否值得读：强烈推荐（训 RL 的 infra 组）
- Relevance Score：4
- Link：https://proceedings.mlr.press/v306/wang26jl.html

### 【Title】Periodic Weak Spots: Phase Sensitivity from Chunked KV-Cache Compression
- 一句话总结：按固定 stride 做 chunked KV 压缩会引入“相位”：同一信息因落在窗口的不同位置，检索准确率可差 **40pp**。
- 核心贡献（2-3点）：
  - 定义 phase sensitivity；平均 benchmark 分数会盖住周期性弱区。
  - 开源长上下文模型上实测，不是玩具设定。
- 工程价值：若线上用了 StreamingLLM / 固定窗压缩 / 分块压缩，评测必须扫 phase，否则 SLA 会被特定偏移打穿。改法方向：随机化窗口边界、重叠窗、或相位感知检索。
- 是否值得读：可选（短、但排障很值）
- Relevance Score：3
- Link：https://arxiv.org/abs/2609.36322

# 额外输出

## 1. 今日最值得读 Top 3

1. **SPLASH** — 唯一把“运行中改并行布局”做成几乎免费 handoff，并给出可跑 SGLang fork。agent/RL rollout 负载会动态变长，这是当前 serving 引擎的结构性盲区。  
2. **QuantMLA** — MLA 已是开源旗舰标配，双路 INT4/INT2 + 融合 kernel + 5× 吞吐是能进推理栈的数字，不是又一篇通用 KV 量化。  
3. **KV-Kaizen** — 把 cache 策略从“全局一种压缩”变成“prefill 前一次、按层组合三轴”，和 SPLASH 一样指向：**静态配置扛不住混合长上下文**。

（做 post-training 的人把第 3 换成 **RLTL;DR** 或 **DistFlow**。）

## 2. 今日趋势观察

- **Inference / KV 明显过密**：同一天 MLA 专用量化、自适应多轴压缩、chunk 压缩相位缺陷同时出现。社区焦点已从“再降 1 bit”转到 **结构感知（MLA 双路、per-layer、相位）**。
- **Serving 控制面升温**：并行布局热切换、跨 provider 路由，说明瓶颈从 kernel 外溢到调度与市场层。
- **Agent 论文在分化**：一边是 meta-controller harness（Thinking Before Thinking），一边是 agent 训练信号（RLTL;DR）。纯 prompt agent 增量变少。
- **SFT/RLHF 当天没有特别强的新对齐算法**；RL 侧增量在 **失败信号内化** 和 **分布式 RL 运行时**，不在 reward model。

## 3. 值得跟进的潜在方向

1. **Layout-adaptive serving**：DOP + 运行时切换很可能成为 SGLang/vLLM 下一季主线；跟 kernel 同等优先。  
2. **结构专用 KV codec**：通用 INT4 已挤不动，MLA/视频世界模型/chunked 压缩都在要求路径或相位专用量化。  
3. **稀疏成功下的 RLVR**：Pass@128=0 时 insight 内化比堆 rollout 更有效——值得做成训练框架里的一等公民（失败摘要缓冲 + 对 insight token 反传）。  
4. **评测陷阱**：KV reuse / chunk compress 的平均分不可信（相位、reuse 污染）。线上必须带 phase sweep 和 reuse-aware 评测集。
