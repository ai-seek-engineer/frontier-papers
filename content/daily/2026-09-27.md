## 1. Inference / 推理优化

### 【Title】Disaggregated Quantization: Specializing LLM Prefill and Decode
- 一句话总结：把量化拆成 **prefill 用算力友好格式、decode 用带宽友好权重**，并在 vLLM 上验证 disagg serving。
- 核心贡献：
  - Prefill/decode 对精度与算力的需求不同：decode 去掉 activation quant 不增成本但抬 decode-heavy 任务精度。
  - 单独训 NVFP4 prefiller + 现成 GGUF decoder：Qwen3.8-27B 上 1-bit decode 的 MMLU-Pro / MMMU-Pro 分别 +32.5 / +35.3，不改 decode ckpt。
  - ODP：prefiller 权重从 SSD stream，8K prompt 上 TTFT 相对 weight-only **1.78×**；PTQ 验证到 **2.8T**。
- 工程价值：直接可接到 **P/D 分离 serving**。单卡也能用 SSD offload prefiller，不必为统一量化格式牺牲两端。
- 是否值得读：**强烈推荐**
- Relevance Score：5
- Link：https://arxiv.org/abs/2609.26333

### 【Title】The KV Cache Working Set: Online Capacity Planning for LLM Inference Systems
- 一句话总结：给 prefix cache 做 **在线 working-set 估计**，回答“要多少 KV 容量才能打到目标 hit rate”。
- 核心贡献：
  - 把 KV working set 定义为达到目标命中率的最小容量；KVSET 可在线分析 + 离线 trace replay。
  - 针对 **agentic 增长式对话/工具历史**，prefix cache 容量规划从拍脑袋变成可测。
  - 生产 trace 验证，估计与真实 cache 部署接近；有开源实现。
- 工程价值：集群扩容、HBM vs host DRAM vs SSD 分层、agent 会话并发上限，都依赖这个数。比再发一篇 eviction heuristic 更有运维价值。
- 是否值得读：**强烈推荐**
- Relevance Score：5
- Link：https://arxiv.org/abs/2609.27746

## 2. AI Infra / 系统

### 【Title】When Fancy Eviction Fails: Rethinking Cache Replacement For LLM Prefix Reuse
- 一句话总结：生产 prefix-cache 上，14 种“高级”eviction 几乎打不过 LRU；真正该优化的是 miss cost 与粒度，不是策略花活。
- 核心贡献：
  - 两家公司生产 trace：reuse 由 **活跃 session 的节奏**主导，recency 已经很强。
  - 新问题是重尾 session footprint + miss cost 随序列长度变化；提出 compute-savings ratio 和两个 offline oracle。
  - 建议：LRU 打底 + one-hit 快淘汰 + compute-aware 部分驱逐 + 容量相关粒度。将放 trace + simulator。
- 工程价值：vLLM / llm-d 一类 prefix cache 别再堆复杂 eviction。把工程时间花在 **部分驱逐与 miss 代价建模**。
- 是否值得读：**强烈推荐**
- Relevance Score：5
- Link：https://arxiv.org/abs/2609.28870

### 【Title】Cross-Model Autoscaling for Shared LLM Serving
- 一句话总结：共享 GPU 池上多模型热切换，用跨模型可比的 Token Service Share 做容量再分配，而不是各模型本地扩缩。
- 核心贡献：
  - TSS：按需求归一化的“每请求有效 token 服务量”，跨异构模型 / SLO 可比较。
  - TRE：固定 GPU 预算下 donor–receiver 迁移，快救援 + 慢再平衡。
  - K8s 热切换栈、不改 inference scheduler；7 条 trace 上相对 SOTA KV-aware 反应式扩缩，P95 **−11.9% ~ −79.0%**。
- 工程价值：MaaS / 多 LoRA / 多基座共池的控制面。信号设计比“再写一个 HPA”重要。
- 是否值得读：**强烈推荐**
- Relevance Score：5
- Link：https://arxiv.org/abs/2609.29160

## 3. LLM Agents（系统设计向）

### 【Title】Hot-Cold Tiering of HBM and High Bandwidth Flash for Agentic LLM Serving
- 一句话总结：Agent 会话 KV 分热冷：每步都读的热集放 HBM，暂停会话的冷池放封装级高带宽闪存。
- 核心贡献：
  - Agentic KV 访问模式：小热集逐步 decode，大冷池只在 resume 时读。
  - Qwen3-Coder-30B-A3B：TBT 14ms，resume 相对 prefill 只加 ~0.1ms，单卡并发会话 **24×**。
  - 相对全走 flash，8-GPU 节点读功耗降 **7.6 kW**。
- 工程价值：不是又一篇 offload KV。是 **HBM+HBF 内存层级怎么服务长生命周期 agent**。对会话暂停/恢复产品线直接相关。
- 是否值得读：**可选**（硬件假设强，但 workload 刻画值钱）
- Relevance Score：4
- Link：https://arxiv.org/abs/2609.25782

## 4. SFT / Alignment / RLHF

### 【Title】Reinforcement Learning with Decomposed Subtasks
- 一句话总结：把整条 multi-turn rollout 的标量 reward 拆成子任务优势，再按 reflection 点把 credit 压到关键 token。
- 核心贡献：
  - SDAE 替换 GRPO 标量 advantage：固定 taxonomy 分份额 → 子任务 group-relative advantage → 按重要性加权到 token。
  - 高异质子任务任务上收益大：ScienceWorld **+11.5**，FrozenLake **+9.8**；HotpotQA / DeepResearch 接近噪声（诊断指标提前预言）。
  - 长 rollout 上 wall-clock/step 反而 **−10.9%**（摊掉 reflect/grade 固定开销）。
- 工程价值：agentic RL 里“整条轨迹一个数”是信用分配瓶颈。可插到现有 GRPO 管线；先看 heterogeneity 诊断再决定值不值得上。
- 是否值得读：**可选**
- Relevance Score：4
- Link：https://arxiv.org/abs/2609.27035

## 5. Reinforcement Learning（系统）

### 【Title】Conduit: An Experience Data Plane for Distributed Reinforcement Learning
- 一句话总结：把 RL 的 experience path（ingest / place / deliver）抽成独立 data plane，而不是埋在 RLlib 控制流里。
- 核心贡献：
  - EDP：experience 的放置与调度成为一等优化目标。
  - 容量/带宽感知分层放置 + 延迟感知调度，不改框架语义。
  - 接 RLlib：experience-path 暴露延迟最多 **−97%**，端到端 iteration **−38%**，扩到 **1024 GPU**，收敛不变。
- 工程价值：大规模 on-policy / 多 actor RL（含 LLM RL）里，buffer 已经是存储+网络系统，不是 queue。这是正确的抽象分层。
- 是否值得读：**强烈推荐**（做 RL infra 的人）
- Relevance Score：5
- Link：https://arxiv.org/abs/2609.24456

### 【Title】Flash-dLLM: IO-Aware KV Caching and Parallel Decoding for Fast, Memory-Efficient Diffusion LLMs
- 一句话总结：给 diffusion LLM 做 IO-aware 融合 KV kernel + 自草稿自校验并行解码，无需额外 draft 模型。
- 核心贡献：
  - 指出 dLLM + KV 后主瓶颈是 GPU mem IO，不是算法步数。
  - 同一模型既是 drafter 也是 verifier。
  - 相对 Elastic-Cache：GSM8K **5.1×**，HumanEval **11.0×**；有代码 https://github.com/VILA-Lab/Flash-dLLM
- 工程价值：若你在跟 dLLM serving，这篇是当前最能落地的加速件。纯 AR 栈可跳过。
- 是否值得读：**可选**
- Relevance Score：3
- Link：https://arxiv.org/abs/2609.26796

## 今日最值得读 Top 3

1. **Disaggregated Quantization**  
   P/D 分离已经是生产默认架构，量化却还在用“一套格式打天下”。这篇把格式、权重、存放位置按阶段切开，并在 vLLM + 超大模型 PTQ 上给了可抄的路径。

2. **When Fancy Eviction Fails**  
   用生产 trace 直接打脸 prefix-cache 算法竞赛。结论可立刻改 serving 优先级：别再优化 LRU 的替身，去处理变长 miss cost 和部分驱逐。

3. **KV Cache Working Set (KVSET)**  
   Agent 工作负载让 prefix cache 从“能用”变成“要规划容量”。没有 working-set 估计，分层存储和并发上限都是拍脑袋。

（做 RL 训练栈的把 Conduit 并列第 3。）

## 今日趋势观察

- **Inference / KV 系统明显过密**：48h 内 KV working set、prefix eviction 实证、P/D 分阶段量化、agent 热冷分层、sparse+compensation 同时出现。主线从“再压 1 bit”转到 **容量规划、命中代价、阶段特化**。
- **控制面 > 内核**：TRE 跨模型扩缩、KVSET 在线分析，说明瓶颈上移到 fleet 调度与缓存供给，而不是再写一个 attention kernel。
- **Agent 论文多，但工程可落地的少**：多数仍是辩论/拓扑。真正有系统味道的是 **agent KV 生命周期** 和 **agentic RL 信用分配/experience plane**。

## 值得跟进的潜在方向

1. **阶段特化的模型资产**：prefiller 与 decoder 不再共享同一份量化权重（甚至精度族不同）。检查点管理、热切换、SSD 流式 prefill 会变成产品问题。
2. **Prefix cache 作为一等容量资源**：working set + compute-aware 部分驱逐 + agent session 热冷分层，三条线会合到同一套分层 KV 控制面。
3. **RL experience path 独立于训练框架**：和 LLM serving 的 KV data plane 同构——ingest / place / deliver。LLM-RL 训练栈大概率会复制这套分层。
