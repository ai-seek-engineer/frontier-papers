【Title】PipeSwift: Revisiting Pipeline Parallelism for Large-Scale Completion-Oriented Agentic Serving  
https://arxiv.org/abs/2609.16491

- 一句话总结：Agent 服务目标从 TTFT/TPOT 变成任务完成时间（JCT），PP 在这个目标下重新变得有用。
- 核心贡献：
  - 实证：prefill-优先调度吞吐最好，但 JCT 可差到 1.40×；最优点不在两端。
  - 用 JCT-aware 调度 + pipeline 内 multi-token prediction 重做 PP runtime。
  - 64×H800、360B+ MoE、真实 coding/search agent replay：相对 SGLang wide-EP 最高 1.45× JCT，相对 vLLM PP2 2.33×。
- 工程价值：直接打生产 agent serving。不要再默认 PD-disagg + 纯 token SLO。PP 的价值在 prefill/decode 平衡，不在单 token 延迟。
- 是否值得读：强烈推荐
- Relevance Score：5
- Link：https://arxiv.org/abs/2609.16491

【Title】GrowMTP: Can RL Grow Its Own Draft Head?  
https://arxiv.org/abs/2609.16648

- 一句话总结：RL rollout 自己就能从零长出 MTP draft head，不必先离线训投机头。
- 核心贡献：
  - 观察：RL rollout 分布窄 + verify 步天然给对齐监督。
  - draft head 梯度与 policy 解耦，从零训练。
  - Qwen3-4B / MiMo-7B / Qwen3.5-4B：rollout 2.13× / 1.93× / 1.36×，端到端 1.60× / 1.41× / 1.20×。
- 工程价值：RL post-train 墙钟主要在 rollout。可当现有 RL 框架的可插拔加速件，尤其适合没有预训 MTP 头的基座。站点：https://growmtp.github.io/
- 是否值得读：强烈推荐
- Relevance Score：5
- Link：https://arxiv.org/abs/2609.16648

【Title】AgentKV: Phase-Aware KV Eviction for Agentic LLMs  
https://arxiv.org/abs/2609.14872

- 一句话总结：Agent 的 think/act/tool 查询子空间不同，用“最近 token”估重要性会系统性丢掉下一阶段需要的 KV。
- 核心贡献：
  - 按 phase 维护 query buffer，对 union 打分。
  - 接到多轮 persistent serving，跨 turn 压缩 + 在线 compact page。
  - 相对 R-KV / Tri-attention 任务分约 +5.5 / +5.3；相对 full-KV SGLang 输出吞吐最高 1.80×。有代码。
- 工程价值：Agent 长轨迹 KV 驱逐不能照搬 chatbot SnapKV。phase-aware 可直接改 serving 驱逐策略。
- 是否值得读：强烈推荐
- Relevance Score：5
- Link：https://arxiv.org/abs/2609.14872

【Title】LoopSpec: Pipelined Self-Speculative Decoding for Looped Transformers  
https://arxiv.org/abs/2609.17184

- 一句话总结：Looped Transformer 用早期 recurrent state 出 draft，pipeline 重叠 draft 与 verify，训练免费。
- 核心贡献：
  - 早层 state 当 draft；深循环做 selective second proposal。
  - 给出最优 proposal depth 闭式解，与实测对齐。
  - greedy/sampling 都无损；最高 6.83×。
- 工程价值：只对 looped 架构有用。若你在跟 recurrent-depth / 参数共享模型，这是当前最对口的 decode 加速。通用 decoder-only 可跳过。
- 是否值得读：可选
- Relevance Score：4
- Link：https://arxiv.org/abs/2609.17184

【Title】FlashVector: Agent for Hierarchical Model Serving Stack Optimization  
https://arxiv.org/abs/2609.17391

- 一句话总结：把“单 kernel 优化 agent”扩成跨 kernel / 计算图 / Triton server / 特征服务的分层优化框架，并上了广告推荐生产。
- 核心贡献：
  - 可扩展 agent 框架，覆盖异构技术栈。
  - Unity Vector：model server 吞吐最高 2×、延迟 1.98×；feature store 吞吐 1.6×。
  - 优化点不只在 CUDA kernel，还包括 Triton C++ 与 Python 特征变换。
- 工程价值：推荐/广告 serving 比 LLM 更“多层栈”。证明 agent 优化要能改 server 代码，不只写 kernel。LLM 栈可借鉴同一分层思路。
- 是否值得读：可选
- Relevance Score：4
- Link：https://arxiv.org/abs/2609.17391

【Title】Shared-Prefix KV Reuse Across Standard LoRA Adapters  
https://arxiv.org/abs/2609.17109

- 一句话总结：标准 LoRA（未为 cache 兼容重训）能否复用 backbone prefill KV？结论偏负：质量略掉，内存几乎没省下来。
- 核心贡献：
  - Qwen3-1.7B + QA/GSM8K adapter，扫 takeover 边界。
  - 全前缀复用 TTFT 好（8K 约 16× warm-cache），质量差不稳定（GSM8K ΔEM −4.6 ~ −0.8）。
  - 实现复用的是 KV 值但存储被 copy，双分支峰值显存只低 12%，物理不共享。
- 工程价值：多 LoRA 同 prefix 的 serving 坑报告。先别默认“reuse prefix KV 就能省显存”；要真共享必须改 allocator。
- 是否值得读：可选（短、实证强）
- Relevance Score：4
- Link：https://arxiv.org/abs/2609.17109

https://arxiv.org/abs/2609.17241

- 一句话总结：无独立 draft 模型的投机解码：浅层高频探索 + 深层低频 verify，用 bonus logits 补树。

## 今日最值得读 Top 3

1. **PipeSwift**  
   目标函数换了：agent 集群该优化 JCT 而不是 token SLO。64 卡、大 MoE、真实轨迹 replay，结论可直接改调度/并行策略。

2. **GrowMTP**  
   砍掉 RL 前的离线 draft-head 预训练。对正在跑 GRPO/PPO 长 rollout 的团队，是少数能立刻减 GPU-hour 的方法。

3. **AgentKV**  
   Agent KV 驱逐的假设被证伪（recency ≠ 下一 phase）。有 SGLang 路径和吞吐数字，比再发一篇通用 SnapKV 变体有用。

## 今日趋势观察

- **Inference / KV / speculative** 仍然是最大流量：LoRA 前缀复用、phase-aware eviction、looped 模型自投机、RL 内生长 MTP。
- **Agent serving 系统化** 明显抬头：不再只谈 tool-calling 准确率，而是 JCT、跨 turn KV、权限 lease、serving 栈 agent。
- **分布式训练新论文偏少**（近 48h 几乎没有新的通信/并行突破）；训练侧加速更多绕到 **RL rollout + spec decode**。

## 值得跟进的潜在方向

1. **Completion-oriented scheduling**：把 PD-disagg / continuous batching 的目标从 TPOT 换成任务完成时间，PP 可能回潮。
2. **Workload-conditioned KV policy**：chat / reason / tool 分 phase 维护 query 代表，而不是单一 recency/score。
3. **Online drafter 与 RL 同循环**：draft head 当 RL 副产品，而不是独立训练作业。
4. **“复用 KV”必须落到 allocator**：多 adapter / 多分支若只 copy 不 share，论文里的显存收益是假的。
