## 1. Inference / 推理优化

【Title】RapidMoE: Exploiting Cross-Asymmetry via Adaptive Residual Offloading for Large-Scale MoE Inference

- 一句话总结：把 expert offload 从“整专家搬运”改成“按残差比特切分”，让 GPU 只算关键位、CPU/存储扛低价值残差。
- 核心贡献（2-3点）：
  - 提出 Cross-Asymmetry：路由偏斜和异构硬件能力对齐，用 residual-split 把卸载粒度从 expert 降到 bit。
  - 双路径路由 + Unified Multi-Level Importance Arbitration，运行时调整 critical expert set，而不是静态 hot set。
  - 数据表示、路由、执行并行三层一起改，避免 PCIe 整专家加载或 CPU 重算两条老路。
- 工程价值：面向内存不够的大 MoE 落地。相对 SOTA offload，decode 最高 3.5×、prefill 2.1×。EuroSys 2027 接收，方法可迁到现有 CPU-GPU hybrid serving，但需要改权重布局和 kernel，不是即插即用。
- 是否值得读：强烈推荐
- Relevance Score：5
- Link：https://arxiv.org/abs/2610.01265

【Title】MegaFlux: Skew-Resilient MoE Megakernels via Pipelined Expert Replication

- 一句话总结：在 megakernel 里把热 expert 复制成运行时决策，并用流水线盖住复制带来的权重/梯度通信。
- 核心贡献（2-3点）：
  - on-device planner 在每 GPU replica budget 内选副本位置和 tile-aligned token block，不改 router 输出。
  - forward 边收权重边算；backward 把 replica gradient reduce 和 expert 计算重叠。
  - 扩展 TensorRT-LLM CuTeDSL MegaMoE，并接到 vLLM 做 DeepSeek-V4-Pro prefill。
- 工程价值：直接打在 EP 推理/训练的 straggler 上。8×B200、147 组配置，forward/backward 几何均值 1.45× / 1.28×，峰值 2.14× / 2.64×；流水线藏掉 forward 权重传输成本的 56–76%、backward 相关成本的 91–100%。端到端 prefill 中位 1.13–1.26×。有现成 kernel 落点，比纯 offload 论文更接近生产。
- 是否值得读：强烈推荐
- Relevance Score：5
- Link：https://arxiv.org/abs/2610.00671

## 2. AI Infra / 分布式

【Title】Leto: Fast In-Place Recovery for LLM Training on Surviving Hardware

- 一句话总结：针对“硬件还能跑、但训练被打断”的 HOF，在原机上原地恢复，而不是重载 checkpoint、重建进程。
- 核心贡献（2-3点）：
  - 把可复用进程状态和模型状态留在同机，其余状态用 shadow trainer 预初始化。
  - 两级纠删保护 + chunk 级事务更新，保证保留状态可恢复且一致；显存紧张时回收 shadow。
  - 6/72 卡 A100 上恢复比最好 checkpoint 基线快 3.6–6.5×，有效训练时间最多 +13.7 pp；13 万卡仿真有效时间 >95%。
- 工程价值：大集群训练的故障恢复路径，不改模型算法。适合已经有 checkpoint 体系、想压 MTTR 的训练平台。实现重，依赖训练框架进程模型。
- 是否值得读：强烈推荐
- Relevance Score：4
- Link：https://arxiv.org/abs/2610.00687

【Title】Efficient Expert-Parallel Communication on PCIe-Connected Consumer GPUs (ThunderEP)

- 一句话总结：消费级 PCIe 多卡没有 GPU 直连，NCCL 的 CPU 中转会和 expert 计算抢资源；ThunderEP 用 DMA 直走并减轮询。
- 核心贡献（2-3点）：
  - 去掉传统 ring 的 relay hop，数据走 DMA engine，避免占计算 SM。
  - 降低 CPU 内存 completion flag 的 polling 开销。
  - 接入 vLLM，在 RTX 4090 / 5090 上评三个常用 MoE。
- 工程价值：dispatch/combine 相对 NCCL 平均 2.00× / 1.53×，端到端最高 1.66×。只对无 NVLink 的消费级/工作站 EP 有用，数据中心 NVLink 集群收益有限。
- 是否值得读：可选
- Relevance Score：4
- Link：https://arxiv.org/abs/2609.40093

## 3. LLM Agents

【Title】AutoCompact: Learning When to Compact Context in Long-Horizon Coding Agents

- 一句话总结：把“何时压缩、保留什么工作状态、压缩后如何续跑”训练进 coding agent 策略，而不是固定 token 阈值。
- 核心贡献（2-3点）：
  - 用 judge 改写错误的压缩决策和摘要，再在环境里续跑，得到可执行轨迹。
  - SFT 后再用任务成功奖励联合优化写代码和压缩。
  - SWE-bench Verified / SWE-PolyBench Verified 绝对提升 9.2 / 5.0 pp；256K 不溢出，16K 溢出时走 fallback。
- 工程价值：长轨迹 agent 的上下文成本是 serving 账单和 KV 的主要来源。策略级 compaction 比再加一层摘要 prompt 更可部署，但训练流程依赖 judge 和可执行环境，复现成本不低。
- 是否值得读：强烈推荐
- Relevance Score：4
- Link：https://arxiv.org/abs/2610.02163

【Title】ActiveSaddler: Automated Curriculum Learning for Agent Harness Optimization

- 一句话总结：harness 优化不该固定训练场景；把失败模式当成非平稳 bandit，让课程和 harness 一起变。
- 核心贡献（2-3点）：
  - 把重复失败抽象成可复用 failure-pattern arms，估计继续打该模式的 learning progress。
  - 在回访已知弱点和探索新场景之间自适应分配。
  - GAIA2 / Terminal-Bench 2.0 上，相对固定场景顺序的同一优化器，Pass@1 +4.4 / +7.5 pp。有项目代码。
- 工程价值：适合已经在做 prompt/tool/control 自动迭代的团队。收益是 harness 质量，不是单次推理延迟。场景集和失败聚类的稳定性需要自己验证。
- 是否值得读：可选
- Relevance Score：3
- Link：https://arxiv.org/abs/2610.00906

## 4. SFT / Alignment / RLHF

【Title】Semifactual Credit-Augmented Policy Optimization (SCAPO)

- 一句话总结：GRPO 把同一 outcome advantage 打到每个 token 上，会强化对无关 prompt 扰动敏感的 token；SCAPO 用半事实稳定性做 token 级信用。
- 核心贡献（2-3点）：
  - 半事实干预保持题目和答案，只测 token 概率漂移。
  - 训练早期压低不稳定 token 的 advantage，但不给“稳定”额外加分。
  - 解码时抑制高漂移候选本身就能提准确率，不必改权重。
- 工程价值：Qwen3-4B/1.7B-Base 上 AIME 2024–2026 相对 GRPO +5.63 / +4.17 pp，多数数学和全部 OOD 上最好。有代码。推理侧可先做高漂移 token 抑制做 A/B，再决定要不要改 RL 训练。额外干预会增加训练采样成本。
- 是否值得读：可选
- Relevance Score：4
- Link：https://arxiv.org/abs/2609.40360

## 5. Reinforcement Learning

本窗口没有独立、有系统或 benchmark 支撑的 RL 系统论文达到入选线。SCAPO 和 ActiveSaddler 已分别归到对齐和 agent。

## 今日最值得读 Top 3

1. MegaFlux。有 B200 大规模配置、megakernel 实现和 vLLM 端到端数字，是今天最接近能进 serving 栈的一篇。
2. RapidMoE。offload 粒度从 expert 降到 bit，是内存受限 MoE 的结构性改法，且有会议接收背书。读的时候和 MegaFlux 对照：一个解决放得下时的 skew，一个解决放不下时的搬运。
3. Leto。训练侧故障恢复仍是被低估的有效 GPU 时间来源；原地恢复比再抠 checkpoint 频率更贴近集群运维。

## 今日趋势

推理和 infra 明显抬头，而且几乎都是 MoE：expert residency、bit-level offload、EP 通信、skew 复制。经典 KV cache / speculative decoding 在这 48 小时没有新的强系统稿。Agent 侧从“再加一个工具”转向 harness 和 context 生命周期（何时压缩、用什么失败模式训练 harness）。对齐只有细粒度信用分配，没有新的偏好学习框架。

## 值得跟进的方向

MoE 的“放置 × 复制 × 卸载”正在合成一条栈：常驻热 expert、按需复制、残差/低比特卸载。下一步值得看的是统一调度器——同一请求在 HBM 预算、PCIe 预算和 skew 之间选 residency、replica 还是 residual offload，而不是三篇论文各管一段。Agent 长轨迹的 compaction 也应接到这条栈上：压缩决策直接决定 KV 和 expert 激活的生命周期。
