**【Title】** AInfer-PD: Communication-Safe In-Place Prefill-Decode Multiplexing for Distributed MoE Rollouts  
- 一句话总结：把 agentic RL rollout 里持续共存的 Prefill/Decode，做成同卡、同 KV、通信安全的 in-place 复用，而不是拆池 + 搬 KV。  
- 核心贡献（2-3点）：  
  - 指出 MoE + Attention TP/DP + DeepEP 下，P/D 并发会交叉 collective、共享可变协议状态。  
  - 跨 rank 协调 P/D collective 顺序，给 DeepEP 的 P/D 路径独立通信状态。  
  - 单节点相对关 multiplexing 的同引擎 7.1–22.5%、相对 SGLang 24.8–32.9%；两节点 18–35%；细粒度边界再砍 8.6–19.8%。  
- 工程价值：直接打 RL 训练里最贵的 rollout。如果你在做 SGLang/vLLM + DeepEP 的 P/D 共置，这篇比再发一篇“拆 P/D 集群”更贴近现网约束。  
- 是否值得读：强烈推荐  
- Relevance Score：5  
- Link：https://arxiv.org/abs/2609.00993

**【Title】** Characterizing the Scalability and Performance of Large-Scale AI Training Under Multi-Tenancy  
- 一句话总结：把“单作业扩展曲线”和“多租户噪声下真实吞吐”拆开测到 2400 GPU，覆盖 Alps / Leonardo / LUMI / JUPITER / NVL72 GB300。  
- 核心贡献：  
  - 五种并行策略 × scale-up / scale-out / rack-scale × 多种分配方案。  
  - 用可复现 noise model 量化作业间干扰，而不是只报理想隔离数字。  
- 工程价值：调度、作业打包、互联选型的决策依据。没有新算法，但比多数“我们在 N 卡上快了 X%”有用。  
- 是否值得读：强烈推荐（集群/调度负责人）；算法岗可选  
- Relevance Score：4  
- Link：https://arxiv.org/abs/2609.00817

**【Title】** mzCache: On-Device LLM Memory Management under Multitasking  
- 一句话总结：手机多任务把权重/KV 挤出内存后，用细粒度共享缓冲 + 混合 swap，做到 GPU 零等待开推、CPU 并行回填。  
- 核心贡献：  
  - 面向恢复的内存切分，支持部分驱逐/部分恢复、跨 CPU-GPU 同时访问。  
  - Android 实机：TTFT 相对存储回填 offload 降 2.1–5.5×。  
- 工程价值：端侧 serving 的 OS×推理交界；云端 KV 分层思路可借鉴，但实现绑定 unified memory SoC。  
- 是否值得读：强烈推荐（端侧/OS）；云推理可选  
- Relevance Score：4  
- Link：https://arxiv.org/abs/2609.01338

**【Title】** The Structure of Quantization Damage in LLMs: Why the Next Bit Should Be Spent Globally  
- 一句话总结：用“逐层升回 8-bit 看能救多少精度”做因果干预，结论是：多出来的那一点 bit，优先花在更细粒度，而不是护几层“关键层”。  
- 核心贡献：  
  - 9 个开源模型、4 个架构族；8/9 模型要救回 75% gap 大约要动一半层。  
  - 同等 bit budget，全局更细 group 比局部修层高 21–52 分。  
  - 8-bit 在 RTN/GPTQ/AWQ 下接近无损；“损坏信号”≠“加精度该加哪”。  
- 工程价值：PTQ 默认策略可改：别再迷信 mixed-precision 护注意力层。实现成本低，决策价值高。  
- 是否值得读：强烈推荐  
- Relevance Score：5  
- Link：https://arxiv.org/abs/2609.01587

**【Title】** Harness-of-Harness: Multi-Day Autonomous Software Development with Continual Improvement  
- 一句话总结：在现有 coding harness 外包一层迭代规划-编码-测试循环，让代理跨多日持续改进，而不是单次长跑。  
- 核心贡献：  
  - 修复 vs 能力增长分开；实现测试与独立评测隔离；交付物/工具/技能逐步暴露。  
  - 三套 harness-model（Codex+GPT-5.5 / OpenCode+DeepSeek-V4-Pro / Pi+MiniMax-M3）平均 +52%，最高 +83%。  
  - 70+ 迭代自主做出可玩 FPS；有 GitHub。  
- 工程价值：落地的是编排与评测隔离，不是新模型。可直接接到现有 coding agent 产品。  
- 是否值得读：强烈推荐（做 coding agent）  
- Relevance Score：4  
- Link：https://arxiv.org/abs/2609.01481

**【Title】** Parsing the Stream: A Live Trace Model for Long-Horizon Agents and Their Observers  
- 一句话总结：把长程 agent trace 做成 append-only ledger → 增量折叠成类型化 run state → 按消费者编译视图。  
- 核心贡献：  
  - 观察侧：编译视图比读 raw trace 少约 14–15× token、成本 5–7×，准确率 0.85–0.87 vs 0.48。  
  - Agent 侧：确定性聚合在 120-hop 顺序依赖任务上 30/30，全上下文只有 8/30。  
  - 给出 fold 失效的任务族；代码 + 数据集已放。  
- 工程价值：这是 agent runtime 的可观测性/记忆基础设施，不是 prompt 技巧。监控台和 agent 自用同一份 state。  
- 是否值得读：强烈推荐  
- Relevance Score：4  
- Link：https://arxiv.org/abs/2609.01466

**【Title】** From Rollouts to Recipes: Self-Contained Post-Training for LLMs  
- 一句话总结：用本次 rollout 的对错和置信度，把样本路由到 GRPO / on-policy 自蒸馏 / 正则 / skip，不再一套 recipe 打全部数据。  
- 核心贡献：  
  - 无外部教师、无额外标注、不额外采样。  
  - Qwen3 / Qwen3.5 数学推理上稳定优于均匀 GRPO、均匀 OPSD、固定混合。

- 工程价值：现有 GRPO 流水线加一层 router 即可试；省的是无效 update，不是新算法魔法。  
- 是否值得读：强烈推荐（post-training 岗）  
- Relevance Score：4  
- Link：https://arxiv.org/abs/2609.01422

**【Title】** Post-Training Science for Supervised Fine-Tuning  
- 一句话总结：把 SFT 的 LR、bs、LoRA vs full、epoch、优化器、数据量做成一次受控扫描，覆盖 Qwen3/Llama dense+MoE 到 235B。  
- 核心贡献：  
  - 真实客户 SFT 任务，评测就是数据生成用的同一套 judge。  
  - 逐杠杆扫，每条建议带不确定性。  
  - 直接回答：val loss 能不能排下游质量、LoRA rank/alpha 学到什么、训几轮开始伤通用能力。  
- 工程价值：这是 SFT 操作手册，不是论文创新。做平台默认超参的人该读。  
- 是否值得读：强烈推荐（SFT 平台）；研究岗可选  
- Relevance Score：4  
- Link：https://arxiv.org/abs/2609.01244

**【Title】** Explore More, Drift Less: Outcome-Only RL Can Suffice for Long-Horizon Interactive Agents  
- 一句话总结：长程 agent 的 outcome-only RL “天花板”来自信号饥饿 + 策略漂移；CANOPY 用同任务大规模探索 + 严格 on-policy/KL 锚定打掉这两点。  
- 核心贡献：  
  - 不堆稠密奖励、SFT prior、技能库、多 agent。  
  - Qwen3-14B 在 AppWorld 登上 2026-02 公开榜（TGC 86.9 / Challenge 67.6）。  
  - 同原则让 Qwen3.5-9B 在 SWE-bench Verified +16.6；计划开源训练栈。  
- 工程价值：改的是 rollout 组规模、更新约束和测试时 interaction budget，不是新 loss。对 agentic RL 训练栈可落地。  
- 是否值得读：强烈推荐  
- Relevance Score：5  
- Link：https://arxiv.org/abs/2609.01245

### 1. 今日最值得读 Top 3

1. **AInfer-PD** — 今天唯一把“agentic RL 的 P/D 共存 + MoE 通信正确性”钉死的系统文。数字在同引擎消融上，可直接对照 SGLang。  
2. **CANOPY (Explore More, Drift Less)** — 挑战当前 agent RL 默认假设（必须加稠密奖励/脚手架）。如果你在训 SWE/AppWorld 类代理，先核对探索规模和 on-policy 约束再加花活。  
3. **Quantization Damage 结构** — 改默认 PTQ 决策：下一 bit 给 granularity，不给“重要层”。实验设计（因果干预）比又一篇 mixed-precision 方法干净。

### 2. 今日趋势观察

- **Agentic RL 的系统面在涨**：rollout 里 P/D 长期共存、outcome-only 能否撑长程、harness 外包迭代，三篇同时出现。重心从“新 RL 公式”转到 **rollout 调度 / 探索预算 / harness 循环**。  
- **Inference 侧今天不是 KV 算法爆发日**（那些多在 8 月），而是 **量化怎么花 bit** + **端侧内存恢复**。  
- **Agent runtime 开始被当操作系统问题**：trace fold、harness-of-harness，而不是再堆一个 planner。

### 3. 值得跟进的潜在方向

- **同卡 P/D multiplexing 的通信隔离**，尤其 DeepEP / expert-parallel 路径。拆池简单但贵；共置要先把 collective 顺序和协议状态拆干净。  
- **Outcome-only RL 的“组内必须有成功/失败混合”**：探索不足会系统性丢掉最难、最有信息的题。训练栈应把 per-task group coverage 做成一等监控。  
- **PTQ：用因果“加精度能救多少”代替 saliency/outlier 启发式**。cheap proxy 和真正该加 bit 的位置经常对不上。  
- **Agent trace 的确定性折叠层**：同一份 run state 同时服务人看的监控和模型自己的上下文，比无限加 context window 更可运维。
