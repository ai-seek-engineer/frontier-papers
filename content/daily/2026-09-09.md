## 1. Model Inference / 推理优化

### 【Title】BeaconKV: Key-Value Cache Compression Guided by Beacon Queries for Efficient Large Reasoning Model Inference  
- **一句话总结：** 用少量“beacon query”代表整段推理 query 分布，训练无关地压 KV，专打长 CoT 推理模型。  
- **核心贡献：**  
  1. 发现 LRM 的 query 在 embedding 空间会聚成少数簇，不必存全部 query 历史。  
  2. 训练无关压缩，最多约 **5.8× 显存下降**、**>4.3× throughput**，精度接近 full cache。  
  3. 有 ICML 2026 标记和代码链接。  
- **工程价值：** 直接可接长 reasoning serving。长 CoT 的 KV 是当前 7B–32B 推理卡脖子点；比“再训一个 draft 模型”便宜。落地关键是 beacon 维护开销和与 paged attention / prefix cache 的兼容。  
- **是否值得读：** 强烈推荐  
- **Relevance Score：** 5  
- **Link：** https://arxiv.org/abs/2609.04971

### 【Title】Random Attention: Rethinking KV Cache Eviction for Efficient Reasoning  
- **一句话总结：** 推理轨迹 KV 驱逐里，复杂打分几乎没用；保 prompt + 每头随机丢，效果打平 SOTA evictor，vLLM 吞吐更高。  
- **核心贡献：**  
  1. 把“打分选 token”这个主流范式打穿：信号主要来自“有没有保住 prompt”，不是 ranking 质量。  
  2. CoT 文本自身重复 + 多头冗余，随机抽样已够。  
  3. vLLM 部署相对最强 evictor **+32–43% throughput**。  
- **工程价值：** 极高。实现成本接近零（不用每步算 attention score / 维护 heap）。适合先做 ablation：你们线上的 SnapKV/H2O 是不是在浪费算力。注意：结论绑定 **reasoning decode**，不要直接套到检索/多轮对话。  
- **是否值得读：** 强烈推荐  
- **Relevance Score：** 5  
- **Link：** https://arxiv.org/abs/2609.03430

## 2. AI Infra / 分布式 / 系统优化

### 【Title】AInfer-PD: Communication-Safe In-Place Prefill-Decode Multiplexing for Distributed MoE Rollouts  
- **一句话总结：** 给分布式 MoE 的 RL rollout 做同卡 P/D 复用，并修掉 P/D 交叉集合通信顺序和 DeepEP 共享可变协议状态。  
- **核心贡献：**  
  1. 把 in-place P/D multiplexing 扩到分布式 MoE rollout（agentic RL 的真实瓶颈）。  
  2. 通信安全：避免 P/D 路径乱序 collective。  
  3. 相对同引擎关 multiplexing **7–35%** 完成时间下降，相对 SGLang 约 **18–33%**。  
- **工程价值：** 直接服务 RL 训练集群，不是 demo serving。谁在跑 Qwen-MoE + GRPO/agentic RL，这篇比再抠 0.5 bit KV 更值钱。  
- **是否值得读：** 强烈推荐（做训练 infra 的人）  
- **Relevance Score：** 5  
- **Link：** https://arxiv.org/abs/2609.00993

### 【Title】Cache-Aware Joint Router Adaptation for Memory-Efficient MoE Inference  
- **一句话总结：** 把 expert cache 命中当成可训问题：后训练同时改 backbone + 轻量 cache router，推理仍走原生 Top-K。  
- **核心贡献：**  
  1. Temporal Router：预测同层复用，不主动 prefetch。  
  2. Spatio-Temporal Router：用前一层 hidden 预热 cache。  
  3. Qwen3 上相对最强 prefetch baseline，流量最多降 **~53%**，命中率升数个点到 18 点。  
- **工程价值：** MoE decode 的专家换入换出是 HBM/PCIe 主成本。优点是不改 Top-K 接口，容易塞进现有 serving；风险是后训练是否破坏原任务分布，以及多卡 EP 下 router 是否仍准。  
- **是否值得读：** 可选  
- **Relevance Score：** 4  
- **Link：** https://arxiv.org/abs/2609.04895

## 3. LLM Agents（有系统设计/落地）

### 【Title】Explore More, Drift Less: Outcome-Only RL Can Suffice for Long-Horizon Interactive Agents (CANOPY)  
- **一句话总结：** 小开源模型上，纯 outcome RL 也能训出长程交互 agent，关键是放大同任务探索 + 严格 on-policy/KL，而不是堆过程奖励。  
- **核心贡献：**  
  1. 诊断：小任务池反复更新 → policy drift + 有效 group 消失。  
  2. CANOPY：同任务探索放大、更新只打 agent action token、测试时把交互预算花回去。  
  3. Qwen3-14B 在 AppWorld 登顶（当时榜）；Qwen3.5-9B SWE-bench Verified **+16.6**。计划放训练栈。  
- **工程价值：** 减少“必须 process reward / 复杂 scaffold”的教条。训练侧要准备更大 env 并发和更稳的 on-policy 管线，和 AInfer-PD 是同一条产线问题。  
- **是否值得读：** 强烈推荐  
- **Relevance Score：** 5  
- **Link：** https://arxiv.org/abs/2609.01245

### 【Title】Fresh Memory, Stale Plans: Dependency-Scoped Validation for Distributed LLM-Agent Memory (PlanFence)  
- **一句话总结：** 共享内存“新鲜”不等于计划仍有效；执行前只校验计划依赖的那几条记录。  
- **核心贡献：**  
  1. 定义 stale-plan execution：读到 r4，仍执行基于 r3 的计划。  
  2. PlanFence：计划引用具体 public records，executor 只校验会影响即将发出的外部动作的依赖。  
  3. 30 个带事后修订的 live workflow：freshness-only 全部踩坑，PlanFence 零非法动作。  
- **工程价值：** 多 agent + 共享 store 的正确性协议，不是又一个 memory 向量库。实现成本低（依赖图 + 校验/一次 replan）。作者自己写明：这是安全/系统成本结果，不是通用涨分。  
- **是否值得读：** 可选（在做 multi-agent 控制面就读）  
- **Relevance Score：** 4  
- **Link：** https://arxiv.org/abs/2609.03340

## 4. SFT / Alignment / RLHF

### 【Title】DE-Venus: A Data-Efficient RLVR Framework for Large Language Models  
- **一句话总结：** 把 RLVR 的监督当成跨“选数据 + 优化策略”的演化状态，而不是绑死在分布式训练循环里的一次性过滤。  
- **核心贡献：**  
  1. 把 sample selection / 不完整监督 / 脏 label 收成同一套 supervision state。  
  2. 公开基准 + 三个业务场景：约 **10% labels** 或 **13% 相关数据** 仍能保质。  
  3. 部分业务配置收敛步数降 **63–75%**。  
- **工程价值：** RLVR 最贵的是 on-policy rollout 和可靠 target。这篇的价值是把数据效率从“训练脚本里的 if”拆成可复用模块。缺代码则落地折扣大。  
- **是否值得读：** 可选  
- **Relevance Score：** 4  
- **Link：** https://arxiv.org/abs/2609.03324

### 【Title】From Rollouts to Recipes: Self-Contained Post-Training for LLMs (Self-Routing)  
- **一句话总结：** 用本次 rollout 的对错和置信度，把样本路由到 GRPO / on-policy 自蒸馏 / 正则 / 跳过，不再一套配方打全部数据。  
- **核心贡献：**  
  1. 无外部教师、无额外标注、不额外采样。  
  2. 数学推理上稳定优于均匀 GRPO / 均匀 OPSD / 固定混合。  
  3. 路由分布随训练变化，少更新低信号样本。  
- **工程价值：** 对已有 VeRL/OpenRLHF 管线是“调度层”改动，不是新算法。实现简单，适合先 A/B。别指望泛化到非可验证任务。  
- **是否值得读：** 可选  
- **Relevance Score：** 3  
- **Link：** https://arxiv.org/abs/2609.01422

## 5. Reinforcement Learning

### 【Title】Cliff: Learning Process Rewards from the First Mistake  
- **一句话总结：** 用现成 LLM 找 rollout 里第一个错，把序列切成正确前缀 / 错误后缀，做成 token-level advantage。  
- **核心贡献：**  
  1. 不训过程奖励模型，只找 first-error。  
  2. 12 个设定上相对 GRPO **+7%**，相对 on-policy distillation **+15%**。  
  3. 弱教师也有效。  
- **工程价值：** process reward 的廉价近似。额外成本是每个 rollout 一次教师前向；和“小模型当 rubric judge”是同一类训时开销问题。first-error 定位噪声会直接污染优势估计。  
- **是否值得读：** 可选  
- **Relevance Score：** 4  
- **Link：** https://arxiv.org/abs/2609.02817

补充一篇不占满额、但 serving 同学应扫一眼的生产负结果：

### 【Title】Same Request, Different Answer: Quantization Amplifies Cache-Induced Divergence in LLM Serving  
- prefix cache 默认开着时，同一请求轨迹会漂；16-bit 上 **36%** episode 改变，4-bit 上 **75%**。关 cache 则 800 episode 全 bit-identical。  
- **工程含义：** 量化 + prefix cache 会把“非确定性”放大到 agent 轨迹级别，评测/回归/合规都会炸。  
- Link：https://arxiv.org/abs/2609.04748

## 额外输出

### 1. 今日最值得读 Top 3

1. **Random Attention** — 可能直接删掉线上 KV scorer。结论反直觉，有 vLLM 吞吐数字，读完就能做实验。  
2. **BeaconKV** — 对准 LRM 长 CoT 内存墙，有压缩比和吞吐，且训练无关，比再训 draft 更贴近现网。  
3. **AInfer-PD** 或 **CANOPY**（二选一按岗位）：训 MoE/agentic RL 读 AInfer-PD；做 agent 策略读 CANOPY。两者都碰到同一现实：rollout 墙钟和探索预算，不是又一个 benchmark 刷分。

### 2. 今日趋势观察

- **Inference 明显扎堆在 KV eviction/compression**，且开始打“打分函数是否必要”和“reasoning 专用假设”，不再只卷 4-bit。  
- **Agent 论文从 prompt 编排转向两类系统问题：** (a) 长程 outcome RL 能否收敛；(b) 分布式共享状态的计划一致性。  
- **RLVR/post-training 在抠数据效率和样本级配方**，说明 rollout 成本已经压过算法花样。  
- **MoE serving/training 的 cache/P-D 复用** 重新变热，和推理侧 KV 是两条并行内存线。

### 3. 值得跟进的潜在方向

- **Score-free / random KV eviction for reasoning**：若复现成立，serving 实现会大幅简化；要尽快在你们的多轮工具调用和检索任务上证伪边界。  
- **Prefix cache × 量化 × agent 轨迹可复现性**：这是生产事故源，不是学术边角。需要 cache 版本、量化路径、采样种子的联合确定性 SLA。  
- **Stale-plan / 依赖作用域校验**：multi-agent 共享 memory 会从“向量库”变成带引用的事务协议。  
- **RL rollout 的同卡 P/D + 通信安全**：agentic RL 的系统瓶颈已经从 loss 公式挪到引擎调度。
