### 1. Inference

**【Title】** VPP: Virtual Pipeline Parallelism for Efficient Chunked Prefill in Long-Context LLM Inference  
- 一句话总结：长上下文 chunked-prefill 的流水线气泡，不靠动态切 chunk，靠虚拟 stage 排布把重 attention 和邻居的轻 stage 叠起来。  
- 核心贡献：  
  1. 指出 equal-size chunk 后期 attention 随 prefix KV 变重，等分 chunk 必然打气泡；动态 resize（DCPP）在超长序列上调度开销反超收益。  
  2. 固定 chunk + V 形虚拟 stage + 异步通信/打包，把 bubble ratio 从 6.4% 打到 0.1%（512K DeepSeek-V3.1 prefill）。  
  3. 落地在 vLLM-Ascend，16×910C，最长 1M token，MoE 模型吞吐 +13.1%（长序列）/ +6.7%（混合）。  
- 工程价值：直接改 serving 调度/PP layout，不改模型；对 P/D 分离、长 prefill 集群有即时价值。Ascend 实现，NVIDIA 栈需移植。  
- 是否值得读：**强烈推荐**  
- Relevance Score：5  
- Link：https://arxiv.org/abs/2608.26523

**【Title】** More GPUs or a Smaller Cache? Tensor Parallelism versus KV Compression for Memory-Bound LLM Serving  
- 一句话总结：KV 爆了到底加卡做 TP，还是原地压缩 KV——把两者放到同一条「$/M token vs latency」轴上比。  
- 核心贡献：  
  1. 校准 A100/A40/H100 的 profiled simulator，扫 TP=1–8 vs 16/8/4-bit + keep-ratio 到 0.25。  
  2. **找不到成本交叉点**：压缩始终便宜 1.20–2.00×；容量/$ 压缩最高 16.5×，8 卡 TP 只有 1.21×。  
  3. 决策边界是「模型相对显存」：约 36B / 80GB；之下加卡浪费，之上权重本身进不去，压缩帮不上（70B 单 A100 不可行）。压缩伤 latency（+8–93%）。  
- 工程价值：容量规划 / 采购决策论文，不是新 kernel。结论可直接进 serving 架构评审。模拟器非线上系统。  
- 是否值得读：**强烈推荐**  
- Relevance Score：5  
- Link：https://arxiv.org/abs/2608.23962

### 2. AI Infra / 分布式训练

**【Title】** Training Communication-Efficient Mixture-of-Experts Language Models with Layer Re-Configuration  
- 一句话总结：别每层都挂 routed MoE；把 expert 容量集中到少数层，用 token-mix + dense FFN 补深度，砍 all-to-all。  
- 核心贡献：  
  1. 异构层模式：解耦 token-mix 深度和 channel-mix（expert）深度。  
  2. 2B–31.5B 阶梯、匹配总参/激活参：验证 loss 与下游持平。  
  3. 31.5B：GPU-hour **-33.3%**，下游略升，推理吞吐也升。  
- 工程价值：从模型拓扑减 EP 通信，比再拧一圈 NCCL 更稳；对 MoE 预训练成本账直接可见。要接受「不是每层都是 MoE」的架构约束。  
- 是否值得读：**强烈推荐**  
- Relevance Score：5  
- Link：https://arxiv.org/abs/2608.28511

**【Title】** Performance Foundations of Parallel & Distributed Reasoning Language Models  
- 一句话总结：把 RLVR/PPO/GRPO 训练当成多模型分布式系统，用 work-depth 把并行策略做成可移植 taxonomy。  
- 核心贡献：  
  1. 从算力视角拆 PPO/GRPO 变体（生成/打分/更新耦合）。  
  2. 分类 intra/inter-model 并行：传统 3D/SP/EP + 分离放置、stage fusion、异步。  
  3. 对照现有 RLM 框架，给可落地指南和开放问题。  
- 工程价值：没有新 kernel，但是 RL 后训练 infra 的「地图」。做 verl/OpenRLHF/自研 RL 集群的人值得通读一章 taxonomy。  
- 是否值得读：**可选**（综述型，但系统密度高）  
- Relevance Score：4  
- Link：https://arxiv.org/abs/2608.27046

### 3. LLM Agents（系统设计）

**【Title】** Logos: An Agent Harness on a Cross-Process Bus  
- 一句话总结：Agent plugin 不要塞进单进程；每个 capability 一个进程，共享状态只有 append-only transcript。  
- 核心贡献：  
  1. 用 composability calculus + LLM 无状态，证单进程不是必要条件。  
  2. ROS 风格跨进程 harness：故障域隔离。  
  3. 80 个 session 在 tool-call 四边界杀进程后可恢复且无重复副作用；对照单进程「一挂全挂」。  
- 工程价值：生产 agent runtime 的故障隔离/幂等/恢复，比再堆一个 planner 有用。偏形式化 + 故障注入，吞吐数字少。  
- 是否值得读：**可选**  
- Relevance Score：4  
- Link：https://arxiv.org/abs/2608.28553

**【Title】** HARTS: Efficient Agentic Reinforcement Learning for Hybrid-Attention Models over Arbitrary Rollout Trees  
- 一句话总结：Agentic RL 的不规则 rollout 树有大量共享前缀；在 hybrid-attention + 重计算上做前缀共享训练，而不是每条轨迹重算。  
- 核心贡献：  
  1. 前缀压缩后的 compact-token work 联合规划 microbatch / DP / slot。  
  2. chunkwise linear attention：线性时间协调边界 state replay，packed 一次前向反传。  
  3. SWE-bench 生成的 agentic RL：fwd/bwd/grad **4.81–4.87×**；数值差≈基线自重跑抖动；τ3-Bench 前 120 step 奖励曲线对齐。  
- 工程价值：Agent RL 训练墙钟的真瓶颈（共享 history 重算）。hybrid-attn（线性+softmax）栈可直接对标。Ant 出品，看复现材料。  
- 是否值得读：**强烈推荐**  
- Relevance Score：5  
- Link：https://arxiv.org/abs/2608.28158

### 4. SFT / Alignment / RLHF

**【Title】** Program Learning with Verifiable Rewards: Symbolic Backpropagation for Post-Training LLMs  
- 一句话总结：能逐步验的任务，别把推理能力焊进权重；学一个可检查的程序，用「符号反传」做稠密 credit assignment。  
- 核心贡献：  
  1. PLVR：程序层带类型本体，输出对 GT 算 loss，按 primitive 签名反向推输入契约（类比 chain rule）。  
  2. LiveCodeBench v6 + Tau2Bench：30B + PLVR 同预算打过 RL **+27.8**，打过大一个数量级的 frontier **+13.6**。  
  3. 新任务边际成本约 100 条例子 + 程序搜索，不重新 SFT；去掉反向搜索后程序质量崩（65.6→17.5）。发布符号反传库。  
- 工程价值：对齐/后训练的另一条路：能力外置、可审计、可迁移。不是标准 RLHF pipeline，集成成本在 primitive 库。  
- 是否值得读：**可选**  
- Relevance Score：4  
- Link：https://arxiv.org/abs/2608.28421

### 5. Reinforcement Learning

**【Title】** Learning to Use Tools: Reinforcement Learning for Tool-Integrated Mathematical Reasoning  
- 一句话总结：Countdown 上先 SFT 教会用计算器，再对比 RLOO/GRPO/DAPO；工具 + 终局可验证奖励就能把算术错误压下去。  
- 核心贡献：  
  1. 失败分析：大量错来自计算而非规划。  
  2. 新 1024 题 held-out Countdown（与训练无 exact overlap）。  
  3. 工具相对无工具约 +10pp pass@k；Tool-DAPO：pass@1 35.8%→**66.0%**。  
- 工程价值：工具调用 RL 的干净小实验；任务窄（Countdown+计算器），算法无新系统。可跳细节，看 SFT→RL 配方即可。  
- 是否值得读：**跳过**（除非你正在做 tool-RL 消融）  
- Relevance Score：2  
- Link：https://arxiv.org/abs/2608.28447

## 额外输出

### 1. 今日最值得读 Top 3
1. **VPP** — 长 prefill 流水线是线上立刻能改的东西；bubble 6.4%→0.1% 是硬指标，且挂在 vLLM 系实现上。  
2. **HARTS** — Agentic RL 从「算法」变成「树状 rollout 的训练系统」；4.8× fwd/bwd 对 hybrid-attn 训练栈是量级变化。  
3. **CE-MoE Layer Re-Config** — 用层拓扑换通信，31.5B 省 1/3 GPU-hour 且不掉点；比又一篇 all-to-all kernel 更可决策。

（honorable：*More GPUs or a Smaller Cache* 适合架构/成本评审，不一定要精读方法细节。）

### 2. 今日趋势观察
- **Inference / KV / 长上下文 serving 仍是主场**：chunked prefill 流水线、TP vs KV 压缩的成本轴、能量按 request 而非 token 记账，都在同一周出现。  
- **Agent 从「会规划」转向「runtime + 训练系统」**：跨进程 harness、rollout 树前缀共享，比新 planner 更密。  
- **MoE 通信**：两条线并行——改通信拓扑（hierarchical all-to-all 成本模型，本周 TerraceMoE 因 step-level gate 失败未收录）和 **改模型层布局减通信次数**（CE-MoE）。后者工程确定性更高。  
- **RLVR 系统化**：Hoefler 组把 reasoning LM 后训练明确写成分布式系统问题，说明 RL 训练 infra 已从框架战争进入并行理论层。

### 3. 值得跟进的潜在方向
1. **虚拟流水线 / 固定 chunk + 布局优化** 是否能迁到 GPU + P/D 分离的 decode 侧（VPP 目前是 Ascend prefill）。  
2. **Hybrid-attention + 树状 rollout 的通用训练 runtime**（HARTS 的 packed state handoff）——会成为 agent RL 框架下一轮标配。  
3. **「少挂 MoE 层」作为一等架构旋钮**：通信受限集群上，expert 密度按层非均匀分配，可能比无限加 EP 更划算。  
4. **Serving 成本轴统一**：把 TP、KV 量化/驱逐、批大小、能量同时画在一张 Pareto 上；本周已有两篇从 $ 和 Joule 两边戳同一漏洞（token 计价 ≠ 资源消耗）。
