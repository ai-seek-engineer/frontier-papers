## 1. Model Inference

【Title】MegaFlux: Skew-Resilient MoE Megakernels via Pipelined Expert Replication

- 一句话总结：固定 expert 放置下的路由偏斜会把 MoE megakernel 打成 straggler；MegaFlux 在不改 router 的前提下做运行时热 expert 复制，并把权重复制和反向梯度规约流水进 megakernel。
- 核心贡献（2-3点）：
  - 片上 planner 在每 GPU replica 预算内选复制位置并分配 tile 对齐 token block。
  - 前向在权重到达后立刻算；反向把 replica 梯度规约和 expert 计算重叠。扩展 TensorRT-LLM 的 CuTeDSL MegaMoE，并补了反向 megakernel。
  - 8×B200、147 组配置：前向几何均值 1.45×、反向 1.28×（峰值 2.14× / 2.64×）。流水线藏掉前向权重复制开销的 56–76%、反向相关开销的 91–100%。vLLM 上 DeepSeek-V4-Pro prefill 端到端中位 1.13–1.26×。
- 工程价值：直接可接到 MoE serving 的 prefill 路径。收益来自消除 EP 负载不均，而不是再压 KV。前提是已经在用 fused MoE megakernel；老的非 fused expert 实现收益会小。未看到公开代码。
- 是否值得读：强烈推荐
- Relevance Score：5
- Link：https://arxiv.org/abs/2610.00671

【Title】Decoding Looped Transformers Better for (Almost) Free

- 一句话总结：循环 Transformer 的中间 loop 本身就是免费的弱模型；LoopCD 用更早一次循环的预测去对比最终预测，免训练就能提高解码质量，并允许减半循环次数。
- 核心贡献（2-3点）：
  - 不训 draft model。LoopCD-Logits 多一次 output pass；LoopCD-Hidden 在隐状态空间对比，输出开销为零。
  - Ouro-2.6B-Thinking 的 AIME 2024 pass@1 从 61.88% 到 73.33%；Huginn 的 HumanEval 从 22.56% 到 31.71%。
  - 循环减半仍能打平或超过全深度无引导基线，前向 FLOPs 降 22.5–48.2%。
- 工程价值：只对 looped / recurrent depth 模型有意义，不是通用 speculative decoding。若你在部署 Ouro、Huginn 一类模型，这是几乎零集成成本的解码策略；标准 decoder-only 服务栈用不上。
- 是否值得读：可选
- Relevance Score：4
- Link：https://arxiv.org/abs/2610.02185

## 2. AI Infra / 训练系统

【Title】Leto: Fast In-Place Recovery for LLM Training on Surviving Hardware

- 一句话总结：很多训练中断是硬件仍可继续跑的故障（HOF），现有系统却按“机器死了”去重载 checkpoint；Leto 把可恢复状态留在同一套硬件上做原地恢复。
- 核心贡献（2-3点）：
  - 工作模型状态和可复用进程状态留在故障机上，其余状态由 shadow trainer 预初始化；显存紧时回收 shadow。
  - 两级纠删保护加 chunk 级事务更新，保证保留状态一致可恢复。
  - 6 / 72 卡 A100：恢复比最好的 checkpoint 基线快 3.6–6.5×，有效训练时间最高多 13.7 个百分点。13 万卡模拟下有效训练时间超过 95%。
- 工程价值：针对的是“进程/软件故障但 GPU 还活着”这一类，不是掉卡或换节点。大集群上 checkpoint reload 的空转成本很高，这类 in-place 路径值得放进训练容错设计。未看到代码；模拟到 13 万卡的外推要打折看。
- 是否值得读：强烈推荐
- Relevance Score：5
- Link：https://arxiv.org/abs/2610.00687

【Title】Format-Aware Fusion for Fast FP4 Pretraining

- 一句话总结：FP4 Tensor Core 的乘加收益经常被 scale、packing、layout 和反向状态吃掉；这篇把量化生产者、scale 域和消费者 layout 按 MXFP / NVFP 绑在一起做融合。
- 核心贡献（2-3点）：
  - 覆盖 native MXFP、global NVFP、CTA-local NVFP 三条路径，而不是只换 matmul 精度。
  - Llama-3 系列 8B、160B token。同卡探针上 BF16 18.8K、TE NVFP 27.6K tokens/s/GPU，自研最快路径 37.9K。MXFP + 行梯度随机舍入 + 固定符号 Hadamard 预条件到 37.2K（86.3% BF16 MFU）。
  - 训练 loss 终点比 BF16 高 2.11%；下游排序和 loss 排序不一致，说明 scale 合同和执行路径会改变结果，不能只看 tokens/s。
- 工程价值：给 Blackwell 上 FP4 预训练一个具体警告：kernel 融合方式和数值配方必须一起选。更像系统配方论文，不是可直接 drop-in 的库。出现在 10 月 2 日 cs.LG new 列表，提交记录写的是 9 月 4 日。
- 是否值得读：可选
- Relevance Score：4
- Link：https://arxiv.org/abs/2610.00053

## 3. LLM Agents

【Title】AutoCompact: Learning When to Compact Context in Long-Horizon Coding Agents

- 一句话总结：长轨迹 coding agent 的上下文压缩不该是固定阈值启发式；把“何时压、保留什么、压完怎么接着干”放进策略，用纠错轨迹做 SFT，再用任务成功做 RL。
- 核心贡献（2-3点）：
  - 先跑 base agent，由 judge 改 compaction 决策和摘要，再在环境里从修正后的状态继续，避免脏轨迹。
  - SFT 之后把编码动作和压缩动作联合 RL。
  - SWE-bench Verified / SWE-PolyBench Verified 绝对提升 9.2 / 5.0 个点；256K 窗口不溢出，16K 窗口溢出时退回 fallback compaction，各预算下都成立。
- 工程价值：可落地的 agent 上下文控制，不是又一个 memory benchmark。对 SWE agent 的 token 账单和窗口溢出都有直接含义。judge 纠错的数据管线是复现成本的大头，论文没给代码。
- 是否值得读：强烈推荐
- Relevance Score：4
- Link：https://arxiv.org/abs/2610.02163

## 4. SFT / Alignment / RL

【Title】CARM: Cancellation-Aware Response Masking for LLM Reinforcement Learning

- 一句话总结：rollout 引擎和训练引擎不一致时，常用的长度归一化几何平均 mask 会让正负 log-ratio 抵消，把明显 off-policy 的响应放进更新；CARM 先取绝对值再平均。
- 核心贡献（2-3点）：
  - 序列级 mask，不改 reward 或 advantage 估计器，改动面小。
  - 证明被接受响应同时受“越界 token 比例”和“越界平均 log 距离”约束。
  - AIME 2024/2025/2026 + BeyondAIME 的 mean@16 比几何平均 mask 高最多 3.13 个点；四个代码基准平均 pass@1 比最强基线高 2.88 个点。
- 工程价值：vLLM/SGLang rollout + 训练引擎的重要性比，是现在 RL 后训练的真实故障点。这是一个可以先加到 mask 逻辑里做 A/B 的补丁，不需要重写 trainer。没有代码链接。
- 是否值得读：强烈推荐
- Relevance Score：5
- Link：https://arxiv.org/abs/2610.02039

【Title】Finetuning with Sampling: SFT Learns Better Than You Think

- 一句话总结：不改 SFT 目标，用 MCMC 把专家轨迹逐步推到参考模型的 on-policy 邻域，让 SFT 在泛化和遗忘上接近 on-policy 后训练。
- 核心贡献（2-3点）：
  - 把“数据是否 on-policy”从学习算法挪到采样算子。
  - 覆盖科学技能、数学推理、开放域专长；作者称泛化更好、遗忘更少，且不只是把 base 分布变尖。
  - 采样被当作后训练栈里的通用原语，而不是某个 loss 的补丁。
- 工程价值：如果结论稳，可以少跑一轮昂贵的 on-policy RL。代价是每条轨迹要多次参考模型采样，数据准备成本不低。论文没给量化表和代码，工程上先当方向而不是配方。
- 是否值得读：可选
- Relevance Score：3
- Link：https://arxiv.org/abs/2610.02140

## 5. Reinforcement Learning

【Title】FERPO: Forward Entropy-Regularized Policy Optimization

- 一句话总结：连续控制里 critic 的动作梯度不可靠；FERPO 只用 critic 值构造熵+KL 正则的目标动作分布，再用 forward KL + SNIS 去拟合，不反传 critic。
- 核心贡献（2-3点）：
  - 目标分布相对 rollout policy 的 KL 约束用来稳住重要性权重。
  - forward KL 鼓励覆盖多个高价值模态，避免 reverse KL 塌到单峰。
  - MuJoCo Playground 和 ManiSkill 上样本效率有竞争力，actor 更新比 REPPO 快。代码：https://github.com/Atarilab/FERPO
- 工程价值：对机器人/连续控制有用，对 LLM RL 没有直接接口。有代码，值得控制方向的人跟，不值得推理/训练 infra 优先读。
- 是否值得读：可选
- Relevance Score：2
- Link：https://arxiv.org/abs/2610.02198

未入选但同批可见：TACO（三值列稀疏优化器，微调优化器状态降约两个数量级，有代码）偏优化器几何，工程收益还要看和 AdamW 预训练模型的对齐；KaliBench / Argo-Bench 是评测，不是系统方法。

## 今日最值得读 Top 3

1. MegaFlux。这批里唯一同时有 kernel、通信重叠、B200 微基准和 vLLM 端到端数字的论文。MoE serving 的下一个瓶颈就是 expert skew，不是再写一个 attention kernel。
2. CARM。改动面最小、对现有 LLM RL 管线最直接。几何平均 mask 的抵消问题在双引擎 rollout 里会稳定出现。
3. Leto。训练容错仍按 checkpoint 重载设计，HOF 原地恢复是集群有效 GPU 时间的杠杆。13 万卡是模拟，72 卡结果已经够读。

## 值得跟进的方向

MoE 运行时 expert replication。MegaFlux 说明固定放置已经不够，复制必须和 megakernel 通信重叠，否则权重复制会把收益吃掉。下一步值得看的是：decode 而不只是 prefill、replica 预算和 KV/显存预算怎么联合调度、以及训练和推理是否能共用同一套 planner。

另一个较小的方向是 LLM RL 的引擎不一致。CARM 把问题收成序列级 mask；若 rollout 和 trainer 的数值差继续变大，mask 只是第一层，重要性比的估计和 truncation 还会回来。
