### 1. Inference 优化

**【Title】** FlashPrefill V2: Block-Sparse Prefill Attention for Long-Context LLM Serving  
（arXiv:2608.19758，Submitted 20 Aug 2026）

- **一句话总结**：把之前的 FlashPrefill 从算法原型升级成可生产落地的 block-sparse prefill 算子，直接对接 SGLang 等框架。
- **核心贡献**：
  1. 引入 zero-order mean correction，把极端稀疏下的精度损失压到约 1 分以内（RULER/LongBench）。
  2. 算子对齐 FlashAttention-3/4（PackGQA、warp specialization、pingpong、FP8），原生支持 paged KV + continuous batching。
  3. H20 上 128K 上下文：相对 FA2 最高 47×（FP8）/27×（BF16），相对 FA3/4 dense 仍有 30×。
- **工程价值**：直接可替换现有 prefill 后端，显著降低 TTFT，尤其适合长上下文 + 高并发服务；代码级可集成性高。
- **是否值得读**：强烈推荐  
- **Relevance Score**：5  
- **Link**：https://arxiv.org/abs/2608.19758

**【Title】** OasisKV: Scaling In-Decode KV Cache Beyond HBM with Lookahead Sparse Prefetching  
（arXiv:2608.08097）

- **一句话总结**：用 speculative decoding 的 lookahead token 预测未来重要 KV，把全量 KV 从 HBM 卸载到 host/remote，只保留稀疏相关块。
- **核心贡献**：
  1. 解码期 attention 天然稀疏 + SD 草稿预测，2k token budget 下精度损失 ≤0.7。
  2. 基于 vLLM 实现，prefill-decode 解耦场景下吞吐约 2×，KV 传输量降 6.5–9.7×。
  3. multi-GPU 长上下文最高 2.1× dense vLLM。
- **工程价值**：直接解决 HBM 容量瓶颈，可与现有 PD 解耦架构叠加；对高并发/长上下文服务实用。
- **是否值得读**：强烈推荐  
- **Relevance Score**：5  
- **Link**：https://arxiv.org/abs/2608.08097

### 2. AI Infra / 分布式训练

**【Title】** ScaleAcross Explorer: Exploring Communication Optimization for Scale-Across AI Model Training  
（arXiv:2605.24326）

- **一句话总结**：Meta 生产经验驱动的跨机房/跨区域 LLM 训练优化器，联合优化并行放置、调度与网络层。
- **核心贡献**：
  1. 系统刻画 parallelism placement / scheduling / network 三维度交互。
  2. 端到端优化器，testbed + 模拟最高 64% 相对生产配置加速，37% 超 SOTA。
  3. 面向数十万 GPU 规模的实际部署考量。
- **工程价值**：对多 DC 训练、异构带宽环境有直接指导；通信优化路径清晰。
- **是否值得读**：可选（规模大才值得深挖）  
- **Relevance Score**：4  
- **Link**：https://arxiv.org/html/2605.24326

**【Title】** IsoExec: Unified Execution to Eliminate Trainer-Inference Mismatch in SkyRL  
（vLLM Blog，2026-08-21）

- **一句话总结**：统一训练与 rollout 引擎的浮点执行契约 + 对齐 kernel，彻底消除 RL 中 trainer-inference logprob 不一致。
- **核心贡献**：
  1. 定义 execution contract，强制 batch-invariant、bitwise 一致。
  2. SkyRL + vLLM + Megatron 实现，8×H100 上平均 logprob 差异压到极低，开销约 25%。
  3. 直接服务 on-policy RL 正确性。
- **工程价值**：RL post-training 的系统级痛点（mismatch 导致训练不稳定），工程落地价值极高。
- **是否值得读**：强烈推荐（RL 系统从业者必看）  
- **Relevance Score**：5  
- **Link**：https://vllm.ai/blog/2026-08-21-isoexec

### 3. LLM Agents / RL 相关（工程落地优先）

**【Title】** Learning to Evict from Key-Value Cache  
（arXiv:2602.10238）

- **一句话总结**：把 KV eviction 建模成 per-head RL 策略，用未来 utility 直接监督，轻量 agent 无需改 LLM。
- **核心贡献**：
  1. KVP 框架：仅用 K/V 向量训练轻量 RL agent，预测未来 token 效用。
  2. RULER + OASST 等多任务显著优于启发式；zero-shot 泛化到 LongBench 等。
  3. 无额外推理开销。
- **工程价值**：可直接替换现有 H2O/SnapKV 等启发式，提升长上下文内存效率。
- **是否值得读**：可选  
- **Relevance Score**：4  
- **Link**：https://arxiv.org/html/2602.10238

### 【额外输出】

**1. 今日最值得读 Top 3**
1. **FlashPrefill V2** — 真正把 sparse prefill 推到生产可用（算子对齐 + 框架集成 + 极端加速），长上下文服务直接受益。
2. **OasisKV** — HBM 卸载 + SD 预测的优雅系统方案，与 PD 解耦天然契合，吞吐提升实打实。
3. **IsoExec** — RL 系统从业者刚需：彻底解决 trainer-inference 数值不一致，影响训练稳定性与可复现性。

**2. 今日趋势观察**  
Inference 侧（尤其 KV 管理 + sparse prefill/decode + speculative decoding 联动）仍是绝对主流，且明显从“算法证明”转向“生产可集成算子/系统”。分布式训练通信优化与跨 DC 主题持续，但新作节奏放缓。RL/Agent 系统侧更关注 rollout-train 一致性与效率（IsoExec、经验回放等），而非纯算法。

**3. 值得跟进的潜在方向**  
- **Speculative Decoding + KV 稀疏/卸载的联合设计**（OasisKV 已开了好头）：用 draft 信息同时加速解码和指导内存管理，可能成为下一代 serving 标配。  
- **RL 训练中的数值一致性与执行契约**（IsoExec 类）：随着 on-policy RL 规模扩大，这会成为系统层刚需，值得做成通用中间件。  
- **Block-sparse prefill 的量化与 continuous batching 深度融合**：FlashPrefill V2 已证明可行性，后续可看与 MoE/ GQA 的进一步协同。
