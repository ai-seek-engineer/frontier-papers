### 【Title】Random Attention: Rethinking KV Cache Eviction for Efficient Reasoning
- 一句话总结：推理长 CoT 场景里，KV eviction 的“重要性打分”几乎没用；保 prompt + 每头随机丢即可对齐最强 evictor，vLLM 吞吐更高。
- 核心贡献（2-3点）：
  - 拆开“打分信号 vs 是否保住 prompt”：差距主要来自后者。
  - 推理轨迹有文本复述 + 跨 head 冗余，随机抽样就够。
  - 四模型、六推理任务，吞吐相对最强 evictor +32–43%。
- 工程价值：可直接塞进 vLLM 类 serving；零打分开销，实现比 SnapKV/H2O 更简单。有公开代码。
- 是否值得读：强烈推荐
- Relevance Score：5
- Link：https://arxiv.org/abs/2609.03430

### 【Title】Unlocking Lossless Speedups in LLMs via Discrete Diffusion（Uno / Ψ-Spec）
- 一句话总结：在保持原 AR 分布的前提下，用轻量 diffusion 头并行出多 token，做成无独立 draft model 的无损加速。
- 核心贡献（2-3点）：
  - AR 权重继续 NTP；diffusion 权重单独蒸馏，训练管线增量小。
  - Ψ-Spec：固定 context 下无损加速 + test-time scaling。
  - 各 batch size 吞吐高于主流 speculative decoding；最高约 3× vs 基座 AR；8B Uno 在 tool/coding/长上下文上打过更大 d-LLM。
- 工程价值：方向是“把 speculative 做进同一套权重”，比维护 draft 模型更干净；有 code + ckpt。接入现有 serving 仍需新采样路径。
- 是否值得读：强烈推荐
- Relevance Score：5
- Link：https://arxiv.org/abs/2609.04010

### 【Title】Hardware-Aware FP4 FlashAttention-4
- 一句话总结：Blackwell FP4 Tensor Core 不会自动让 attention 变快；要改 softmax/量化数据流才能吃到带宽。
- 核心贡献（2-3点）：
  - Direct-P：score 直接映射成 FP4 概率，GB200 前向最高 2.13× vs BF16。
  - Causal 路径把前向量化复用到 backward，8B 单卡 update 最高 1.14×。
  - 分布式训练里 MXFP4 概率/value 会发散，需回退 FP8——这是部署红线。
- 工程价值：给 Blackwell 上 attention kernel / 训练稳定性的硬约束，不是又一篇“4bit 更快”口号。
- 是否值得读：强烈推荐（做 kernel / 训练栈）
- Relevance Score：5
- Link：https://arxiv.org/abs/2609.04105

### 【Title】BASP: Communication-Efficient Batch-Aware Sequence Parallelism for LLM Training
- 一句话总结：现有 SP 对 batch 不敏感、通信组过大；按 micro-batch 切 SP 组，缩小 all-to-all。
- 核心贡献（2-3点）：
  - 用 micro-batch size 把 GPU 分成不相交 SP 组。
  - 通信局部化，精度与显存与 baseline 一致。
  - A100 上 Llama/Qwen e2e 训练 1.17–1.31×。
- 工程价值：Megatron/DeepSpeed 类长序列训练可直接试的并行改法，增量小、风险低。
- 是否值得读：可选
- Relevance Score：4
- Link：https://arxiv.org/abs/2609.03151

### 【Title】Speculative Macro Commit for Faster Tool-Using Agents
- 一句话总结：把 speculative decoding 从 token 级抬到“多步 tool 宏动作”：小模型在隔离环境预跑，大模型匹配后一次性 commit。
- 核心贡献（2-3点）：
  - 从训练轨迹挖 recurring action skeleton 做 macro library。
  - Actor 下一步对上 draft 首动作即提交后续观测。
  - τ²-Bench：精度持平，相对 sequential -18.6% 延迟；AppWorld wall time -44.9%（完成率略降）。有代码。
- 工程价值：agent 延迟瓶颈在 tool 串行，不在单 token；可挂现有两级模型 serving。
- 是否值得读：强烈推荐
- Relevance Score：5
- Link：https://arxiv.org/abs/2609.03236

### 【Title】Headroom-Drift Replay: A Primitive for Principled Replay Control in GRPO
- 一句话总结：agentic RL 的墙钟被环境 rollout 吃掉；只用“组级 replay 选择”就能省时间，不改 on-policy 主路径。
- 核心贡献（2-3点）：
  - Headroom 估剩余学习价值；Drift 门控与当前策略兼容性。
  - 不引入额外生成/混合策略管线。
  - 数学 / 多模态 / Agentic Search 上打赢 naive replay，质量对齐更重的 replay 方法，环境交互场景墙钟更低。COLM 2026。
- 工程价值：给现有 GRPO 训练栈加一个 buffer 策略就能降成本。
- 是否值得读：强烈推荐（做 RL post-train）
- Relevance Score：4
- Link：https://arxiv.org/abs/2609.03941

### 【Title】LeanGRPO: Eliminating Redundant Recomputation in Diffusion RL
- 一句话总结：DanceGRPO/FlowGRPO 在同 backend on-policy 下对选中 timestep 二次前向是数学冗余；改 DP 布局干掉 recompute。
- 核心贡献（2-3点）：
  - Retain：rollout 带梯度，update 直接复用图/激活。
  - Reweight：逐步用临时 advantage 反传，轨迹结束后校正。
  - FLUX.1-dev / Wan 上最高 1.83× e2e，目标函数不变。
- 工程价值：diffusion RL 训练栈的纯系统优化，模式可迁移到 LLM RL 的“rollout 与 update 同引擎”场景。
- 是否值得读：可选（做生成模型 RL infra）
- Relevance Score：4
- Link：https://arxiv.org/abs/2609.03528

1. **Random Attention**

3. **Speculative Macro Commit**  
   Agent 产品真正的延迟在 tool 回合。把 spec 从 token 抬到 action chain，工程叙事完整、有代码。

## 今日趋势观察

- **Inference / KV 仍是主航道**：随机 eviction、NoPE-MLA 自带 eviction 信号（VestigeKV，更窄）、FP4 attention、边云 spec 同一天出现。社区在从“更好的 importance score”转向“打分可能不必要 / 信号已在 cache 布局里”。
- **Agent 从算法转向 runtime**：宏动作投机提交 + 异构 GPU 工作流编排，说明瓶颈已是调度/环境交互，不是再写一个 planner prompt。
- **RL 论文工程化**：GRPO replay 控制、diffusion GRPO 去重算，都在抠 rollout 墙钟，而不是新 reward 公式。

## 值得跟进的潜在方向

1. **Reasoning-trace 冗余感知的 KV 策略**：Random Attention 的结论暗示“保 prompt + 极简 eviction”可能是默认正确；下一步是自适应压缩比，而不是更贵的 scorer。
2. **跨粒度 speculative**：token（Uno）→ tool macro（SMC）→ workflow 物理图（异构调度）。统一“draft / verify / commit”抽象会成为 agent serving 标准件。
3. **低精度 attention 的训练红线**：FP4 前向能加速，MXFP4 训练会发散。推理量化与训练稳定是两条线，不要混用同一套 recipe。
