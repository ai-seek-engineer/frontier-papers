### 【Title】BeaconKV: Key-Value Cache Compression Guided by Beacon Queries
- 一句话总结：针对长 CoT 推理模型的“回头看早期计划”现象，用少量 beacon query 代替整段 query 历史做 KV 压缩。
- 核心贡献（2-3点）：
  - 指出现有压缩默认“最近 query ≈ 未来注意力”，在 LRM 长推理上失效（Thought Revisiting Tokens）。
  - training-free：把 query 聚类成少量 beacon，预测会被重访的 KV。
  - 最高约 5.8× 显存下降、吞吐 >4.3×，精度接近满 cache。
- 工程价值：可直接挂到 decode 路径做 reasoning serving；不改权重。实现成本主要是 query 聚类/维护，比再训 draft 模型便宜。
- 是否值得读：强烈推荐
- Relevance Score：5
- Link：https://arxiv.org/abs/2609.04971

### 【Title】VestigeKV: The NoPE-MLA KV Cache Carries Its Own Sparse-Attention Signal
- 一句话总结：在 NoPE-MLA 上，用 cache 里已有的 64-d 解耦分支当 salience 通道，做到 **query-independent + training-free** 的稀疏注意力调度。
- 核心贡献（2-3点）：
  - 打穿 H2O/SnapKV 在“查询尚未出现就要压 cache”时的失败模式。
  - 11% row 读取即可分出 attended tier + GPU archive；行不量化、不训练。
  - Kimi Linear 48B：8× 压缩 retrieval=1.00，32× 仍 0.96（8k–65k）。
- 工程价值：对 MLA/NoPE 产线极有针对性；选择+调度可落地，不绑量化内核。非 MLA 架构不要硬套。
- 是否值得读：强烈推荐（做 MLA serving 必读）
- Relevance Score：5
- Link：https://arxiv.org/abs/2609.03949

### 【Title】Epoch: Compiling Diffusion Blocks for Sparse MoE Serving
- 一句话总结：把 diffusion LM 的 block 当编译单元，而不是把每次 refinement 当普通 dense MoE forward。
- 核心贡献（2-3点）：
  - 编译 block plan：活 token / 新 decode / 必须 refresh 的位置才走 routed expert。
  - 覆盖驱动的 active expert 集合 + FreshLane 贯穿 EP dispatch/combine。
  - 8×H100，LLaDA-MoE 系列 7B–100B：端到端最高 2.7×，大 batch 基线 OOM 时仍可跑。
- 工程价值：扩散语言模型一旦进 serving，vLLM 式 token-clock 会浪费专家通信。这是少见的 **compiler + MoE runtime** 真系统文。
- 是否值得读：强烈推荐
- Relevance Score：5
- Link：https://arxiv.org/abs/2609.09748

### 【Title】Miles v0.1: Production-Level Post-Training
- 一句话总结：开源全栈 post-training：SGLang rollout + Megatron/FSDP trainer + 三种权重同步，并跑通 744B 异步 agentic RL。
- 核心贡献（2-3点）：
  - 组件可验证、可替换：full RL / LoRA RL / on-policy distillation / SFT / 扩散 RL。
  - 64×GB300 上 GLM-5.2 744B-A40B 终端 coding，前 30 step 中位 263s/step。
  - 明确 rollout-train 对齐与异步拆分。
- 工程价值：比再发一篇 PPO 变体有用。可当内部 RL infra 对照实现。
- 是否值得读：强烈推荐（做训练 infra）
- Relevance Score：5
- Link：https://arxiv.org/abs/2609.08368

### 【Title】KVMem: Virtualizing Million-Token Agent Workspaces on a Consumer GPU
- 一句话总结：把 agent 工作区溢出历史当 **paged KV**（GPU/Host/NVMe），而不是摘要或反复 prefill 文本。
- 核心贡献（2-3点）：
  - 注意力空间轻量索引选历史 block，物化不超过原生窗口的 execution view。
  - DeepSWE + Qwen3.8-27B：成功率 43.8%→48.4%（相对纯 compaction）。
  - 笔记本 24GB RTX 5090 Laptop：27B NVFP4 + MTP，虚拟 1M tokens，约 50 tok/s。
- 工程价值：agent 长会话的正确抽象是 **KV 虚拟内存**，不是无限 context。可与 paged attention / prefix cache 组合。
- 是否值得读：强烈推荐
- Relevance Score：5
- Link：https://arxiv.org/abs/2609.04852

### 【Title】From Monolithic Blending to Agentic Orchestration（生产客服）
- 一句话总结：超大混成模型拆成 **有界 ReAct 编排器 + 小 generator + 后端校验的 context contract**，并给出线上延迟/成本。
- 核心贡献（2-3点）：
  - 百万级/月、11 语、P90 10s 约束下的架构迁移。
  - 编排器 P90 3.87s→2.24s，GPU 占用约降 1/3。
  - 自托管相对外购推理成本下降一个数量级量级。
- 工程价值：少见的真实流量 agent 系统设计，不是新算法。调度/契约/延迟预算可抄。
- 是否值得读：可选（偏产品架构，算法增量少）
- Relevance Score：4
- Link：https://arxiv.org/abs/2609.05758

### 【Title】Cache-Aware Joint Router Adaptation for Memory-Efficient MoE Inference
- 一句话总结：把 expert cache 命中当成 **模型侧可训问题**，后训练轻量 cache router，推理仍走原生 Top-K。
- 核心贡献（2-3点）：
  - Temporal Router：预测同层复用，不主动预取。
  - Spatio-Temporal：用因果前驱 hidden 预热 cache。
  - Qwen3 上相对最强 prefetch：hit +1.15–18.03pt，权重流量 -4.6–53.3%。
- 工程价值：MoE decode 的瓶颈常是专家搬运。可与现有 expert cache/prefetch 叠加，不必改 serving Top-K 语义。
- 是否值得读：可选
- Relevance Score：4
- Link：https://arxiv.org/abs/2609.04895

### 【Title】Long-Horizon Language Model Reinforcement Learning via Progressive Point Matching
- 一句话总结：用无偏的段级 dense reward（对照一条参考轨迹做 progressive matching）替代稀疏 outcome，让超长 horizon 数学 RL 能动起来。
- 核心贡献（2-3点）：
  - 理论+合成环境：段级奖励对长轨迹的样本效率指数级更好。
  - 每任务只需一条 reference trajectory 即可实例化。
  - 极难数学：稀疏 reward 零进展；段奖励在更大 test-time budget 上抬升 success/pass@k。
- 工程价值：不直接加速推理，但降低长程 RL 的 rollout 浪费；和 Miles 这类异步 RL 栈是配套方向。
- 是否值得读：可选
- Relevance Score：4
- Link：https://arxiv.org/abs/2609.07303

## 今日最值得读 Top 3

1. **Epoch**  
   Diffusion-MoE 一旦上线，现有 serving 时钟模型会系统性浪费 EP 通信。这是本窗口里系统味道最纯的一篇：编译单元换了，吞吐 2.7× 有对照。

2. **KVMem + BeaconKV（并列第二，按你栈选一篇精读）**  
   - 做 **agent 长会话**：KVMem。工作区 ≠ context window，这是产品级抽象纠偏。  
   - 做 **LRM/长 CoT serving**：BeaconKV。压缩假设被长推理打穿，方法可插。

3. **Miles v0.1**  
   744B 异步 agentic RL 的可运行栈比又一篇 reward shaping 更值钱。用来对齐内部 slime/verl/OpenRLHF 设计。

## 今日趋势观察

- **Inference / KV 仍是主航道**：压缩从“最近 token 启发式”转向 **结构信号**（MLA vestige、reasoning beacon、head-level summarization）。
- **Serving 时钟在分裂**：自回归 token-clock vs diffusion block-clock vs agent session-clock。一套 vLLM 默认假设不够用。
- **Agent 论文里真正有工程含量的，开始谈 KV 虚拟化、编排器延迟、生产契约**，而不是再堆一个 ReAct prompt。
- **Post-training infra 开源化**：异步拆分、权重同步、on-policy distillation 被写成可替换组件，而不是实验室脚本。

## 值得跟进的潜在方向

1. **Query-independent KV 选择**：VestigeKV 只在 NoPE-MLA 上漂亮；GQA/MLA/混合注意力上有没有等价“cache 自带 salience”？
2. **Agent workspace = 分层 KV OS**：GPU hot / host warm / NVMe cold + 注意力索引，而不是无限摘要。
3. **非自回归 / block-diffusion MoE 的编译式 serving**：Epoch 只开了一个口，EP 通信与 live-token 集合还会再出一轮系统活。
4. **量化 × prefix cache 的可复现性**：同请求不同答案已被量化放大（相邻工作 [Same Request, Different Answer](https://arxiv.org/abs/2609.04748)）。线上开 cache + 低比特权重前，先测 trajectory 漂移，别只看吞吐。
