【Title】
Disaggregated Quantization: Specializing LLM Prefill and Decode  
arXiv:2609.26333 · 2026-09-22

- 一句话总结：把量化拆成 prefill / decode 两套格式与权重，而不是整条链路共用一种量化。
- 核心贡献（2-3点）：
  - Prefill 走低精度算力友好格式（如 NVFP4），Decode 走更紧的权重量化；decode 阶段去掉 activation 量化，decode-heavy 任务精度回升且不增加 decode 成本。
  - 单独训一份 compute-native prefill 权重，decode checkpoint 不动；Qwen3.8-27B 上 1-bit decode 的 MMLU-Pro / MMMU-Pro 分别 +32.5 / +35.3。
  - Offloaded Disaggregated Prefill（ODP）从 SSD 流式加载 prefill 权重，8K prompt 上 TTFT 相对 weight-only baseline 1.78×；在 vLLM 里做了 disaggregated serving 精度验证，PTQ 做到 2.8T。
- 工程价值：直接贴合现有 P/D disaggregation。多一份 prefill checkpoint 是真实运维成本，但 ODP + vLLM 路径说明这不是实验室玩具。对「长 prompt、短生成」和「极低 bit decode」两类产品都有明确杠杆。
- 是否值得读：强烈推荐
- Relevance Score：5
- Link：https://arxiv.org/abs/2609.26333

【Title】
CompKV: Compensation-Aware KV Selection for Long-Context LLM Inference  
arXiv:2609.26300 · 2026-09-22

- 一句话总结：稀疏注意力不要先按 attention mass 选 token 再补偿，而应按「漏选后补偿残差最大」来选。
- 核心贡献（2-3点）：
  - 把 token 分块，选择目标显式对齐下游 block-mean compensation；理论给出残差由 block attention mass × 块内 logit 方差共同决定。
  - 用块级统计量近似残差，可部署；异步实现把选择开销藏到计算后面。
  - RULER / LongBench-Pro 上优于评过的稀疏基线，self-attention 最高 6.85× vs full attention。
- 工程价值：长上下文 serving 的主矛盾仍是 KV 带宽。这是「选哪些 token」而不是又一种 eviction 启发式，和现有 sparse attention / 补偿类 kernel 可组合。缺公开代码声明，落地需要自己对 kernel。
- 是否值得读：强烈推荐（做长上下文推理的人）
- Relevance Score：4
- Link：https://arxiv.org/abs/2609.26300

【Title】
Flash-dLLM: IO-Aware KV Caching and Parallel Decoding for Fast, Memory-Efficient Diffusion LLMs  
arXiv:2609.26796 · 2026-09-22

- 一句话总结：给 diffusion LLM 补上 I/O 友好的 fused KV kernel，并用模型自身做 draft-and-verify，不另训 draft model。
- 核心贡献（2-3点）：
  - 指出 dLLM + KV cache 后主瓶颈是 GPU memory I/O，不是「再少算一点 attention」。
  - 自 draft / 自 verify 的并行解码，和 fused cache 绑在一起，而不是两套独立加速。
  - 相对最强基线 Elastic-Cache：GSM8K 5.1×、HumanEval 11.0×；有代码：https://github.com/VILA-Lab/Flash-dLLM
- 工程价值：若你还在纯 AR serving，这篇是旁路；若团队在跟 dLLM / block-diffusion，这是目前最像能进推理栈的一篇。Kernel 思路（减少 cache 相关冗余搬运）对 AR 的 fused attention 也有迁移价值。
- 是否值得读：可选（AR 团队）/ 强烈推荐（dLLM 团队）
- Relevance Score：4（方向相关则 5）
- Link：https://arxiv.org/abs/2609.26796

说明：Inference 方向严格应只留 2 篇。上面第三篇是因为 dLLM 推理本周密度异常，单独保留；若只能读两篇，丢 Flash-dLLM、留前两篇。

【Title】
Flux: Optimal Scheduling of Optical Circuit Switches for LLM Training  
arXiv:2609.25949 · 2026-09-22

- 一句话总结：光电路交换机不要按聚合流量单独排程，要按整次 iteration 的 compute/comm 结构排，把 recon 延迟藏进计算。
- 核心贡献（2-3点）：
  - 指出「OCS 调度与 compute 解耦」会让通信卡 recon、电路利用率低、NIC buffer 暴涨。
  - 跨不同 switching 速度复用电路、摊销 recon。
  - 相对周期调度：iteration time 最高约 10×，峰值 NIC buffer 降三个数量级以上。
- 工程价值：只有在上 OCS / 光电混合互联的集群才刚需。对 InfiniBand 以太网集群是前瞻，但对下一代训练网络拓扑设计是硬参考：调度必须看见集体通信时间表，而不是看见流量矩阵。
- 是否值得读：可选（无 OCS 可跳细节，读问题定义即可）
- Relevance Score：4
- Link：https://arxiv.org/abs/2609.25949

【Title】
NSP: Accelerating Variable-Length LLM Training via Nested Sequence Parallelism  
arXiv:2609.22755 · 2026-09-19（窗口边缘，但系统增量够硬）

- 一句话总结：长尾序列长度下，不要把 GPU 切成互斥的 SP 组，而在同一批 GPU 上嵌套不同大小的 SP 组。
- 核心贡献（2-3点）：
  - 点破 dynamic-SP 的二次不平衡：分组切卡 → 组间再 imbalance → 再靠 micro-batch 补。
  - 嵌套 SP，共享 GPU，兼容常见 SP backend，模型代码不用改。
  - 生产集群、Qwen3-MoE、最长 384K：相对 Static SP 最高 1.48×，相对 FlexSP 最高 1.16×。
- 工程价值：长上下文 / 变长 packing 训练的真实痛点。1.16–1.48× 在千卡上就是真金白银。实现复杂度高于「再调一个 SP degree」，但问题定义对上了生产数据分布。
- 是否值得读：强烈推荐（训练系统）
- Relevance Score：5
- Link：https://arxiv.org/abs/2609.22755

【Title】
DeepSeek Elastic Compute (DSec): A Sandbox Infrastructure for Effective Agentic Training at Scale  
arXiv:2609.22978 · 2026-09-19

- 一句话总结：把 agentic RL 的 stateful sandbox 做成可弹性超卖的生产平台，而不是「每条 rollout 起一个 Docker」。
- 核心贡献（2-3点）：
  - 统一 SDK 覆盖 FnCall / container / microVM / full-VM；分层镜像 + 3FS 按需拉镜像。
  - 与 RL 框架共设计：stateful rollout 和可抢占 GPU 训练解耦，空闲回收、保留 rollout 状态，并处理 reward hacking。
  - 单生产单元约 160 节点、日均约 300 万 sandbox、并发 >38 万、创建速率 >5k/s。
- 工程价值：Agent RL 的隐藏瓶颈已经从 GPU 变成环境密度、镜像分发和生命周期。这篇是系统设计报告，可复用思路（分层环境、内存共享、训练-环境协同调度），不是新算法。
- 是否值得读：强烈推荐（做 agent 训练平台）
- Relevance Score：5
- Link：https://arxiv.org/abs/2609.22978

【Title】
Measuring the Serving Stack Instead of the Model: Hidden Confounds in Local Tool-Use Evaluation  
arXiv:2609.26693 · 2026-09-22

- 一句话总结：本地 tool-use「模型不会调工具」经常是 serving 栈的协议/模板问题，不是模型能力。
- 核心贡献（2-3点）：
  - Ollama 默认 `tools=` 被静态 template flag 拦住：部分模型文本回 tool call，部分走 native `tool_calls`，Phi-3/Gemma-3 直接在推理前拒绝。
  - 拒绝/重试耗尽若没进结构化失败元数据，下游会记成 0% fidelity。
  - 跨 Ollama / vLLM / SGLang 同一请求行为不同；constrained decoding 消灭 parse fail 但可能不终止；turn-pooled vs per-instance 估计差约 55 分。
- 工程价值：极高。任何本地 agent / tool 评测、任何「换一个 inference engine 分数崩了」的排查清单。比再发一篇 agent 框架有用。
- 是否值得读：强烈推荐（短、立刻能改评测协议）
- Relevance Score：4
- Link：https://arxiv.org/abs/2609.26693

【Title】
Towards Full Pipeline FP8 Reinforcement Learning for LLMs  
arXiv:2609.22870 · ByteDance Seed · ~2026-09-19/22

- 一句话总结：全链路 FP8 RL 会炸熵，不是只靠 TIS 修 train-infer mismatch 就能稳；要用校准过的 clip bound。
- 核心贡献（2-3点）：
  - 诊断：FP8 clip 边界和 BF16 分布不对齐，坏更新惩罚不足并累积，表现为中途 entropy surge。
  - Calibrated Clipping：按下界分位数对齐 BF16，再平衡上界，恢复 trust-region 语义。
  - GRPO / DAPO，8B–32B，多种 FP8 granularity：熵尖峰消失，性能回到 BF16；吞吐最高约 1.5× BF16。
- 工程价值：RLVR / agentic RL 的训练成本正在逼近 pretrain。能把整条 rollout+update 推到 FP8 且不塌，是训练栈优先级事项。和「只量化 generator」不是同一件事。
- 是否值得读：强烈推荐
- Relevance Score：5
- Link：https://arxiv.org/abs/2609.22870

【Title】
Beyond Repeated Sampling: Learning Search Policies for LLM Reasoning  
arXiv:2609.26704 · 2026-09-22

- 一句话总结：pass@k 别只会独立采样；用 RL 训一个小 concept generator，给冻结的大 answer model 提供可探索的搜索策略。
- 核心贡献（2-3点）：
  - 把「多采几条完整答案」改成「一条轨迹吐多样 concept，再生成答案」。
  - 小模型 RL，目标是最大化冻结大模型的下游成功率；可迁移到未一起训过、甚至不同家族的 answer model。
  - 困难数学上，同等 answer 计算预算下明显超过 naive repeated sampling，也超过更大未调 concept 模型。
- 工程价值：test-time compute 的调度问题，不是又一个 verifier。对推理产品：小模型当 search policy、大模型当 solver，比无脑 N 路采样更可控。还不是 serving 系统论文。
- 是否值得读：可选
- Relevance Score：3
- Link：https://arxiv.org/abs/2609.26704

【额外输出】

1. 今日最值得读 Top 3  
   - **Disaggregated Quantization**：P/D 已经是主流 serving 形态，量化却还按整模型一套走；这篇把格式、权重、落盘位置按阶段拆开，并给了 vLLM / ODP 路径。  
   - **Full Pipeline FP8 RL**：Agent/推理 RL 的成本墙；不解决 FP8 稳定性，量化加速只停在 generator。  
   - **DSec 或 NSP（按职责二选一）**：做 agent 训练读 DSec（环境密度才是瓶颈）；做长上下文训练读 NSP（变长 SP 的正确抽象）。评测/agent 协议问题另加一篇短文 Serving Stack。

2. 今日趋势观察  
   - Inference 明显偏「阶段特化 + KV 流量」：prefill/decode 量化拆分、补偿感知稀疏 KV、dLLM 的 IO-aware cache。Speculative decoding 仍有稿（DeepSeek-V4 tree spec，09-21），但增量弱于量化/KV。  
   - Infra 从「再写一个并行维度」转向「看见真实异构」：变长序列嵌套 SP、OCS 与 compute 联合调度、agent sandbox 超卖。  
   - Agent 论文里，有系统设计/评测污染分析的比「又一个 multi-agent 协议」更值得看。  
   - RL 与系统交叉变密：FP8 全管线、sandbox 与训练解耦，而不是新 reward 公式。

3. 值得跟进的潜在方向  
   - **Prefill/Decode 异构量化与异构 checkpoint**：一份 decode GGUF + 一份 NVFP4 prefiller + SSD 流式，是否会成为单机/边缘默认形态。  
   - **Compensation-aware sparse KV**：选择准则和补偿算子联合设计，而不是「先 evict 再补」。  
   - **Agentic RL 的环境层**：镜像分层、状态保留、防 reward hacking，会先于新 RL 算法成为产能瓶颈。  
   - **FP8（及更低）RL 的数值契约**：clip / 重要性采样 / 熵在量化空间里语义漂移，是接下来半年训练栈必打的补丁。  
   - **dLLM 推理栈**：若 dLLM 继续进产品，缺的不是算法而是 fused KV + 自投机解码，和当年 AR 补 FlashAttention / paged KV 同一阶段。
