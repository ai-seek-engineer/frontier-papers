### 1. Inference / 推理优化

【Title】AgentSpec: Speculative Decoding for Batch Inference of LLM Agents  
- 一句话总结：面向 **Agent 批量推理** 重做 speculative decoding，解决大 batch 下传统 SD 掉速甚至变慢的问题。  
- 核心贡献（2-3点）：  
  1. 诊断两个根因：agent 工作流语义路径乱猜导致拒稿率高；动态 token budget 用不满。  
  2. structure-isolated drafting：只在工作流语义段内投机，拒稿率极低。  
  3. redundancy-aware budget allocation：用 agent 级信息分配空闲 draft budget。  
- 工程价值：直接打在 vLLM 上，4 家模型 × 5 类 workload；现有 EAGLE-3 / NGram / SuffixDecoding 在 agent 大 batch 上会慢于自回归，AgentSpec 仍能到约 **2.02×**。可复用到 tool-call / 多段 JSON / 固定 schema 输出。  
- 是否值得读：强烈推荐  
- Relevance Score：5  
- Link：https://arxiv.org/abs/2608.24004

【Title】Elastic KV Cache for LLM Serving: A Working Reclamation Mechanism, and Why Chunked Prefill Already Closes the Gap  
- 一句话总结：用 CUDA 用户态 VMM 把 prefill 预留显存在 decode 期借给 KV pool，并给出一个少见的 **负结果**：chunked prefill 已经把收益吃掉了。  
- 核心贡献：  
  1. 不改 attention kernel、兼容 CUDA Graph / prefix cache 的弹性 VMM 分配器。  
  2. 静态占用会在 prefill burst 上 OOM，动态 toggle 必要。  
  3. 实测：chunk 8k vs 32k 的 TTFT 中位差约 1%；调 `max_num_batched_tokens` 往往比弹性回收更赚；TP4 时预留只占 KV 的 2.7%。  
- 工程价值：对 vLLM/SGLang 调度器设计很有用——别再盲目做“decode 回收 activation reserve”。低 TP、超长 context、极端 burst 才可能有 ~18% KV / ~10% decode 吞吐。机制会开源。  
- 是否值得读：强烈推荐（负结果比新 SOTA 更省坑）  
- Relevance Score：4  
- Link：https://arxiv.org/abs/2608.23658

### 2. AI Infra / 分布式训练 / 系统优化

【Title】psRL: Efficient Training for Agentic AI via Training-Time Prefix Sharing  
- 一句话总结：Agentic RL 瓶颈从 rollout 转到 **update**；用训练样本前缀冗余做分布式前缀共享，吞吐最高 **5.2×**。  
- 核心贡献：  
  1. 明确新瓶颈：tree / stepwise RL 让样本暴增，update 主导端到端。  
  2. 两种前缀共享调度：细粒度切分 + 负载均衡。  
  3. 可变 block + 动态 KV manager，兼顾命中率与显存。  
- 工程价值：直接服务 VeRL / slime / AReaL 一类训练栈。生产 trace 验证；代码即将开源。树采样、共享 system prompt、多 rollout 同 prompt 的训练都能吃到。  
- 是否值得读：强烈推荐  
- Relevance Score：5  
- Link：https://arxiv.org/abs/2608.25683

【Title】Performance Foundations of Parallel & Distributed Reasoning Language Models  
- 一句话总结：把 RL-for-LLM（PPO/GRPO 及变体）当成 **多模型并行系统** 做 taxonomy，而不是算法综述。  
- 核心贡献：  
  1. 从算力视角拆 PPO/GRPO 流水线成本。  
  2. 覆盖 DP/TP/PP/SP/CP/EP，以及拆分放置、stage fusion、hybrid、async。  
  3. 用 work-depth 模型给可移植的系统指南与开放问题。  
- 工程价值：做 RLM 训练框架选型/扩容的地图。Hoefler 组出品，适合对照 LlamaRL / VeRL / AReaL 的并行缺口。无单点 SOTA 数字，偏架构。  
- 是否值得读：可选（做训练系统必读，做推理可扫）  
- Relevance Score：4  
- Link：https://arxiv.org/abs/2608.27046

### 3. LLM Agents（系统设计 / 落地）

【Title】Agent Lightning v1.0: Towards Harnessed Agentic RL  
- 一句话总结：训练时不重写 agent，用真实 harness（工具/控制流/环境）做 RL；~3500 行，K8s 原生。  
- 核心贡献：  
  1. 定义 harnessed agentic RL：harness 拥有环境循环，训练引擎只经 endpoint proxy。  
  2. 处理 retokenize、sample merge、advantage、loss norm、collocated async 调度。  
  3. Qwen3.5-9B + 6K 样本，SWE-bench Verified **41.8% → 56.4%**。  
- 工程价值：可复现流水线 + 防 reward hacking；已被 Uni-Agent / AReaL 2.0 / slime / Polar 一类框架借鉴。这是目前最接近“用生产 agent 直接 RL”的开源路径。  
- 是否值得读：强烈推荐  
- Relevance Score：5  
- Link：https://arxiv.org/abs/2608.17528  
  代码：https://github.com/microsoft/agent-lightning

【Title】Zero-Shot Self-Orchestration with Ledger-Based Control for Improved LLM Coding Performance  
- 一句话总结：无训练、无 per-bench 调参的 manager–worker + 共享文件系统 + ledger，在 LiveCodeBench hard 上测清“多 agent 到底赚什么”。  
- 核心贡献：  
  1. 控制变量：同一模型单 pass vs 同一 scaffold，不混 token budget / 工具。  
  2. 收益条件化：部分模型 +10~30 分，部分持平或变差。  
  3. 机制主要是上下文管理与问题分解；manager 大约 3× token，但可比换更大模型更便宜。  
- 工程价值：别默认上 MAS。小模型 / 关 reasoning 时更值；大模型开 reasoning 增益有限。有账本式状态，比纯 prompt 编排可运维。  
- 是否值得读：可选  
- Relevance Score：3  
- Link：https://arxiv.org/abs/2608.26480

## 额外输出

### 1. 今日最值得读 Top 3

1. **psRL** — Agentic RL 的成本结构已经变了：tree/stepwise 采样让 update 成为主瓶颈。这是少有直接打 update 吞吐、还有 5.2× 和生产 trace 的系统文。  
2. **AgentSpec** — Speculative decoding 从“单请求加速”进入“agent 批量服务”。现有 SD 在 agent 大 batch 上会负优化，这篇给了可进 vLLM 的改法。  
3. **Elastic KV Cache** — 少见的诚实负结果 + 可复用 VMM 实现。能避免团队花几周做 decode 回收 activation reserve，却发现 chunked prefill 已经够用。

（若只能再加一篇落地文：Agent Lightning v1.0，看 harness 与训练引擎如何拆，以及 SWE-bench 的完整脚本。）

### 2. 今日趋势观察

- **Inference × Agent 交叉明显变密**：投机解码、KV 调度、TTL、session-aware routing 都在从“通用 LLM serving”改写成“多轮 + 工具 + 状态”。  
- **RL 训练系统重心后移**：rollout 优化已经很多，新文开始打 **update 前缀共享、异步 off-policy、自适应 TP、harness 对齐**。  
- **KV 工作进入“分层/弹性/负结果”阶段**：不再只是 eviction heuristic，而是 HBM 外预取、VMM 回收、以及证明某些回收没必要。  
- Alignment/SFT 本周安静，工程注意力在 serving 与 agentic RL infra。

### 3. 值得跟进的潜在方向

1. **Update-phase prefix sharing**：tree RL / GRPO 多样本同前缀会成为训练标配，psRL 这类 KV/调度应进主流框架。  
2. **Agent-aware speculative decoding**：结构约束 draft + 动态 budget，比通用 EAGLE 更贴 tool/JSON/plan-act 循环。  
3. **Harness-owned RL**：训练循环不重写 agent；关键工程问题是 retokenize、advantage 对齐、collocated GPU 分时。  
4. **“先证明不值得做”的 serving 机制**：chunked prefill vs 弹性 KV 这类负结果，能大幅减少无效 infra 投入。
