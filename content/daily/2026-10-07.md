### 1. Model Inference

【Title】DeferKV: Rethinking Eviction Timing for One-Shot KV Cache Compression

- 一句话总结：一次性 KV 淘汰不要在 prefill 结束就拍板，推迟到第一个真实 decode step，用生成侧 attention 修正重要性估计。
- 核心贡献（2-3点）：
  - 量化了 prefill query 与后续 decode attention 的不一致，最大单步收益在 prefill–decode 边界。
  - 把 prompt 侧和第一步 decode 侧信号做时间融合后再做不可逆淘汰。
  - 无训练、无 draft、无未来 query 预测，评测覆盖 LongBench、RULER、NIAH。
- 工程价值（重点分析：是否能用于推理/infra优化）：可直接挂到现有 one-shot 压缩（StreamingLLM / SnapKV 类）后面，改的是淘汰时机而不是 kernel。延迟几乎不增加，适合长上下文 serving 在固定预算下抬质量。不是带宽优化，不能替代 offload 或量化。
- 是否值得读：强烈推荐
- Relevance Score：4
- Link：https://arxiv.org/abs/2610.06286

【Title】Shared Stopping Decisions Change Answers in HQQ Cache Quantization

- 一句话总结：HQQ 做 KV cache 量化时，batch 内共享的停止误差会让无关请求改写目标答案。
- 核心贡献（2-3点）：
  - request-local group 仍用共享平均误差决定何时停止更新，4-bit 下 170/384 次对比答案被同 batch 的其他问题改变。
  - 重放对方的 update count 可以双向复现答案和 cache fingerprint。
  - FP32 停止均值只能减小 cache 差，消不掉答案变化；固定迭代或 request-local stopping 可去掉该依赖。
- 工程价值（重点分析：是否能用于推理/infra优化）：这是 serving 正确性 bug，不是加速论文。任何把 HQQ 接到 continuous batching 的实现都该先查 stopping 是否跨请求共享。修复是调度/数值问题，不需要新模型。
- 是否值得读：强烈推荐
- Relevance Score：5
- Link：https://arxiv.org/abs/2610.06251

### 2. AI Infra

【Title】MOLT: A Fine-Grained GPU Memory Sharing System for LLM Serving with Opportunistic Fine-Tuning

- 一句话总结：推理副本里秒级波动的空闲显存，按 activation 粒度借给 PEFT，推理要内存时只重算被抢走的 activation，不丢掉整个 step。
- 核心贡献（2-3点）：
  - 指出副本是 autoscaling 的最小单位，副本内部空闲显存回不来。
  - 回收粒度从整个 training sample 降到 backward 已保存的单个 activation，且只回收没有 in-flight GPU 工作仍在引用的内存，覆盖 CPU–GPU 异步和 TP。
  - 24B–70B、H100 SXM 与 B200、trace 负载下，推理 SLO 达成率 ≥99.7%，完成的微调工作量是丢弃式共享的 1.9–3.3×。
- 工程价值（重点分析：是否能用于推理/infra优化）：直接对应“推理低谷顺便微调”的生产形态。关键不在 colocating，而在秒级回收且不废 step。实现成本在显存所有权和异步依赖追踪，不是算法。适合已有 serving + PEFT 流水线的团队评估。
- 是否值得读：强烈推荐
- Relevance Score：5
- Link：https://arxiv.org/abs/2610.05748

【Title】From Overloaded to Guaranteed: High-Throughput Multi-SLO Enforcement for LoRA-Assisted On-Premise LLM Deployment (HALO)

- 一句话总结：私有化多 LoRA 服务的 SLO 被 LoRA 计算开销和刚性 batch 打穿，HALO 用 SM 分区重叠 base/LoRA，并按 request slack 调度。
- 核心贡献（2-3点）：
  - 空间复用：把 GPU SM 分区，让 base 与 LoRA 计算重叠，而不是串行加一层。
  - 按 request-level slack 解耦执行，紧急请求优先，空闲预算做 traffic shaping。
  - 目标是压 SLO violation，同时相对现有 serving 提高吞吐。论文给出的是方向性结果，绝对倍数需读全文核对。
- 工程价值（重点分析：是否能用于推理/infra优化）：对准医院、政务这类单机/小集群、多适配器、多 SLO 的部署，而不是公有云大池。SM 分区依赖具体 GPU 占用模型，迁移到 vLLM/SGLang 前要确认和 CUDA graph、TP 是否冲突。
- 是否值得读：可选
- Relevance Score：4
- Link：https://arxiv.org/abs/2610.04956

### 3. LLM Agents

【Title】Mining Agent Skills from Production Traces

- 一句话总结：生产 trace 往往没有可靠成败标签，技能挖掘不该默认用 success-only 证据或单一技能形态。
- 核心贡献（2-3点）：
  - 固定挖掘流水线，比较六种证据类型 × 技能形态。
  - ThinkingBox-Bench 上 workflow 比 ontology 高 1.7 pp，Goldilocks 比 success-only 高 2.4 pp；无结果标签的 blind 模拟差 3.1 pp。
  - APEX-Agents 偏好 ontology，证据体制差异不明显。任务结构比统一 meta-skill 更决定收益。
- 工程价值（重点分析：是否能用于推理/infra优化）：对技能库产品有直接启示：不要用成功轨迹一刀切。增益小，不是系统优化，也没有新 runtime。适合做 agent 平台的人扫结论，不适合当本周实现项。
- 是否值得读：可选
- Relevance Score：2
- Link：https://arxiv.org/abs/2610.05777

### 5. Reinforcement Learning

【Title】LoGRA: Scaling LLM Reinforcement Learning with Low-Rank Gradient Sketches

- 一句话总结：用低秩梯度草图留下 RL 更新信号，再加预测式 KL 步长控制，把原本单机八卡放不下的 LLM RL 变成可跑。
- 核心贡献（2-3点）：
  - 低秩草图同时服务参数更新和策略同步，而不是只做通信压缩。
  - predicted-KL step control 在应用更新前估计策略偏移并缩放步长。
  - 推理任务上平均训练显存最高降 45.7%，27B 在单机 8 卡稳定跑过 1100 step，dense Adam 同配置 OOM。代码在 Molt library。
- 工程价值（重点分析：是否能用于推理/infra优化）：这是训练侧显存墙，不是推理。对只有单机 8 卡、又要做 reasoning RL 的团队价值最高。草图秩和 KL 预测的数值稳定性需要在自己的 reward 上复现，不能直接当无损 Adam 替换。
- 是否值得读：强烈推荐
- Relevance Score：5
- Link：https://arxiv.org/abs/2610.06647

边界外但值得知道：10-04 的 HiNa-MoE（CPU AMX 上 MoE FFN 最高 3.37×、端到端最高 2.09×，PACT 2026）和 TP/PP 解析模型（arXiv:2610.05305）不计入本日主列表。

## 今日最值得读 Top 3

1. MOLT。问题定义清楚：副本级扩缩容填不满秒级显存空洞。activation 级回收加 in-flight 安全，是能进 serving 代码的系统工作，且有 H100/B200 和 24B–70B 数据。
2. LoGRA。单机八卡把 27B RL 从 OOM 拉到 1100+ step，显存降幅有数，并给出代码入口。比多数 alignment 论文更接近工程瓶颈。
3. HQQ shared stopping。不是加速，但会让量化 KV 的答案依赖 batch 同伴。已上线 4-bit KV 量化的服务应先核对 stopping 是否跨请求，再谈吞吐。

DeferKV 紧随其后：改动小、无训练，适合作为 KV 压缩的默认补丁，但系统杠杆小于上面三篇。

## 今日趋势观察

推理和 infra 仍主导，且都围着内存墙，不是新解码算法。本日有效工作集中在三处：KV 量化的批处理正确性、副本内部空闲显存、on-prem 多 LoRA 的 SLO。Agent 稿数量不少，但多为 trace 挖掘或模块类比，缺少 runtime 或工具沙箱层面的系统设计。RL 侧值得看的是优化器显存，不是新 reward。

## 值得跟进的潜在方向

推理与微调在同一 GPU 上按 activation 生命周期共享显存。MOLT 说明回收可以细到 backward 保存的 activation，并在异步和 TP 下保持安全。下一步值得看的是：这套所有权模型能否接到 continuous batching 的 KV 分配器上，以及低谷微调会不会污染前缀缓存和 CUDA graph。另一条是批处理诱导的数值非确定性。HQQ 的共享停止条件说明量化状态机如果跨请求聚合，SLO 和正确性会绑在一起。
