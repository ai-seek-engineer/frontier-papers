### 【Title】OasisKV: Scaling In-Decode KV Cache Beyond HBM with Lookahead Sparse Prefetching  
**arXiv:2608.08097**（8 Aug 2026）  
- **一句话总结**：用 speculative decoding 的 lookahead token 预测未来重要 KV，实现 decode 阶段 HBM 外稀疏预取，显著突破 HBM 容量瓶颈。  
- **核心贡献**：  
  1. 利用 SD draft token 做训练无关的未来 KV 重要性预测，保持仅 0.7 点精度损失（2k token budget）。  
  2. 背景 attention pipeline + 多级内存（host/remote）预取，与 vLLM 深度集成。  
  3. Prefill-decode 解耦场景下，KV 传输量降 6.5–9.7×，decode 节点 host 内存降 2.2–2.6×。  
- **工程价值**：直接可插 vLLM 类 serving 系统；对 long-context / reasoning / multi-GPU 吞吐提升 1.69–2.1×，是当前最实用的 HBM-offload + sparsity 方案之一。  
- **是否值得读**：强烈推荐  
- **Relevance Score**：5  
- **Link**：https://arxiv.org/abs/2608.08097  

### 【Title】Fewer Tokens, Smaller Cache: Reward-Coordinated Efficient Reasoning (ReCo)  
**arXiv:2608.04771**（5 Aug 2026）  
- **一句话总结**：用轻量 process-reward 同时驱动自适应 KV 压缩、reflection 惩罚和 early-stop，从生成侧与缓存侧双向砍掉 reasoning 冗余。  
- **核心贡献**：  
  1. 发现高 reward step 对 context 丢失更 tolerant，据此做 step-wise adaptive compression。  
  2. 小 cache 会诱发更多 token 生成的“补偿效应”被显式建模并抑制。  
  3. 三组件统一在 process reward 下，token 量降 37–65%，端到端延迟 2.08–2.35×。  
- **工程价值**：推理优化直接可用（尤其 reasoning model serving）；不依赖复杂训练，主要改 decoding 策略与 cache 管理，易于落地到现有引擎。  
- **是否值得读**：强烈推荐  
- **Relevance Score**：5  
- **Link**：https://arxiv.org/abs/2608.04771  

### 【Title】CommBench: Can LLMs Write Correct and Efficient GPU Communication Code?  
**arXiv:2608.04450**（5 Aug 2026）  
- **一句话总结**：首个大规模、可自动验证的 GPU 通信代码生成 benchmark（>100 任务，覆盖 P2P/collective/EP/fusion），揭示当前 LLM 在系统编程上的巨大缺口。  
- **核心贡献**：  
  1. 专家级参考实现 + 编译/执行/性能联合评估框架（防作弊）。  
  2. 覆盖 NVLink 与 RDMA，统一正确性+性能指标。  
  3. 最强模型（GPT-5.5）仅 30.7% 任务达到竞争性能。  
- **工程价值**：AI Infra / 分布式训练通信层自动化的关键基础设施；对写 NCCL 替代、kernel fusion、EP 通信的工程师极有参考价值，也可作为评估系统 LLM 的标准。  
- **是否值得读**：强烈推荐（Infra 方向）  
- **Relevance Score**：4.5  
- **Link**：https://arxiv.org/abs/2608.04450  

### 【Title】Muscle Memory for Agents: Compile not Merely Retrieve  
**arXiv:2608.08995**（10 Aug 2026）  
- **一句话总结**：把反复出现的用户意图编译成专用 specialist agent，而不是每次检索+解释，显著降低 multi-turn 纠正税。  
- **核心贡献**：  
  1. 提出 “compile vs retrieve” 的 memory 范式，四阶段 pipeline（Harvest→Analyze→Augment→Evaluate）。  
  2. 行为模式与任务模式分离 + 质量门控 + 两阶段触发。  
  3. 90 场景实验：specialist 触发时 88.9% win rate，个性化增益 +2.05，准确率损失极小。  
- **工程价值**：Agent 系统设计可直接借鉴；对生产级个人化/垂直 agent 有落地路径（编译后可缓存、可版本化、可调度）。  
- **是否值得读**：可选（有系统实现与实验）  
- **Relevance Score**：4  
- **Link**：https://arxiv.org/abs/2608.08995  

### 【Title】Practical Online KV Cache Compaction for LLM Agents: An Empirical Study  
**arXiv:2608.00902**（2 Aug 2026，仍属近期高相关）  
- **一句话总结**：系统评估 agent 场景下的 online KV compaction（未来 query 未知），发现延迟 compaction + token eviction 比 attention matching 更稳健。  
- **核心贡献**：  
  1. 对比 TE vs AM，以及多种 cheap proxy（boundary / repeat-prefill / delayed future）。  
  2. 立即 compaction 常伤性能，延迟到 agent 未来 query 可恢复大部分 gap。  
  3. TE 在 80% cache 压缩下仍保持大部分 accuracy，并提升吞吐。  
- **工程价值**：Agent serving 的 KV 管理实操指南，比纯算法论文更贴近生产 online 路径。  
- **是否值得读**：可选  
- **Relevance Score**：4  
- **Link**：https://arxiv.org/abs/2608.00902

**今日最值得读 Top 3**  
1. **OasisKV** — 真正把 speculative decoding 的 draft 信号变成系统级 KV 预取与多级内存管理，吞吐数字扎实，直接对接 vLLM，是 inference 工程师本周最高 ROI 论文。  
2. **ReCo** — 从“只砍 cache”升级到“协调生成与 cache”，对 reasoning 模型成本控制有明确可落地路径，实验覆盖广。  
3. **CommBench** — 暴露 LLM 在 GPU 通信系统编程上的真实能力鸿沟，同时提供可复现评估基础设施，对 AI Infra 团队和系统 LLM 研究者都极有价值。

**今日趋势观察**  
- Inference / KV 管理持续高密度：HBM 容量、稀疏预取、reward 驱动压缩、agent online compaction 都在出现。  
- Speculative decoding 已从“加速技巧”变成系统信号源（OasisKV 用它做 lookahead）。  
- Agent 方向更偏“系统设计与 memory 范式”，而非纯 prompt 工程。  
- AI Infra 出现对通信代码生成的严肃 benchmark，说明系统层自动化需求在上升。

**值得跟进的潜在方向**  
1. **SD-as-signal**：把 speculative draft 当作未来访问模式预测器，用于 cache prefetch / eviction / 调度（OasisKV 已开端）。  
2. **Process-reward 驱动的联合优化**：同时控制 token 生成长度与 KV 预算（ReCo 路线）。  
3. **Compile-time agent specialization**：从 retrieval memory 走向可执行、可缓存的 compiled specialist（Muscle Memory 思路），适合生产多用户个性化场景。  
4. **LLM-for-systems 评估基础设施**：CommBench 类 benchmark 可扩展到 kernel、调度、存储等更多系统层。  

今日高价值论文集中在 inference 系统与 agent 落地设计，纯算法小改动较少。优先读 OasisKV 和 ReCo。
