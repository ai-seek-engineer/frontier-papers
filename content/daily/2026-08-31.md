### 1. Inference / 长上下文 Prefill

**【Title】** VPP: Virtual Pipeline Parallelism for Efficient Chunked Prefill in Long-Context LLM Inference

- 一句话总结：不改 chunk 大小，用 V 形虚拟流水级把长序列 chunked prefill 的中间重计算和邻 chunk 的头/尾轻计算重叠，打掉 pipeline bubble。
- 核心贡献：
  - 指出 Dynamic CPP 用动态 chunk 换负载均衡，长序列上调度开销不划算。
  - VPP：固定 chunk + virtual stage + 异步通信/打包，针对 MoE + 超长 prefill。
  - 16× Ascend 910C、最长 1M token：吞吐最高 +13.1%；512K DeepSeek-V3.1 prefill bubble 6.4%→0.1%。
- 工程价值：直接打 vLLM-Ascend 类 chunked prefill 流水；思路可迁到 GPU PP/EP（V-shape 遍历、跨请求 drain bubble）。长上下文 prefill 集群值得对照现有 DCPP/Sarathi。
- 是否值得读：强烈推荐
- Relevance Score：5
- Link：https://arxiv.org/abs/2608.26523

### 2. Inference / Speculative Decoding（机制上限）

**【Title】** Beyond Parallel Blindness: Information Floors and Model Gaps in Block Drafting

- 一句话总结：把 block drafter 的拒绝拆成“块内信息缺失下界”和“模型没拟合好可观测信息”，解释并行草稿为什么天花板低。
- 核心贡献：
  - 全并行信息地板在 Qwen3-4B 末槽达 0.286 → 单槽接受率理论上限约 71%。
  - 只要实现 **1 个已生成 token** 的短程条件，地板可消掉 86–100%。
  - 现有 DFlash/DSpark 大量拒绝来自 model gap，不是信息论下限。
- 工程价值：不要再盲目加并行 draft 宽度。优先：短程条件（串行 1 token / 局部依赖）+ 提高 draft 质量，而不是堆更多并行槽。对 MTP/block speculative 产品路线有决策价值。
- 是否值得读：强烈推荐（短、结论可落地）
- Relevance Score：5
- Link：https://arxiv.org/abs/2608.27339

### 3. Inference / KV Eviction

**【Title】** TwinKV: A Composable Repair Pass for KV Cache Eviction via Pairwise Key Redundancy

- 一句话总结：attention 分数和 token 对答案的因果贡献几乎无关（Spearman ≈ 0），用 key 近重复做“修补层”交换孤儿/冗余 donor。
- 核心贡献：
  - 用 leave-one-out 打穿主流 eviction 的 attention-score 假设。
  - TwinKV 是 composable repair，不替换原 policy、不改预算。
  - LongBench/LooGLE/RULER 上对部分 policy 有增益，对已近天花板的 adaptive policy 和 few-shot 分类基本无效。
- 工程价值：可挂在现有 eviction（H2O/SnapKV 类）后面做后处理；增益不稳，先当诊断工具：检查你的 eviction 是否在“丢掉无副本的关键 token”。不建议直接上生产。
- 是否值得读：可选
- Relevance Score：3
- Link：https://arxiv.org/abs/2608.27128

### 4. AI Infra / RL-for-LLM 训练系统

**【Title】** Performance Foundations of Parallel & Distributed Reasoning Language Models

- 一句话总结：把 R1/o3 类 RLVR 训练当成分布式系统问题，用 work-depth 给 PPO/GRPO 及多模型流水线做并行分类和容量规划。
- 核心贡献：
  - 从计算视角拆 PPO vs GRPO 及其变体的成本结构。
  - 税目：DP/TP/PP/SP/CP/EP + 多模型特有的 disagg placement、stage fusion、hybrid parallel、async。
  - 对照现有 RLM 框架，给可执行的系统设计指南和开放问题。
- 工程价值：做 RL post-training 集群的必读地图。不是新 kernel，但是排期、切分、异步 actor-learner、多模型共置的决策框架。Hoefler 组，系统味重。
- 是否值得读：强烈推荐
- Relevance Score：5
- Link：https://arxiv.org/abs/2608.27046

### 5. AI Infra / Agent RL 训练吞吐

**【Title】** psRL: Efficient Training for Agentic AI via Training-Time Prefix Sharing

- 一句话总结：agentic RL 瓶颈已从 rollout 转到 update；利用样本前缀冗余做训练期 prefix sharing，吞吐最高 5.2×。
- 核心贡献：
  - 树/逐步 RL 让样本暴涨、rollout 边际成本低 → update 占墙钟。
  - 两种细粒度 prefix-sharing 调度（复用 vs 负载均衡）。
  - 动态块大小 + KV manager，提高 prefix hit。
- 工程价值：Megatron/FSDP + agent RL（tree GRPO 等）可直接借鉴；和推理 prefix cache 同源，但用在 **不可变 update batch**。代码声称将开源。生产 trace 验证。
- 是否值得读：强烈推荐
- Relevance Score：5
- Link：https://arxiv.org/abs/2608.25683

### 6. LLM Agents（系统设计）

**【Title】** WikiSkill: Compiling Agent Experience into Persistent Knowledge for Skill Evolution

- 一句话总结：把执行轨迹、可沉淀 wiki、可执行 skill 三层拆开，用持久知识库驱动 skill 迭代，而不是只在优化历史里散落 insight。
- 核心贡献：
  - experience / wiki / skill 分离，持续把经验编进 wiki 再生成 skill。
  - 多 benchmark：优于现有 skill-evolution；小模型+skill 可超更大无 skill 模型。
  - skill 可跨模型迁移，甚至“别人演化的 skill”优于自己演化。
- 工程价值：Agent 产品里 skill 库怎么版本化、如何避免每次从 log 重挖，这篇给了可落地架构。不是 serving 优化，但是 agent runtime/知识层设计。
- 是否值得读：可选（偏产品架构，非推理栈）
- Relevance Score：4
- Link：https://arxiv.org/abs/2608.27454

### 7. SFT / Alignment / RLHF（DPO 调参）

**【Title】** Disentangling Optimization Scale from Preference Scale in DPO

- 一句话总结：DPO 的 β 同时管“偏好噪声尺度”和“有效步长”，所以固定 LR 下 KL 对 β 非单调，loss 曲线跨 β 不可比。
- 核心贡献：
  - 小 β 死区、中 β 峰值、大 β 再压 KL。
  - 相同 loss 可对应数倍参考 KL。
  - centered-softplus 改写：argmin 等价，两个尺度可独立调；β→0 连续到线性 margin。
- 工程价值：任何还在扫 β 的对齐训练都应改目标或至少解耦 LR。能解释“换 β 效果乱跳”。实现改动小。
- 是否值得读：可选（短、对 DPO 产线有用）
- Relevance Score：4
- Link：https://arxiv.org/abs/2608.27032

### 8. RL / 推理后训练

**【Title】** Understanding Evolution Strategies for LLM Reasoning: Broader Reasoning Coverage than GRPO

- 一句话总结：ES 不是“省显存的弱 GRPO”；群体多样性带来更宽 reasoning coverage（更高 Pass@K），可与 GRPO 串起来用。
- 核心贡献：
  - 理论：verifier 投影的 JS 多样性利于 Pass@K。
  - GRPO 熵崩、ES 保 Pass@K；GRPO→ES 顺序训练兼顾 Pass@1 与 Pass@K。
  - 大参数漂移但功能稀疏；大模型可用更小 population。
- 工程价值：推理模型 post-train 多一条低激活/无 critic 路径；Pass@K 产品（采样多解）比纯 greedy 更相关。注意 ES 通信/评估开销，需和 Hoefler 那篇一起看系统成本。
- 是否值得读：可选
- Relevance Score：4
- Link：https://arxiv.org/abs/2608.27351

## 值得跟进的潜在方向

1. **Virtual / 非均匀 pipeline layout（VPP 类）**  
   固定 chunk + 改遍历形状，比动态切 chunk 更适合超长 MoE prefill。下一步看 GPU + DeepSeek/Qwen-MoE 能否复现 bubble≈0。

2. **Speculative decoding：短程条件 > 更宽并行草稿**  
   一块并行草稿的信息地板已经测出来了。跟进方向是 1-token lookahead、局部依赖 draft、以及把 model gap 压下去，而不是 MTP 宽度竞赛。

3. **Agentic RL 的 update-side prefix sharing**  
   rollout 优化空间变小后，训练 batch 的公共前缀是下一波 Megatron/verl 补丁点。psRL 若开源，值得对标现有 packing/prefix-cache。

4. **（略出窗口但同主题）KV 预留内存弹性回收**  
   Aug-24 的 Elastic KV 给出负结果：chunked prefill 已经吃掉大部分 reserve。新 KV 论文要先回答“chunked prefill + TP 之后还剩多少可回收内存”，否则容易空转。
