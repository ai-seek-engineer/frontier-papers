### 1. Model Inference / 推理优化

**【Title】** Practical Online KV Cache Compaction for LLM Agents: An Empirical Study  
（arXiv:2608.00902，2026-08-02）

- **一句话总结**：针对Agent长轨迹的在线KV compaction实证，揭示“立即压缩伤害性能、延迟压缩+代理query才有效”，Token Eviction在不完美proxy下更稳健。
- **核心贡献**：
  - 系统对比Token Eviction vs Attention Matching，并适配Agent turn-level压缩。
  - 研究边界/重复prefill/延迟未来生成等廉价proxy源，证明延迟使用Agent未来query可大幅恢复性能。
  - 跨规模模型验证：TE在80% KV压缩下保留大部分精度，且可提升吞吐。
- **工程价值**：直接可落地到vLLM等serving引擎的Agent路径。当前Agent推理的最大瓶颈就是轨迹KV膨胀，本文给出实用在线策略与关键设计选择（proxy-query），对长horizon Agent serving有即时指导意义。
- **是否值得读**：强烈推荐  
- **Relevance Score**：5  
- **Link**：https://arxiv.org/abs/2608.00902

**【Title】** Fewer Tokens, Smaller Cache: Reward-Coordinated Efficient Reasoning  
（arXiv:2608.04771，2026-08-05）

- **一句话总结**：用process reward统一协调KV压缩强度与生成侧冗余（reflection token惩罚+早停），实现推理模型端到端加速。
- **核心贡献**：
  - 发现高reward step对压缩更耐受，低reward step更敏感，提出reward-adaptive压缩。
  - 同时约束生成侧：reward-banded reflection惩罚 + confidence early-stopping。
  - 在多推理模型+6 benchmark上，token数降37-65%，端到端latency 2.08-2.35×，精度基本保持。
- **工程价值**：把“压缩”与“生成行为”放在同一reward闭环，比单纯KV eviction更系统。对Long-CoT推理serving（尤其需要控成本的场景）有直接优化路径，轻量reward estimator可集成。
- **是否值得读**：强烈推荐  
- **Relevance Score**：5  
- **Link**：https://arxiv.org/abs/2608.04771

**【Title】** RestoreKV: Recovering Full-Cache Behavior Under Aggressive Query-Agnostic KV Cache Eviction  
（arXiv:2608.01247，2026-08-02）

- **一句话总结**：在query-agnostic eviction后，用极少量LoRA restore token从全量KV生成紧凑“恢复缓存”，显著降低激进压缩带来的性能崩塌。
- **核心贡献**：
  - 关键“丢失信息虽context-specific，但恢复机制可共享”的洞察。
  - 参数高效自蒸馏（仅优化0.4%参数），无任务特定调优。
  - 在多个backbone与benchmark上，对5种基线eviction方法在绝大多数预算下均有提升（如5%预算时KVzip从38.2→73.2）。
- **工程价值**：query-agnostic场景（一次压缩多次复用）是生产高复用率路径。RestoreKV开销极低（<0.5%一次性），可叠加现有eviction，适合长上下文prefix缓存优化。
- **是否值得读**：可选（有明确系统价值，但创新幅度中等）  
- **Relevance Score**：4  
- **Link**：https://arxiv.org/abs/2608.01247

### 2. LLM Agents / RL相关

**【Title】** HindSearch: Trajectory-Level Hindsight Critique for Search-Augmented Reinforcement Learning  
（arXiv:2608.01597，2026-08-03）

- **一句话总结**：对失败搜索轨迹用hindsight critique（judge看gold answer）生成辅助蒸馏信号，显著提升search-augmented GRPO效果。
- **核心贡献**：
  - 解决binary exact-match reward浪费失败轨迹信息的问题。
  - 冻结judge写短critique → 学生on-policy蒸馏搜索动作。
  - 在标准7-benchmark上Qwen2.5-3B达到39.4%平均EM，优于先前search-RL基线；去掉gold answer后增益消失，确认hindsight是关键。
- **工程价值**：对search/tool-use Agent的RL post-training有直接参考。失败轨迹利用率低是当前Agent RL的痛点，本方法实现成本低（frozen judge），可集成现有GRPO pipeline。
- **是否值得读**：可选  
- **Relevance Score**：3.5  
- **Link**：https://arxiv.org/abs/2608.01597
