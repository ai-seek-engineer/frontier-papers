## 1. Inference

【Title】ResidualQuant: KV Cache Quantization for Looped Transformers with 2-Bit Residuals

- 一句话总结：循环 Transformer 的 KV 随 loop 数线性膨胀，用末轮 KV 当参考、其余轮只存 2-bit 残差，把带宽墙打回去。
- 核心贡献（2-3点）：
  - 利用跨 loop KV 高度相似，残差走 least-square scale + rotation，再加 loop 级混精。
  - 理论 KV 存储降 80.7%，混精下精度接近 BF16；同内存预算比 rotation baseline 高最多 13 个点。
  - RTX 5090 上固定 batch decode 最高 2.73×，更小 footprint 允许 2× batch，峰值吞吐最高 4.15×。
- 工程价值：只对 looped / recurrent-depth 模型有直接收益，普通 decoder 不能照搬。若你们在上 Ouro / looped 推理，这是 KV 流量而不是算力问题，kernel 侧主要是残差重构，部署面比稀疏 eviction 小。
- 是否值得读：强烈推荐（仅限 looped 模型栈）
- Relevance Score：4
- Link：https://arxiv.org/abs/2610.10381

【Title】Democratizing MoE inference on commodity GPUs with CoMoE

- 一句话总结：消费级卡没有 NVLink / P2P，EP 的 all-to-all 不该再按数据中心拓扑做；把 host 提升成路由枢纽。
- 核心贡献（2-3点）：
  - Dispatch：共享 token 只写 host 一次（host-backed multicast），去掉出站冗余。
  - Combine：host staging 上做 token 级聚合，拆掉全局同步，减轻 straggler。
  - RTX 5090 上吞吐最高 1.46×，接近有 NVLink 的 A800，硬件成本约 23.4%。
- 工程价值：本地 / 隐私 MoE 服务可以直接用。收益来自 PCIe 拓扑，不是算法近似，精度风险低。要确认实现是否开源、以及和 SGLang/vLLM EP 的接口差距。
- 是否值得读：强烈推荐
- Relevance Score：5
- Link：https://arxiv.org/abs/2610.09424

## 2. AI Infra

【Title】Expert Coupling in MoE Pretraining: Reducing All-to-All Overhead with Correlated Placement and Token Shuffling

- 一句话总结：预训练早期 router 已经形成专家共激活，用它做放置和 token 搬运，不改路由决策。
- 核心贡献（2-3点）：
  - MI300X 上 EP32 top-2 all-to-all 占 step 45%，top-6 占 60%。层内 0.8% expert pair 吃掉 42% token。
  - Correlated placement + 每 token 每 GPU 只发一次，最多去掉 58% dispatched rows；sequence parallel 下在 attention 后的 reduce-scatter 里把 token 预送到下一层专家所在卡。
  - Megatron-LM，EP 8–64，all-to-all 时间 1.16–2.63×，端到端 step 最高 1.41×。数学等价。
- 工程价值：训练通信优化里少见的“不改模型语义”。可直接对标现有 EP planner。放置要随 router 漂移重算，否则早期统计会过期。
- 是否值得读：强烈推荐
- Relevance Score：5
- Link：https://arxiv.org/abs/2610.09372

【Title】NeMo-DCR: Bit-Exact Delta-Compressed Refit for Scalable Agentic RL at Trillion-Parameter Scale

- 一句话总结：Agentic RL 的训练/rollout 分离后，跨区传完整 checkpoint 是主路径阻塞；只传变化且 bit-exact。
- 核心贡献（2-3点）：
  - BF16 训练每步大约 1% 权重的存储值变化。跨 AWS region 传 1T 全量要 87.5 min。
  - 仿射映射 + XOR mask / overwrite，接收端 in-place 应用，失败可重试，joint commit 绑定下一轮 delta 的基线。不重建完整 tensor，不走跨集群 collective。
  - 30B–1T、变化率 3–5% 时比纯传输全量快 12–40×；1T、3% 变化的 relay-tree refit 约 150 s。代码在 NeMo RL PR #2444。
- 工程价值：disaggregated RL / 多集群 rollout 的 weight sync 可以直接跟。bit-exact 比“近似 delta”更适合上生产。前提是变化率维持在个位数百分比。
- 是否值得读：强烈推荐
- Relevance Score：5
- Link：https://arxiv.org/abs/2610.08430

## 3. LLM Agents

【Title】CoTrace: Data Recipes for Training Terminal Agents with Harness-Model Co-Evolution

- 一句话总结：terminal agent 的能力在权重和 harness 的接口上，轨迹不能无差别回放。
- 核心贡献（2-3点）：
  - harness 搜索和策略训练交替、按组件晋升，避免“用过期 harness 的轨迹训当前策略”。
  - 失败模式驱动 harness 合成；SFT 只用与已采纳 runtime 匹配的验证 rollout，RL 用新交互。
  - Tmax split 上 Qwen3.5-9B SFT 从 78 到 88 solved，在线 RL 变体到 90；小的 harness 匹配语料优于更大的混 harness 池。
- 工程价值：有用的是数据路由，不是又一个 agent 框架。做 coding/terminal agent 的团队应把 trajectory provenance 当成一等字段。绝对分依赖私有 split，外推要谨慎。
- 是否值得读：可选
- Relevance Score：3
- Link：https://arxiv.org/abs/2610.10426

本窗 agent 系统稿偏少。SquidAgent（并行编排，相对 Claude Code 约 2.2× throughput）在 10-06，超出本窗。

## 4. SFT / Alignment

【Title】OnlineQAT: On-Policy Distillation for Ultra-Low-Bit Large Language Models

- 一句话总结：低比特 QAT 若只在离线 completion 上恢复，部署时会走进学生自己生成、训练没覆盖的前缀。
- 核心贡献（2-3点）：
  - 先 block-wise QAT 得到可用低比特初始化，再对学生自身回复做 on-policy distillation，教师给 sampled reverse-KL。
  - Qwen3-1.7B：W3A16 平均 57.28（比 ReasoningQAT +2.90），W2A16 32.52（+0.44）。3-bit 收益明显大于 2-bit。
- 工程价值：W4 以上不必上。W3 服务若已有 QAT 流水线，OPD 是小改动、对部署分布更对齐。模型只到 1.7B，大模型显存和教师成本未证。
- 是否值得读：可选
- Relevance Score：3
- Link：https://arxiv.org/abs/2610.10022

## 5. RL

【Title】BoT-GRPO: Efficient Process-Reward RL for Reasoning via Bag-of-Token Aggregation

- 一句话总结：有 token 级奖励时，不要再把整条 rollout 的同一个 advantage 铺到每个 token。
- 核心贡献（2-3点）：
  - 跨 rollout 收集 token reward，按序列长度倒数加权，再相对组统计算 per-token advantage。无 critic，可替换 GRPO。
  - React 前端代码：到 80% compile rate 比 GRPO 快最多 1.9×，也快于 GSPO / DAPO / PURE。
  - AIME 上 Pass@k 绝对提升最多 8.1%，步数约一半。奖励稳定性比奖励细粒度更重要。
- 工程价值：已有 process RM 的 GRPO 栈可以当 drop-in。没有可靠 token reward 就不要上。实验在 3B 级，和 GSPO/DAPO 的对比值得自己复跑。
- 是否值得读：可选
- Relevance Score：4
- Link：https://arxiv.org/abs/2610.09804

未列入但可扫一眼：EDR（用期望解码轮数训练并行 speculative drafter，finetune DSpark/DFly，https://arxiv.org/abs/2610.10411）；EncBank（下层当文档编码器，4-bit 状态缓存，prefill 1.40×，https://arxiv.org/abs/2610.10058）；vLLM-Omni 技术报告（多阶段 omni/TTS/diffusion/robot 统一编排，https://arxiv.org/abs/2610.09307）。后两篇工程相关，但方法增量或评测不完整。

## 今日最值得读 Top 3

1. NeMo-DCR。Agentic RL 的跨集群 refit 是真实关键路径，bit-exact + 失败恢复 + 已有 NeMo RL PR，比又一篇 GRPO 变体更接近可落地。
2. Expert Coupling。all-to-all 在 MI300X EP 上已占 step 一半左右，放置/shuffle 不改路由，Megatron 上有 1.16–2.63× 通信和最高 1.41× step。训练集群能直接对账。
3. CoMoE。非 NVLink MoE 的通信模型该改了。host 当路由枢纽是系统选择，不是稀疏近似，1.46× 和成本比有部署含义。

ResidualQuant 数字更大，但绑定 looped 架构，排在这三篇之后。

## 今日趋势

- 推理侧仍是内存/互连，不是 FLOPs：KV 残差量化、host 路由、encoder 状态缓存、omni 多阶段 runtime 同一天出现。纯 speculative 算法稿少，训练目标开始从 block surrogate 转到期望轮数（EDR）。
- Infra 明显多于 agent 框架。MoE 通信（训练放置 + 消费级推理）和 RL rollout 的 weight sync 是两条主线。
- Agent 稿很多，但有系统设计且有数字的少；值得看的是 harness–数据耦合，不是新的多 agent 拓扑。
- Alignment / RL 仍以 GRPO 变体和 on-policy distillation 为主，系统侧的增量大于算法侧。

## 值得跟进的方向

Disaggregated agentic RL 的 weight synchronization。全量 refit 在 1T、跨区已经是小时级。delta、bit-exact、可重试 commit 会变成和 rollout 引擎并列的组件；下一步是变化率随训练阶段的分布，以及和量化 rollout（FP4/FP8）共存时的精确性边界。
