【Title】
Flash-dLLM: IO-Aware KV Caching and Parallel Decoding for Fast, Memory-Efficient Diffusion LLMs

- 一句话总结：把 dLLM 的 KV 更新和并行 draft-verify 做成 I/O 感知融合核，training-free 加速扩散语言模型解码。
- 核心贡献（2-3点）：
  - Flash-Cache：QKV+RoPE+cache write 融合，避免中间 KV 回写 HBM；只刷新新 token + 高注意力 decoded token。
  - Flash-Verify：同一 dLLM 自 draft/自 verify，双视角 attention mask，无需辅助 draft 模型。
  - LLaDA-1.5 + A100：相对 Elastic-Cache，GSM8K **5.1×**、HumanEval **11.0×**；相对无 cache greedy 最高约 **148×**；相对 Fast-dLLM 约 **-48% GPU 显存**，可扩到 batch 32。
- 工程价值：直接打 dLLM 落地最大痛点（cache I/O + 并行接受率）。有 Triton 实现和官方 repo，可当 kernel 模板；对 AR serving 的启发是“cache 与 verify 必须共设计，否则 I/O 吃掉加速”。
- 是否值得读：强烈推荐
- Relevance Score：5
- Link：https://arxiv.org/abs/2609.26796 ；代码 https://github.com/VILA-Lab/Flash-dLLM

【Title】
Disaggregated Quantization: Specializing LLM Prefill and Decode

- 一句话总结：Prefill / Decode 用不同精度、权重和放置策略，而不是一套量化打全程。
- 核心贡献（2-3点）：
  - Decode 去掉 activation quant，decode-heavy 任务精度回升且不增加 decode 成本。
  - 单独训 compute-native prefill 权重（如 NVFP4 prefiller + 已发布 GGUF decode），Qwen3.8-27B 上 1-bit decode 的 MMLU-Pro **+32.5**、MMMU-Pro **+35.3**，decode checkpoint 不动。
  - Offloaded Disaggregated Prefill（SSD 流式加载 prefiller）：8K prompt 上 TTFT **1.78×**；在 vLLM 里评了 disagg serving；PTQ 验证到 **2.8T**。
- 工程价值：和现有 PD 分离、vLLM、GGUF 路径对齐。单卡可用 ODP 摊销第二套权重；集群可把 prefiller 和 decoder 拆节点。比“全程 INT4/FP8”更接近真实 serving 瓶颈。
- 是否值得读：强烈推荐
- Relevance Score：5
- Link：https://arxiv.org/abs/2609.26333

【Title】
The KV Cache Working Set: Online Capacity Planning for LLM Inference Systems (KVSET)

- 一句话总结：用 Mattson stack 在线估 prefix-cache 工作集，给容量规划一个可计算的 hit-rate 曲线，而不是拍脑袋配 HBM。
- 核心贡献（2-3点）：
  - 定义 KV working set = 达到目标命中率所需最小 cache 容量（对 agent 多轮/工具历史尤其关键）。
  - 一次扫页算 LRU stack distance，同时得到多容量下的 hit/miss，避免对每个容量单独仿真。
  - 面向在线分析，服务于 prefix caching 的 provision 与调度。
- 工程价值：这是 **serving 容量规划**，不是又一篇 eviction heuristic。可直接接到 vLLM/Mooncake 类 prefix pool：决定 HBM vs host vs SSD 分层、并发 session 上限、agent 长会话是否值得保 cache。
- 是否值得读：强烈推荐（短、可落地）
- Relevance Score：5
- Link：https://arxiv.org/abs/2609.27746

【Title】
SARA: SLO-Aware Resource Allocation for Disaggregated Agentic LLM Services

- 一句话总结：用排队论给 PD 分离的 agentic serving 做 SLO-aware 资源分配，目标是成本约束下最大化 goodput。
- 核心贡献（2-3点）：
  - Prefill≈M/G/k，KV transfer≈M/G/1，Decode≈广义生灭过程；结论：prefill 卡算力、decode 卡 HBM。
  - 分位数 SLO + 部署成本约束下的分配框架。
  - 阶段 SLO 预测误差 **<5%**；同成本 goodput 平均 **+26.6%**。
- 工程价值：从“枚举配置/profiler”升级到可解释的容量模型。适合做 PD 分离 + 长上下文 agent 的集群规划（卡数、HBM、链路带宽怎么配）。仿真+硬件都有。
- 是否值得读：强烈推荐
- Relevance Score：4
- Link：https://arxiv.org/abs/2609.26763

【Title】
Flux: Optimal Scheduling of Optical Circuit Switches for LLM Training

- 一句话总结：OCS 调度与训练计算时间轴联合优化，而不是按聚合流量独立切光路。
- 核心贡献（2-3点）：
  - 指出“算力和光路分离调度”导致电路利用率低、NIC buffer 爆炸。
  - 按整作业结构复用电路，把 recon delay 藏到 compute/comm 后面。
  - 相对周期调度：iteration time 最高 **10×**，峰值 NIC buffer **降 3 个数量级以上**。
- 工程价值：对上光交换/新型 DC fabric 的训练集群有直接意义；即使不用 OCS，也强化一个系统原则：**通信拓扑调度必须看 iteration 时间线**。偏 infra 硬件，落地门槛高。
- 是否值得读：可选（有光交换才必读）
- Relevance Score：4
- Link：https://arxiv.org/abs/2609.25949

【Title】
KernelOPT: Dispatch-Aware Agentic Search for GPU Kernel Optimization

- 一句话总结：多 agent 优化编译器生成的 Triton 子核，尊重 cuBLAS/cuDNN 调度，四道门禁后再缝回整模。
- 核心贡献（2-3点）：
  - 不把整模当黑盒；只动 Inductor 生成的 Triton，vendor GEMM 保留。
  - 四闸：静态检查 → 多种子正确性 → 整模 float64 fallback → 性能门；全不过则回退 baseline。
  - KernelBench 250 题：相对 `torch.compile` geomean **1.40× / 1.15× / 1.07×**（L1/L2/L3）。
- 工程价值：这是少见的“agent 真正进编译/serving 热路径”且有安全回退。可对标内部 kernel autotune；注意 L3 收益已经变薄，别期待万能。
- 是否值得读：强烈推荐（做推理/编译的人）
- Relevance Score：4
- Link：https://arxiv.org/abs/2609.30059

【Title】
Breaking the Environment Wall: Evolving LLM Agent Environments for Recursive Self-Improvement (Env-Rethink)

- 一句话总结：环境本身不可 agent-ready（碎片、噪声、演化），用 27B 系统建 Collection Map / Event Log，并演化更难环境来训 agent。
- 核心贡献（2-3点）：
  - 量化“环境墙”：SOTA agent 从 **83.9% → 57.6%**。
  - 自适应组织上下文 + 离线轨迹学噪声结构 + 用虚拟事件史改环境。
  - 30 任务 × 9 模型，rubric pass **+15.1%+**。
- 工程价值：对办公/科研 agent 产品：别只刷模型，先做环境索引和证据版本管理。系统设计可抄（map/log/evolve），但不是即插即用推理优化。
- 是否值得读：可选
- Relevance Score：3
- Link：https://arxiv.org/abs/2609.29773

【Title】
Conduit: An Experience Data Plane for Distributed Reinforcement Learning

- 一句话总结：把 RL 的 experience buffer 做成独立数据面（放置/调度/分层），和训练框架解耦。
- 核心贡献（2-3点）：
  - EDP：ingestion / placement / delivery 三个控制点。
  - 容量+带宽感知放置（CPU/GPU/跨节点），时延感知调度。
  - 接 RLlib、逻辑不变：experience-path 暴露延迟最高 **-97%**，iteration **-38%**，扩到 **1024 GPU**，收敛保持。
- 工程价值：LLM-RL（GRPO/DAPO）里 rollout replay 已经是系统瓶颈。这篇给的是可复用 runtime 抽象，不是又一个算法 trick。值得对标内部 rollout store。
- 是否值得读：强烈推荐（做 RL infra）
- Relevance Score：5
- Link：https://arxiv.org/abs/2609.24456

【Title】
Verifiable Hidden Dynamics Play: Generating Agentic RL Environments from Solved Mechanisms

- 一句话总结：先解一个可执行动力学模型，再渲染成带工具的 agent 环境，奖励和状态机同源，批量造可验证 RL 环境。
- 核心贡献（2-3点）：
  - 3300 个环境，单个成本“几美分级”。
  - Qwen3.6-35B-A3B 五族诊断均分 **0.204 → 0.815**；hold-out 机制族 + 外部 function-call / 旅行规划 / 电商也涨。
  - 规模匹配训练后，机制变大、horizon 变长仍保留收益。
- 工程价值：agent RL 最缺的是 **便宜、可验证、可扩的环境工厂**。比手写 sandbox 更可扩展；跟进点是把这套管线接到现有 rollout 集群（和 Conduit/DSec 一类 infra 互补）。
- 是否值得读：可选（做 agent RL 数据飞轮则强烈）
- Relevance Score：4
- Link：https://arxiv.org/abs/2609.27321

### 1. 今日最值得读 Top 3

1. **Flash-dLLM** — 有融合核、有 code、有相对 SOTA 的 5–11×。dLLM 若要进生产，I/O+verify 共设计是必读范式；AR 团队也能抄 fused cache 思路。
2. **Disaggregated Quantization** — 把“PD 分离”从调度层推进到 **量化/权重形态层**，并接到 vLLM/GGUF/SSD offload。这是下周就可以在 serving 栈里做实验的方向。
3. **KVSET + Conduit（并列第三的系统课）** — 一个回答“prefix cache 到底要多大”，一个回答“RL experience 路径怎么不再拖 iteration”。都是容量/数据面问题，不是模型论文。

若只能再加一篇产品向：**SARA**（agentic PD 分离的 SLO 配平）。

### 2. 今日趋势观察

- **Inference / KV 仍然是绝对主场**：48h 内 KV cache（工作集、风险约束 eviction、补偿感知稀疏、2-bit 视频 KV、PD 分重量化）密度明显高于 agent 算法论文。
- **Serving 从“kernel 加速”上移到“容量规划 + SLO 合同”**：KVSET、Risk-Controlled Eviction、SARA 都在谈 hit-rate、material degradation 频率、分位数 SLO，而不是平均分数。
- **Agent 论文更偏环境/评测/内核搜索，少纯 prompt agent**；真正有系统味道的是 KernelOPT、Env-Rethink、VHD-Play。
- **RL 成本中心明确转向 rollout / experience path**（Conduit、rollout efficiency taxonomy、环境生成）。

### 3. 值得跟进的潜在方向

1. **Phase-specialized 量化 + 权重放置**（prefill NVFP4 / decode 低 bit 权重量化 + ODP）。和现有 PD 分离正交，单卡和集群都能试。
2. **Prefix-cache working set 作为一等观测指标**：agent 会话增长后，HBM 配比应跟 working set 走，而不是跟 max context 走。
3. **Eviction 的风险合同化**（同日 *Risk-Controlled KV-Cache Eviction*，https://arxiv.org/abs/2609.27981）：平均掉点合格、长上下文/RULER 上合同失败就 fallback full KV。生产比“再压 25% cache”更重要。
4. **Agent RL = 可验证环境工厂 + experience 数据面**：VHD-Play 造环境，Conduit 运轨迹；缺的是把两者接到同一套弹性 sandbox（稍早的 DSec 是同类生产线索）。
5. **编译器感知的 kernel agent**：KernelOPT 的“只改 generated Triton + 四闸回退”比端到端自己写 kernel 更可能进 CI。

过滤掉的：纯调参、无系统数字、或窗口外综述（如 6 月 KV survey）；H-Spec / Hot-Cold HBM+HBF / KITE 也相关，但日期或硬件假设更窄，未占名额。
