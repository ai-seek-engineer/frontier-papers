### 1. Inference

**【Title】** OmniKVQuant: KV Cache Quantization for Omni-LLMs  
- 一句话总结：把旋转量化从纯文本 KV 扩到音视频混合 cache，并给出 fused 2-bit decode kernel。  
- 核心贡献：  
  - 诊断 multimodal KV 的两类失败：temporal key drift、跨模态 value 几何不一致。  
  - 窗口内定 key 量化范围 + 按模态分旋转 value；2-bit 仍能保住多数音视频 benchmark。  
  - Triton fused kernel：decode 时 unpack，不物化 FP16 cache。  
- 工程价值：Omni 模型 KV 比文本涨得更快，这是少有“可直接进 serving stack”的 multimodal KV 方案。  
- 是否值得读：强烈推荐  
- Relevance Score：5  
- Link：https://arxiv.org/abs/2609.11582

**【Title】** AMEND: Audited Margins Enable Nonblocking Drops in GPU-PIM LLM Decoding  
- 一句话总结：用历史 margin 预测稀疏块，GPU 只拉 survivor，PIM 并行打分被丢掉的块，去掉选择器对关键路径的串行依赖。  
- 核心贡献：  
  - 解决 “先算 QK 再丢块” 或 “PIM 选择器挡 decode” 两种现有路径。  
  - LongBench/RULER 质量接近 dense；模拟 batch=8、8K–64K 下 1.40–3.63× decode，能耗降 28–66%。  
- 工程价值：短期难上产（GPU-PIM），但对 HBM-PIM / 稀疏注意力调度是清晰系统设计；带宽墙下一阶段路线图。  
- 是否值得读：可选（做 serving/硬件的读）  
- Relevance Score：4  
- Link：https://arxiv.org/abs/2609.09823

### 2. AI Infra / 分布式 / 系统

**【Title】** Online Draft Co-Training for Speculative Decoding in Large-Scale, Long-Context RL Post-Training  
- 一句话总结：RL 里 draft 跟 policy 一起在线训，并补上 256K 级 CP + PP 特征旁路，把 speculative 真正接到大规模 RL rollout。  
- 核心贡献：  
  - packed zigzag ring attention 把 branch attention 和主序列因果注意力合在一起。  
  - TapChannel 跨 PP stage 传 target 中间特征，不打乱 pipeline。  
  - 到 122B：draft 跟上 policy，rollout / E2E 都有实质加速；声称有代码。  
- 工程价值：RL 成本 90%+ 在 generate。这是把 speculative 从推理 serving 迁到 **RL infra** 的少有完整系统文。  
- 是否值得读：强烈推荐  
- Relevance Score：5  
- Link：https://arxiv.org/abs/2609.07108

**【Title】** UNISON: A Co-Designed Near-Memory Scheduler of Session KV Residency for LLM Agents  
- 一句话总结：Agent loop 的 KV 是“会话级驻留”问题，不是普通多轮 chat 的 LRU；近存调度同时决定谁被踢、idle 窗口里谁升到快层。  
- 核心贡献：  
  - SPEAR：用 gap + turn-indexed hazard 决定 eviction。  
  - TIDE：把 tool wait 当成 DMA budget 做分层。  
  - 1415 session / 3.3 万 turn：hit +0.3–23.1%，AMAT −22–51%，长程 TTFT −58–89%；28nm 调度核开销可忽略。  
- 工程价值：Agent serving 的 KV 生命周期和 chat 完全不同；软件 LRU/timeout 会把“活着的 wait”当冷数据丢掉。可直接改 router / cache manager。  
- 是否值得读：强烈推荐  
- Relevance Score：5  
- Link：https://arxiv.org/abs/2609.09643

### 3. LLM Agents（系统设计）

**【Title】** T1: Terminal Agent Reinforcement Learning for Long-Horizon Tasks  
- 一句话总结：用异步 RL（slime + Megatron + SGLang）把 ~10B active 的终端 agent 拉到接近 Opus 级 Terminal-Bench，并写清长上下文 PPO 的工程取舍。  
- 核心贡献：  
  - 训练/推理拆池、routing replay、critic warm-up、oversample 截长尾。  
  - 84k context PPO，生产配置有明确 step time 分解。  
  - 同 harness 下从 base 43.8% 拉到领先开源带。  
- 工程价值：不是“再一个 agent prompt”，而是 **可复用的长程 agent RL 训练栈**（SGLang KV patch、DP 推理副本数 vs 训练时间）。  
- 是否值得读：强烈推荐  
- Relevance Score：5  
- Link：https://arxiv.org/html/2609.11042

**【Title】** Decoupling Readiness from Release for Tail-Aware Scheduling of Agentic LLM Workflows  
- 一句话总结：Agent workflow 的 E2E 不只看 kernel 速度，还看“就绪 turn 何时放行”；用 mean-CVaR 控未完成尾部。  
- 核心贡献：  
  - 就绪 ≠ 立即 release；维护已放行未完成工作量预算。  
  - 在线估 turn 工作量 + 按队列压力调预算。  
  - 真实 SWE agent trace：轻载≈eager，争用下 P95 最高 3.50×。  
- 工程价值：现有 serving 按 request 调度；agent 是 DAG of turns。可接到 gateway / workflow orchestrator，不必改模型。  
- 是否值得读：强烈推荐  
- Relevance Score：4  
- Link：https://arxiv.org/abs/2609.10964

### 4. SFT / Alignment / RLHF

**【Title】** Miles v0.1: Production-Level Post-Training  
- 一句话总结：把异步 RL、BF16 训 / FP8 推、CI 门控、蒸馏缩短回答写进一套可跑 744B-A40B 的 post-training 产品文档。  
- 核心贡献：  
  - 64×GB300 对半拆 generate/train；TP2/PP4/CP4/EP8 + DP attention + MTP。  
  - 轨迹飞行数与训练 batch 解耦；定期同引擎 held-out eval。  
  - 蒸馏可把回答砍半而不稳掉 accuracy（有具体 run）。  
- 工程价值：比论文更像 **runbook**。对要对齐 OpenRLHF/verl/slime 的团队，配置表本身就有用。  
- 是否值得读：可选（做 post-train infra 必看）  
- Relevance Score：4  
- Link：https://arxiv.org/html/2609.08368

### 5. Reinforcement Learning

**【Title】** Long-Horizon Language Model Reinforcement Learning via Progressive Point Matching  
- 一句话总结：稀疏 outcome reward 在超长轨迹上学不动；用一条参考轨迹做无偏的 segment 级 dense reward。  
- 核心贡献：  
  - 理论：segment 级 progressive matching 对长程样本效率指数级好于 outcome-only。  
  - 极难数学上 sparse 零进展，segment reward 在更大 test-time budget 上抬 success / pass@k。  
  - 每任务只需一条 reference trajectory，落地成本低。  
- 工程价值：不改分布式栈，改 reward 形状。适合已有 RLVR、但长程任务不收敛的团队。  
- 是否值得读：可选  
- Relevance Score：4  
- Link：https://arxiv.org/abs/2609.07303

## 额外输出

**1. 今日最值得读 Top 3**

1. **Online Draft Co-Training** — RL 成本在 rollout，speculative 必须跟 policy 共进化；同时给了 256K CP 和 PP 旁路，是 inference × RL infra 交叉点上最硬的一篇。  
2. **UNISON** — Agent 上量后 KV 问题从“token 级分页”变成“session 级驻留 + tool-wait DMA”。这是 serving 团队会立刻碰到、但现有 vLLM/SGLang 策略几乎没建模的层。  
3. **T1** — 少有把长程终端 agent RL 的模型结果和训练系统（slime/SGLang/副本配比/截尾）写在一起的报告，可直接对照自己的 post-train 流水线。

**2. 今日趋势观察**

- **Inference 仍是最大头**，但重心从“再压 0.5 bit KV”转到 **多模态 KV、跨请求/跨 checkpoint 复用、PIM/近存、外置 NVMe cache**。  
- **Agent 论文明显工程化**：调度、session KV、turn release、terminal RL，不再只是 planner prompt。  
- **RLHF/RLVR infra** 继续异步化：generate/train 拆池、FP8 rollout、speculative 进训练环，几乎成为默认叙事。

**3. 值得跟进的潜在方向**

- **Session-aware KV OS**：eviction / tiering / 跨 session 复用按 agent 状态机而不是 LRU。UNISON + KVShareArena 是两端（硬件调度 vs 软件基准）。  
- **Training-time speculative decoding**：draft 必须 online 跟上 evolving policy，否则 acceptance 崩；和权重稀疏同步（SparseRL-Sync 一类）会合成完整 RL 通信栈。  
- **Workflow 级调度 ≠ request 级调度**：turn release、CVaR 尾部、tool-wait 重叠，会成为 agent 网关的新控制面。
