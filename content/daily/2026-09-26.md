【Title】
CompKV: Compensation-Aware KV Selection for Long-Context LLM Inference  
- 一句话总结：稀疏注意力的 token 选择应按“漏选后补偿残差”优化，而不是先选再补。  
- 核心贡献（2-3点）：  
  - 把 block 选择目标显式对齐到 mean-compensation 残差（attention mass × 块内 logit 方差）。  
  - 用块级统计近似残差，并给出异步实现。  
  - RULER / LongBench-Pro 上优于对比稀疏基线，self-attention 最高约 6.85×。  
- 工程价值：可直接改 sparse attention serving 路径；选择准则轻量，比再叠一层复杂 predictor 更可落地。  
- 是否值得读：强烈推荐  
- Relevance Score：5  
- Link：https://arxiv.org/abs/2609.26300

【Title】
Disaggregated Quantization: Specializing LLM Prefill and Decode  
- 一句话总结：Prefill 与 Decode 用不同量化/权重形态，而不是一套精度打全程。  
- 核心贡献（2-3点）：  
  - Decode 去掉 activation quantization 可抬 decode-heavy 任务精度且不增 decode 成本。  
  - 单独训 compute-native prefill 权重；27B 上 NVFP4 prefiller 显著抬 1-bit decode 的 MMLU-Pro / MMMU-Pro。  
  - Offloaded Disaggregated Prefill：SSD 流式加载 prefill 权重，8K prompt TTFT 约 1.78×。  
- 工程价值：高度贴合 PD 分离集群；一份 decode checkpoint + 一份 prefill checkpoint 是可上线的 serving 形态。  
- 是否值得读：强烈推荐  
- Relevance Score：5  
- Link：https://arxiv.org/abs/2609.26333

【Title】
The KV Cache Working Set: Online Capacity Planning for LLM Inference Systems  
- 一句话总结：把 prefix cache 容量从“拍脑袋配内存”变成可在线估计的 working set。  
- 核心贡献（2-3点）：  
  - 用 Mattson stack 一次扫描估计多容量点 hit rate。  
  - 面向 agentic 增长前缀工作负载，而不是静态 prompt。  
  - 生产 trace 验证，开源支持在线/离线回放。  
- 工程价值：集群容量规划、HBM vs host memory 分层直接可用；比再发一篇 eviction heuristic 更值钱。  
- 是否值得读：强烈推荐  
- Relevance Score：5  
- Link：https://arxiv.org/abs/2609.27746

【Title】
When Fancy Eviction Fails: Rethinking Cache Replacement For LLM Prefix Reuse  
- 一句话总结：生产 agent 前缀缓存上，花式替换策略几乎打不过 LRU。  
- 核心贡献（2-3点）：  
  - 两家公司生产 trace + 14 种 eviction，HBM 紧/内存池大两种设定。  
  - 提出 compute-savings ratio 与离线 oracle，量化“命中率 ≠ 省算力”。  
  - 结论：保留 recency，叠加 one-hit 快淘汰 + 高代价 miss 的 compute-aware 部分驱逐。将发 traces/simulator。  
- 工程价值：直接打脸很多论文级 cache policy；serving 团队应先改指标再改算法。  
- 是否值得读：强烈推荐  
- Relevance Score：5  
- Link：https://arxiv.org/abs/2609.28870

【Title】
Risk-Controlled KV-Cache Eviction: From Memory Budgets to Risk Targets  
- 一句话总结：KV eviction 不该只看平均质量，而应按“不可接受劣化频率”签 SLA。  
- 核心贡献（2-3点）：  
  - 定义 material degradation + deployment risk。  
  - 同一风险合同在 LongBench 可认证 SnapKV 75% retention，在 RULER-32K 则必须 fallback 全量 KV。  
  - 把可靠性指标映射成可运营的内存工作点。  
- 工程价值：生产上比“平均掉 1 分可接受”更接近真实 SLO；适合做 eviction 开关/fallback 策略。  
- 是否值得读：可选  
- Relevance Score：4  
- Link：https://arxiv.org/abs/2609.27981

【Title】
Flash-dLLM: IO-Aware KV Caching and Parallel Decoding for Fast, Memory-Efficient Diffusion LLMs  
- 一句话总结：扩散 LLM 的加速瓶颈是 I/O，要把 fused KV kernel 和自草稿并行解码一起做。

【Title】
Verifiable Hidden Dynamics Play: Generating Agentic RL Environments from Solved Mechanisms  
- 一句话总结：先解一个可执行动力学模型，再生成带 hidden state 的 agent 环境，而不是先写任务再找 verifier。  
- 核心贡献（2-3点）：  
  - 3300 个环境，单环境成本几美分；reward 与动力学同源，可验证。  
  - Qwen3.6-35B-A3B agentic 分 0.204→0.815，并泛化到未见 mechanism family。  
  - 外推到 function calling / 旅行规划 / 365 天电商；对比表明可学差距主要在 stateful 交互。  
- 工程价值：agent RL 最缺的是便宜、可验证、可扩规模的环境工厂，不是又一个 multi-agent wrapper。  
- 是否值得读：强烈推荐  
- Relevance Score：5  
- Link：https://arxiv.org/abs/2609.27321

【Title】
RRSI: Regularized Recursive Self-Improvement of Agent Harnesses  
- 一句话总结：自动改 agent harness（prompt/控制流/工具/记忆）会过拟合训练集，要用正则限制进化。  
- 核心贡献（2-3点）：

- 一句话总结：全链路 FP8 RL 的真问题不是 train-infer mismatch，而是 clipping 边界与 BF16 分布错位导致熵爆炸。

### 1. 今日最值得读 Top 3

1. **When Fancy Eviction Fails** — 生产 trace 打假“高级 eviction”；prefix cache 团队应先改目标函数（省算力 vs hit rate）。  
2. **KV Cache Working Set (KVSET)** — 把 serving 容量从经验值变成可测量 working set，和上一篇构成“怎么配 + 怎么淘汰”闭环。  
3. **Disaggregated Quantization** — PD 分离后最该做的量化形态拆分，有 TTFT 和精度数字，接近可上线设计。

### 2. 今日趋势观察

Inference / KV serving 明显过热：eviction、working set、PD 量化、sparse selection 同一窗口扎堆。Agent 方向从“多角色对话”转向 **可验证环境工厂 + harness 进化正则**。纯 SFT/RLHF 新方法少，RL 侧重心是 **FP8 稳定性和 rollout 成本**。

### 3. 值得跟进的潜在方向

- **Prefix cache 的“算力节约”指标**：命中率已不够，需要 miss 代价加权的容量/替换策略。  
- **PD 分离下的异构精度契约**：prefill 一份高精度/高吞吐权重，decode 一份极致压缩 KV/权重，外加 fallback SLA（Risk-Controlled 那套）。  
- **Stateful、可执行的 agent 环境生成**：比人工写 traj 更可扩展；下一步看能否接到真实工具沙箱而不是合成 mechanism。
