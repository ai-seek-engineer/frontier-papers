## 1. Model Inference / 推理优化

【Title】Tail-Replay: Escaping the Curse of Linear Attention in Prefix Caching for Hybrid LLMs  
- 一句话总结：给 Gated DeltaNet 这类 hybrid LLM 做真正可用的 token 级 prefix cache，而不是只能在 checkpoint 边界复用。  
- 核心贡献（2-3点）：  
  1. 指出线性注意力状态是对前缀的有损压缩，命中后只需 replay 很短 suffix 就能近似恢复 recurrent state。  
  2. 只缓存精确 full-attention KV，不存 recurrent checkpoint，复用边界由共享 token 决定。  
  3. 5–10% replay budget 下，LongBench/RULER 保住 92.8–99.9% full-prefill 质量，并给 8K/16K/32K 命中前缀的 TTFT 加速。  
- 工程价值：Qwen3-Next / Jamba 类 hybrid 上线时，radix/prefix cache 会直接踩这个坑。这是 serving 路径上的真实问题，不是又一篇 KV 剪枝。  
- 是否值得读：强烈推荐  
- Relevance Score：5  
- Link：https://arxiv.org/abs/2608.30310

【Title】SemKV: Semantic Mixed-Precision KV Cache Quantization Guided by the Quality Cliff  
- 一句话总结：KV 量化不是平滑掉点，而是存在可复现的质量悬崖；混合精度应在悬崖之上做网格插值。  
- 核心贡献（2-3点）：  
  1. Llama-3.1-8B + affine quantizer：2.322 bit 与 FP16 统计不可分，2.0 bit 崩——悬崖区间 (2.0, 2.322]。  
  2. 悬崖之上 8 种 importance 指标几乎可互换，混精的价值是插值到均匀量化到不了的平均精度。  
  3. SemKV 保全部 token、两档悬崖上精度：6.0× 存储、n=900 三种子无显著质量差；换 TurboQuant-MSE 可到 7.9×。  
- 工程价值：直接打“随便压到 2bit”的部署幻想。上线前先测本模型/本 workload 的 cliff，再选 bit 网格，比再发明一个 importance score 更有用。  
- 是否值得读：强烈推荐  
- Relevance Score：5  
- Link：https://arxiv.org/abs/2608.28911

## 2. AI Infra / 分布式训练 / 系统优化

【Title】More GPUs or a Smaller Cache? Tensor Parallelism versus KV Compression  
- 一句话总结：KV 不够时，加卡做 TP 和原地压缩不该用两套指标；放到同一美元轴上，压缩几乎总是更便宜。  
- 核心贡献（2-3点）：  
  1. 用标定过 A100/A40/H100 的 profiled simulator，把 TP=1..8 和 KV 16/8/4-bit、keep-ratio 到 0.25 画在 cost/MTok vs latency 上。  
  2. 找不到成本等价交叉点：压缩便宜 1.20–2.00×；容量/$ 压缩最高 16.5×，8 卡 TP 只有 1.21×。  
  3. 决策边界是模型相对显存：约 36B @ 80GB。之下加卡浪费；之上权重本身装不下，压缩救不了，TP 是入场券。压缩会让 per-token latency 差 8–93%。  
- 工程价值：容量规划论文。别再默认“KV 爆了就 TP”。延迟敏感走 TP，吞吐/$ 走压缩。  
- 是否值得读：强烈推荐  
- Relevance Score：5  
- Link：https://arxiv.org/abs/2608.23962

【Title】Performance Foundations of Parallel & Distributed Reasoning Language Models  
- 一句话总结：把 R1/o3 这类 RL-for-LLM 训练当成分布式系统问题，系统化 PPO/GRPO 的算力结构与并行策略。  
- 核心贡献（2-3点）：  
  1. 从 compute 视角拆 PPO/GRPO 及变体（多模型、rollout/训练耦合）。  
  2. 给出 intra/inter-model 并行 taxonomy：传统 DP/TP/PP/SP/CP/EP + 解耦放置、stage fusion、hybrid、异步。  
  3. 用 work-depth 把 insight 写死，并对照现有 RLM 框架给落地指南。  
- 工程价值：做 RL post-training 集群的必读地图。不是新算法，但是排障/选型/拆 actor-critic-ref 的公共语言。  
- 是否值得读：强烈推荐（系统负责人）；算法同学可选  
- Relevance Score：4  
- Link：https://arxiv.org/abs/2608.27046

## 3. LLM Agents（系统设计/落地）

【Title】AgentSpec: Speculative Decoding for Batch Inference of LLM Agents  
- 一句话总结：标准 speculative decoding 在 agent 大批次下会比自回归还慢；按 workflow 语义段做 drafting + 动态 token budget。  
- 核心贡献（2-3点）：  
  1. 诊断两大死因：无关语义路径导致高拒绝率；动态 token budget 用不满。  
  2. structure-isolated drafting：只在 agent 工作流语义连贯段上投机。  
  3. vLLM 上 5 workload × 4 模型族：现有方法大批次甚至慢于 AR，AgentSpec 仍快，最高 2.02×，稳定压过 EAGLE-3 / NGram / SuffixDecoding。  
- 工程价值：agent serving 不是“把 EAGLE 打开”。工具调用/结构化输出会毁掉接受率。可直接改 vLLM 投机策略。  
- 是否值得读：强烈推荐  
- Relevance Score：5  
- Link：https://arxiv.org/abs/2608.24004

## 5. Reinforcement Learning

【Title】TailSieve: Partial-Rollout-Guided Tail Routing for LLM Rollouts  
- 一句话总结：同步 RL rollout 的长尾不是请求级竞速，而是要把超长 generation 从高并发 batch 里隔离出去。  
- 核心贡献（2-3点）：  
  1. 理想已知长度时，makespan 最优 ≈ tail isolation + load balance；简单 top-k 接近 oracle。  
  2. 用 cutoff 的 partial rollout 当免训 tail 信号；分层控制器同时调隔离组数和 tail/bulk replica 切分。  
  3. 保持 on-policy：消耗的 response 用当前策略重生成。纯路由最高 1.67×；tail 池再配 MTP/DFlash 最高 2.59×。  
- 工程价值：直接打 VeRL/OpenRLHF 同步 barrier。比再写一个长度预测器更接近生产。  
- 是否值得读：强烈推荐  
- Relevance Score：5  
- Link：https://arxiv.org/abs/2608.22788

【Title】GMTS: Gradient Magnitude-based Token Selection Improves RLVR Training  
- 一句话总结：高熵 token 重要，是因为它常对应大梯度；跨 answer 时熵不够，应用梯度幅值代理做 token 筛选。  
- 核心贡献（2-3点）：  
  1. 单条答案内高熵≈大梯度，但跨答案时 reward 不同，熵不能当全局重要性。  
  2. GMTS 用熵-梯度关系近似梯度排序，只训 top 20%。  
  3. 三推理域、多尺寸上稳定超过纯熵筛选。  
- 工程价值：改 GRPO loss mask 就能试，训练吞吐几乎不变、信号更干净。但是否通到非推理任务未证。  
- 是否值得读：可选  
- Relevance Score：3  
- Link：https://arxiv.org/abs/2608.30632

## 额外输出

### 1. 今日最值得读 Top 3

1. **Tail-Replay** — hybrid 架构已经进生产，prefix cache 语义变了。不读会在 serving 上直接做错系统假设。  
2. **AgentSpec** — agent 推理的投机解码不能复用 chatbot 结论；有 vLLM 实现和大批次负结果，可立即对照现网。  
3. **TailSieve** 或 **More GPUs or a Smaller Cache**（二选一按岗位）：前者解 RL 训练墙钟，后者解推理扩容该加卡还是压 KV。

### 2. 今日趋势观察

- **Inference 明显占主导**，且从“再压 0.5 bit”转向 **hybrid/prefix cache 正确性**、**质量悬崖**、**agent 批次投机失效**。  
- **RL 系统化**：rollout 调度、token-level 梯度筛选、RLM 并行 taxonomy 同时出现——训练侧瓶颈从算法公式转到 barrier/长尾/多模型并行。  
- Agent 论文数量多，但多数是 harness/评测；真正有 serving 数字的仍少。

### 3. 值得跟进的潜在方向

- **Hybrid / 线性注意力的缓存语义**：checkpoint vs suffix-replay vs sparse state；和 radix tree 怎么合。  
- **投机解码 × 工作负载结构**：agent 段、RL tail 池、长上下文 partial verify（SpecPV 同类）正在汇合。  
- **容量规划的统一成本轴**：TP / KV 压缩 / PD 分离不要再分三篇论文各报各的指标。  
- **同步 RL 的路由+投机联合**：TailSieve 已证明 tail 池更适合深投机；下一步是和异步 RL、partial rollout 复用前缀一起做。
