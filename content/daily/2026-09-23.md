### 1. Model Inference

**【Title】** KV-COBRA: KV Cache Compression via Co-Optimized Bit-Rank Allocation  
- 一句话总结：KV 极限低比特的瓶颈不是压缩算法本身，而是 **每个 head 上 rank 截断 vs 量化比特的预算分配**。  
- 核心贡献：  
  1. 把 per-head rank + bit-width 做成资源分配问题，而不是全局均匀量化/截断。  
  2. Hadamard 旋转 + 按 attention-KL 重排 SVD 基，让分配器对 query 更敏感。  
  3. 0.5–4 bpd 上低比特精度掉点最小，且声称无 per-token 额外开销。  
- 工程价值：可直接叠在现有 low-rank + scalar quant 管线上；对长上下文 serving / 端侧 RAM 更有用，比再发明一种 codec 更可落地。  
- 是否值得读：强烈推荐  
- Relevance Score：5  
- Link：https://arxiv.org/abs/2609.24298

**【Title】** Adapting Tree-Structured Speculative Decoding to DeepSeek-V4  
- 一句话总结：把树形投机接到 DeepSeek-V4-Flash 的压缩/稀疏状态管线，而不是再做一个线性 draft。  
- 核心贡献：  
  1. branch-aware causal verification + 临时状态隔离 + 接受路径 refresh，保证多分支下 compressed state 一致。  
  2. 同预算下 accepted length 全面高于线性投机（D=8：约 2.83–3.41 vs 2.39–2.84）。  
  3. 吞吐最高约 +18.5%，小预算时收益边际。  
- 工程价值：对 **MLA / 压缩 KV / 稀疏上下文** 的模型，线性投机会踩状态一致性坑；这篇是适配经验，不是新算法。适合已经在跑 DeepSeek 系 serving 的团队。  
- 是否值得读：强烈推荐（若你在跟 V4/Flash 推理栈）  
- Relevance Score：4  
- Link：https://arxiv.org/abs/2609.24698

### 2. AI Infra / 分布式 / 系统

**【Title】** DeepSeek Elastic Compute (DSec): A Sandbox Infrastructure for Effective Agentic Training at Scale  
- 一句话总结：把 agent RL 的沙箱当成一等生产系统：统一 SDK 覆盖 FnCall / container / microVM / full-VM，并和训练调度解耦。  
- 核心贡献：  
  1. 分层镜像 + 3FS 按需加载，解决大规模环境冷启动。  
  2. 与 RL 框架共设计：stateful rollout 与可抢占 GPU 训练分离，空闲回收但保留轨迹状态。  
  3. 生产量级：单单元 ~160 节点、日 300 万沙箱、并发 38 万+、创建速率 5k+/s。  
- 工程价值：这是目前最接近“可抄架构”的 agent 训练 infra 报告。如果你在做 tool-use RL / coding agent 集群，优先级高于大多数算法论文。  
- 是否值得读：强烈推荐  
- Relevance Score：5  
- Link：https://arxiv.org/abs/2609.22978

**【Title】** PipeSwift: Revisiting Pipeline Parallelism for Large-Scale Completion-Oriented Agentic LLM Serving  
- 一句话总结：Agent 工作负载的目标不是 decode TPS，而是 **JCT（整条轨迹完成时间）**；PP 在 prefill/decode 平衡上反而赢。  
- 核心贡献：  
  1. 指出 prefill 优先调度能拉高 TTFT 和 decode 吞吐，但 JCT 不是最优。  
  2. 重新启用 PP：对 360B+ MoE、64×H800、真实 coding/search 轨迹，JCT 相对 SGLang wide-EP 最高 1.45×，相对开源 PD-disagg SOTA 1.54×。  
- 工程价值：直接打生产 agent serving 的调度假设。PD-disagg 不是所有 agent 流量的默认最优。  
- 是否值得读：强烈推荐  
- Relevance Score：5  
- Link：https://arxiv.org/abs/2609.16491

### 3. LLM Agents（系统设计）

**【Title】** Ask the Tool, Don't Guess: Agent Tool Calls Hold Their Progress, and the Serving System Should Read It  
- 一句话总结：KV 驻留/换出不该靠猜 tool 时长，而该读 tool 自己的进度信号。  
- 核心贡献：  
  1. 证明 call 开始前的静态估计无法可靠排序 tool 时长。  
  2. harness 无感抽取进度，决策点精度比现有 predictor 高数倍到一个数量级。  
  3. 接入生产引擎后，tool 返回后的 p90 TTFT 相对 LRU 降约 21%。  
- 工程价值：改动面小、收益明确，是 agent serving 里最容易落地的一条：给 tool runtime 加 progress hook，而不是再训一个 duration model。  
- 是否值得读：强烈推荐  
- Relevance Score：5  
- Link：https://arxiv.org/abs/2609.18849

**【Title】** TierKV: Long-Context On-Device LLMs via Predictive Multi-Tier KV Caching  
- 一句话总结：端侧长上下文不要边 decode 边被动驱逐，用 prefill hidden state **预先**把 token 分到 exact / low-rank / flash 三层。  
- 核心贡献：  
  1. 预测未来 cache demand，打破 eviction 的循环依赖。  
  2. 闭式求解层边界与 per-layer rank。  
  3. 8 个模态模型、3 个 SoC：prefill 最高 17.6×，RAM 常驻 KV 降 12.5–34%。  
- 工程价值：手机/边缘 serving 可直接对标；云侧也可借鉴 “prefill 阶段一次性规划 KV 层级” 而不是 decode 期 reactive policy。  
- 是否值得读：可选（端侧团队强烈，云侧可选）  
- Relevance Score：4  
- Link：https://arxiv.org/abs/2609.21172

### 4. SFT / Alignment / RLHF / RL

**【Title】** ASPIRE: Asynchronous Batched Self-Speculative Decoding for Long-Context LLM Inference  
- 一句话总结：批内请求不要共用同一个 draft-verify 节拍，让每条请求按自己的接受率决定何时 verify。  
- 核心贡献：  
  1. mixed forward：同一 batch 里 draft 和 verify 共存。  
  2. 在线 scheduler + intra-draft 单层 full attention 刷新，减轻稀疏 draft 的 stale。  
  3. 相对自回归 1.70–4.58× decode 吞吐，相对最强 self-spec 基线平均再快约 27%。  
- 工程价值：长上下文 + 连续批处理的投机系统，核心卡点是同步调度而不是 draft 质量。可对照 vLLM/SGLang 的 spec 实现。  
- 是否值得读：强烈推荐  
- Relevance Score：5  
- Link：https://arxiv.org/abs/2609.17943

## 今日最值得读 Top 3

1. **DSec** — 少见的生产级 agent 训练 infra 白皮书：并发规模、镜像分层、与 RL 抢占共设计都是真实约束，不是 benchmark 故事。  
2. **PipeSwift** — 直接推翻 “agent serving = 把 chatbot 调度套上去”：优化目标从 TPS 换成 JCT 后，并行策略会换。  
3. **KV-COBRA** 或 **Ask the Tool**（并列第三，看你岗位）：做推理内核选 COBRA；做 serving/agent 编排选 Ask the Tool。前者改内存公式，后者改调度输入。

## 今日趋势观察

- **Inference / KV 仍然是主航道**：树形投机、per-head bit-rank、异步 self-spec、多级 KV，全部在打同一件事——decode 被 KV 带宽和状态一致性卡住。  
- **Agent 论文从 “会不会用工具” 转向 serving 原语**：tool 进度、KV 驻留、JCT、沙箱生命周期。这是过去两天最明显的增量。  
- Alignment/SFT 新文工程密度偏低，被 infra 和推理挤出榜单。

## 值得跟进的潜在方向

1. **Compressed / structured KV 上的投机解码正确性**（V4-Flash 这类 MLA/压缩状态）：线性 draft 不够，需要分支隔离与 accepted-path refresh。  
2. **Agent-aware KV 生命周期**：tool 进度、phase（think/act/tool）子空间、跨 turn splice，而不是统一 LRU/SnapKV。  
3. **训练侧弹性沙箱与 GPU 训练解耦**：DSec 把 rollout 环境做成可超卖、可抢占、可回放的集群服务，这会成为 agentic RL 的默认 infra 形态。
