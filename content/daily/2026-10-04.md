## 1. Inference

【Title】MegaFlux: Skew-Resilient MoE Megakernels via Pipelined Expert Replication

- 一句话总结：固定 expert placement 下的路由倾斜会让 megakernel 出现 GPU straggler；MegaFlux 把热点 expert 复制变成运行时决策，并把复制引入的权重/梯度传输藏进 persistent kernel。
- 核心贡献（2-3点）：
  - 片上 planner 在 replica budget 内选复制位置并分配 tile 对齐的 token block，不改 router 输出。
  - forward/backward megakernel 流水化复制：权重大块到达即算；backward 把 replica gradient reduction 与 expert 计算重叠。
  - 扩展 TensorRT-LLM CuTeDSL MegaMoE，并接入 vLLM 跑 DeepSeek-V4-Pro prefill。
- 工程价值：8×B200、147 组配置，相对固定放置 geo-mean 前向 1.45×、反向 1.28×，峰值 2.14× / 2.64×。流水线藏掉前向 56–76%、反向 91–100% 的复制通信。端到端 prefill 中位仅 1.13–1.26×，说明层内收益会被非 MoE 路径稀释，适合作为 EP megakernel 的 skew 补丁，而不是单独的 serving 方案。
- 是否值得读：强烈推荐
- Relevance Score：5
- Link：https://arxiv.org/abs/2610.00671

【Title】RapidMoE: Exploiting Cross-Asymmetry via Adaptive Residual Offloading for Large-Scale MoE Inference

- 一句话总结：CPU-GPU 异构 MoE 的瓶颈不是“该不该 offload expert”，而是 expert 级搬运和 PCIe/CPU 算力错配；RapidMoE 把 offload 粒度从 expert 降到 bit/residual。
- 核心贡献（2-3点）：
  - residual-split：表示、路由、执行三条路径按硬件能力切开，关键路径留在 GPU，残差走异构设备。
  - Unified Multi-Level Importance Arbitration 在线调整 critical expert set，守 accuracy-latency 前沿。
  - EuroSys 2027 接收；相对 SOTA offload，decode 最高 3.5×、prefill 最高 2.1×。
- 工程价值：对单机/边端和 PCIe 异构池比纯 expert cache 更有落地感。代价是存储布局和双路径 kernel 要一起改，不是 vLLM plugin 级改动。和 MoE-CORE 同周出现，说明 memory-constrained MoE 已从“prefetch expert”转向表示级切分。
- 是否值得读：强烈推荐
- Relevance Score：4
- Link：https://arxiv.org/abs/2610.01265

## 2. AI Infra

【Title】Leto: Fast In-Place Recovery for LLM Training on Surviving Hardware

- 一句话总结：硬件可继续跑的故障（HOF）不该走 checkpoint reload；Leto 把可复用进程态和模型态留在同一批 GPU 上，用 shadow trainer 做原地恢复。
- 核心贡献（2-3点）：
  - 工作模型态 + 可复用进程态保留，其余状态预热在 shadow trainer；显存紧张时回收 shadow。
  - 两级纠删 + chunk 级事务更新，保证保留态可恢复且一致。
  - 6/72×A100：恢复比最好 checkpoint 基线快 3.6–6.5×，有效训练时间最多 +13.7 pp；13 万卡仿真声称 >95% productive time。
- 工程价值：直接打在大集群 goodput 上，而不是单步 MFU。和现有 NCCL/checkpoint 栈是互补关系，适合故障频繁、重启成本高于重算的训练任务。仿真外推要单独打折。
- 是否值得读：强烈推荐
- Relevance Score：5
- Link：https://arxiv.org/abs/2610.00687

【Title】ePACT: Energy-Performance-Aware Commitment Tracking for LLM Serving

- 一句话总结：电费按小时承诺结算时，省电不等于省钱；ePACT 在 SLO 约束下最小化超用/欠用的不对称偏差成本。
- 核心贡献（2-3点）：
  - 两级控制：全局按剩余承诺更新区间能量目标，本地预测能耗和完成时间后选 GPU 容量与时钟。
  - 粗到细动作搜索与 serving 异步，deadline miss 预测失败则 service-first 回退。
  - H20/H200 24 小时仿真：相对 vLLM，不对称偏差成本降 73.8% / 75.7%，小时偏差约 2.2%，SLO 接近 vLLM。
- 工程价值：对有购电合约或碳/功率上限的集群有直接成本意义；对按需云 GPU 价值低。控制器可插在 vLLM 容量层，不改模型。缺公开代码线索，复现成本高。
- 是否值得读：可选
- Relevance Score：3
- Link：https://arxiv.org/abs/2610.01784

## 3. LLM Agents

【Title】Can AI Scientists Coordinate at Runtime?

- 一句话总结：设计时固定 workflow 不够用；RAC 在运行时从已有 AI-scientist host 里选 agent、发有范围的 work contract，并用产物做校验。
- 核心贡献（2-3点）：
  - 运行时协调而不是再堆一个新 agent 角色。
  - artifact-grounded verification，把协调和可检查产物绑在一起。
  - 作者明确指出预算受限时，额外协调机制收益有上限。有代码。
- 工程价值：对做 research/coding agent 编排的人有用，重点是合同边界和校验，不是又一个 planner。系统深度弱于上面的 serving/训练论文，更像协议+实验。
- 是否值得读：可选
- Relevance Score：3
- Link：https://arxiv.org/abs/2610.00980

2. 今日趋势观察

3. 值得跟进的潜在方向
   - MoE 的“相位不对称”：prefill 用全专家、decode 用裁剪/驻留/复制，KV 直接交接。SlimWise（9/28，vLLM）和本周 MoE-CORE / RapidMoE / MegaFlux 在同一条线上。下一步值得看的是：复制、offload、pruning 能否在一个 residency 控制器里共存，而不是各写一套 cache。
