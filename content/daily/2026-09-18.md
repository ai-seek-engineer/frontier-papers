【Title】ASPIRE: Asynchronous Batched Self-Speculative Decoding for Long-Context LLM Inference  
https://arxiv.org/abs/2609.17943

- 一句话总结：把 batched self-speculation 从“全 batch 同步 draft/verify”改成请求级异步调度，长上下文 decode 吞吐再抬一截。
- 核心贡献（2-3点）：
  - mixed forward：同一 batch 里 draft 请求和 verify 请求一起跑，取消全局相位同步。
  - 在线 scheduler：用 per-request 接受率 + batch 成本模型决定何时 verify。
  - draft 中单层 full attention 刷新稀疏上下文，压 staleness。
- 工程价值：直接打长上下文 memory-bound decode；相对 AR 1.70–4.58×，相对最强 self-spec 再高约 27%。可进 vLLM/SGLang 类 continuous batching 路径，不依赖额外 draft 模型。
- 是否值得读：强烈推荐
- Relevance Score：5
- Link：https://arxiv.org/abs/2609.17943

【Title】Fathom: Per-Query Read Depth for Sparse Decoding over Offloaded KV Caches  
https://arxiv.org/abs/2609.17652

- 一句话总结：host 上百万 token KV + 索引扫描成为瓶颈时，按 query 决定每个 key channel 读几 bit，而不是固定 top-k 全扫描。
- 核心贡献（2-3点）：
  - 4-bit K 按 bit-plane 存，前缀平面 = 该 channel 的 t-bit 量化。
  - query 用 reverse water-filling 按通道重要性分配 bit budget。
  - 1M token、Qwen3-8B：相对 Double Sparsity/Loki/SparQ r=32 的 136-bit scan，单步 GPU 时间 1.67×。
- 工程价值：针对 **offload 后的 agent 长会话**，不是 GPU-resident KV。已有 4-bit K 的 serving 栈可复用存储格式；index 在 GPU 上时收益消失——部署前先确认瓶颈在 host scan。
- 是否值得读：强烈推荐（做长会话/offload 的人）
- Relevance Score：5
- Link：https://arxiv.org/abs/2609.17652

【Title】Token Latency Fairness: Performance Isolation for Multi-Tenant LLM Serving (FairInference)  
https://arxiv.org/abs/2609.18112

- 一句话总结：多租户 serving 从“长期吞吐公平”升级到 **per-token 延迟隔离**：好用户相对独占延迟最多多 δ。
- 核心贡献（2-3点）：
  - δ-token fairness：隔离下 d 时间出的 token，共享下 ≤ d+δ。
  - scheduler 用 per-token deadline，同时 bound GPU 共享延迟和 **共享 KV cache 引入的额外延迟**。
  - 对 well-behaved 用户，相对 SGLang/VTC/DLPM 的 TTFT/TBT/TTLT 尖刺大幅压住，吞吐不崩。
- 工程价值：SaaS/内部多租户的真实痛点。实现落在 prefill/decode 准入和 cache 驱逐策略，可改 SGLang 调度器。注意 GPU 无细粒度分片时如何估 isolated latency。
- 是否值得读：强烈推荐
- Relevance Score：5
- Link：https://arxiv.org/abs/2609.18112

【Title】SSD-LLaMA: SSD-Native Inference for Trillion-Parameter MoE at 1+ Token/s on a Consumer PC  
https://arxiv.org/abs/2609.18110

- 一句话总结：消费级单卡 + SSD 跑万亿 MoE，decode 相对基线最高约 15×，并宣称 RTX 5090 + ≤32GB RAM 达到 >1 tok/s。
- 核心贡献（2-3点）：
  - 针对 expert 投递优化的 SSD I/O pipeline。
  - 三层存储层级动态装载/驻留 expert，不做 pruning/替换。
  - CPU–GPU 混合执行平衡。
- 工程价值：本地/边缘跑超大 MoE 的系统模板（I/O 调度 > 算法花活）。数字激进，落地前必须核对自己的 SSD/PCIe 拓扑和 expert 激活模式；对云端 HBM 集群优先级低于 FairInference/ASPIRE。
- 是否值得读：可选（做本地 MoE/offload 再读）
- Relevance Score：4
- Link：https://arxiv.org/abs/2609.18110

【Title】Ask the Tool, Don't Guess: Agent Tool Calls Hold Their Progress, and the Serving System Should Read It  
https://arxiv.org/abs/2609.18849

- 一句话总结：agent 等 tool 时 KV 占着 GPU；serving 不要猜 tool 时长，让 tool **运行中上报进度**，再决定 KV 留/换/预热。
- 核心贡献（2-3点）：
  - 证明调用前固定估时（名字、历史、声明 duration、引擎占用）无法知道真实时长，甚至排不了序。
  - 四个公开 agent corpus：多数 tool 时间里存在可读进度（剩余比例或“快结束”信号）。
  - 接到生产引擎：tool 返回后 p90 TTFT 相对 LRU 降约 20.7%/20.8%，接近 oracle。
- 工程价值：agent serving 的 KV 生命周期问题比再抠 5% decode kernel 更赚钱。改动小（progress hint + 调度），需要 tool/runtime 协议约定。和 FairInference 互补：一个管租户隔离，一个管 tool-wait 的 cache。
- 是否值得读：强烈推荐
- Relevance Score：5
- Link：https://arxiv.org/abs/2609.18849

【Title】The Inference Engineering Pareto Atlas  
https://arxiv.org/abs/2609.17863

- 一句话总结：在同一模型/引擎/三档 GPU 上扫 54 个优化组合，画出 cost–quality–latency 前沿，而不是再报一个孤立 speedup。
- 核心贡献（2-3点）：
  - Qwen2.5-7B + vLLM 0.12，L4/A100/H100，测量校准模拟器（锚定点漂移 <1.5%）。
  - 组合方法比单点方法更常上 Pareto；质量门槛会换赢家（AWQ-4bit 快但 GSM8K 掉点；裸 FP8 KV 吞吐正常但 200 题全错）。
  - n-gram spec 在该栈上 0.90–0.98×，几乎无收益。
- 工程价值：选型决策文档，不是新算法。提醒：量化/KV/spec 不能只看 latency；约束不同则 H100 vs A100 赢家不同。
- 是否值得读：强烈推荐（做推理平台选型）
- Relevance Score：4
- Link：https://arxiv.org/abs/2609.17863

【Title】ECHO: Early-layer Collaborative Hierarchical Orchestration with Bonus Logits in Speculative Decoding  
https://arxiv.org/abs/2609.17241

- 一句话总结：draft-model-free spec：浅层高频探树 + 深层低频 verify，用 bonus logits 纠路径。
- 核心贡献（2-3点）：
  - 内外双环：early layer 便宜多步 draft-tree；outer 全模型 verify + 状态复用。
  - 终层 bonus logits 修正/补候选。
  - 2.4–2.9×，无额外部署参数；最优加速依赖一次性 fine-tune。
- 工程价值：可进无 draft 模型的 serving；有 one-shot FT 成本。和 ASPIRE 比：ECHO 吃层间不对称，ASPIRE 吃 batch 异步。
- 是否值得读：可选
- Relevance Score：4
- Link：https://arxiv.org/abs/2609.17241

## 今日最值得读 Top 3

1. **ASPIRE** — 长上下文 + 投机解码的下一块硬骨头是 **batch 内异构 draft 长度**。混合 forward + 请求级 verify 时机，能直接接到现有 continuous batching，数字完整。
2. **Ask the Tool** — agent 流量里 KV 被 tool-wait 钉死是生产事故级问题；“让 tool 报进度”比再训一个 duration 预测器更对症，改动面小、接近 oracle。
3. **FairInference** — 多租户从 token 公平队列进化到 **token 延迟隔离 + 共享 KV 延迟记账**。Berkeley 系系统论文，对平台调度有明确接口。

## 今日趋势观察

- **Inference / KV / spec 明显占主导**：ASPIRE、Fathom、ECHO、Pareto Atlas、SSD-LLaMA 同一窗口扎堆。焦点从“再做一个 draft 模型”转到 **异步 batch、offload 扫描、质量-成本联合前沿**。
- **Agent 论文开始长在 serving 上**，而不是新 planner：tool 进度、KV 去留、tool-wait 期间的内存。纯 prompt agent 几乎没有工程增量。
- **SFT/RLHF 本日偏弱**：STRETCH 是课程式自训练；安全 alignment 增量小，未入选。RL 侧更多机器人（WeaveRL），LLM RL 系统稿偏少。

## 值得跟进的潜在方向

1. **Agent-aware KV lifecycle**：progress hint + 预取 + 多租户 δ-fair 合成一条调度策略（Ask the Tool × FairInference）。
2. **Offloaded / hierarchical KV 的 query-adaptive I/O**（Fathom）：agent 百万 token 会话会把瓶颈从 HBM 挪到 host 扫描和 PCIe。
3. **优化组合的质量门禁**：Pareto Atlas 里“FP8 KV 全错、n-gram spec 无效”说明平台需要 **同一评测网格**，而不是堆开关。
4. **消费级 SSD-MoE**：若 I/O 流水线可复现，会反向影响云上 expert 缓存策略；先验证 PCIe 带宽模型和 expert 驻留命中，再投入。
