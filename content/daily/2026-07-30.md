### 1. Inference Optimization

**【Title】** AngelSpec: Towards Real-World High Performance Inference with Speculative Decoding  
- 一句话总结：统一 MTP + block-parallel diffusion 的投机解码框架，按领域专精 drafter 并做在线 verification 自适应。  
- 核心贡献：  
  1. 数据-结构共专精：MTP 训对话、block-diffusion 训代码/数学。  
  2. DFly 架构（hybrid target-conditioning + predecessor AR head）。  
  3. 把 verification 当作 batch 级共享资源，按置信度+成本模型动态调深度。  
- 工程价值：直接可用于生产推理服务。Hy3 系列平均 accepted length +30%，并发 4–64 下 throughput 最高，相对 AR 1.98–2.40×，相对 DFlash 再高 10.5–11.8%。已开源训练与扩展代码。  
- 是否值得读：强烈推荐  
- Relevance Score：5  
- Link：https://arxiv.org/abs/2607.25852

**【Title】** OmniDelta: Skill-Driven Budget Allocation for Token Compression in OmniLLMs  
- 一句话总结：训练无关的 skill-driven 跨模态+模态内 token 预算分配，解决 OmniLLM 长音视频序列压缩。  
- 核心贡献：  
  1. 用 skill pool 做 intent-aware 跨模态预算转移。  
  2. 基于局部复杂度与时序冗余做帧/段级再分配。  
  3. 可与现有 pruning 策略无缝组合。  
- 工程价值：纯推理侧优化，无重训。Qwen2.5-Omni-7B 25% retention 时 GPU 显存 -22%，端到端 1.64× 加速，新 Pareto 前沿。适合多模态服务落地。  
- 是否值得读：强烈推荐  
- Relevance Score：4  
- Link：https://arxiv.org/abs/2607.25669

### 2. AI Infra / 分布式训练 / 系统优化

**【Title】** SpecBox: Speculative Sandbox Scheduling for Efficient LLM Agent Serving  
- 一句话总结：面向 MCP 沙箱的投机预分配 runtime，解决 agent 多租户多轮场景下冷启动与内存占用矛盾。  
- 核心贡献：  
  1. 关键词+流式语义 embedding 做 mid-generation 意图预热。  
  2. 依赖图驱动的随机 prefetch 跨 step 预测。  
  3. 语义结果缓存 + 共享内存零拷贝传输。  
- 工程价值：直接服务 agent 基础设施。P99 端到端延迟最高降 2.9×，峰值内存相对永久预留降 45.9%。系统论文，可落地。  
- 是否值得读：强烈推荐  
- Relevance Score：5  
- Link：https://arxiv.org/abs/2607.23933

**【Title】** PowerScale: Energy-Efficient Geo-Distributed Model Training with Federated Datacenter Power  
- 一句话总结：分层 Sync-Async 聚合，兼顾网络延迟层级与数据中心电力约束，降低 geo-distributed 训练能耗。  
- 核心贡献：  
  1. 区域 cluster 内高频本地同步 + 全局异步推送。  
  2. 按网络距离+电力可用性组 cluster。  
  3. 自适应同步频率随训练进度降低通信。  
- 工程价值：100-site 模拟显示 time-to-accuracy 持平或略优，能耗最高降 3.9×。对超大规模训练电力受限场景有直接参考价值。  
- 是否值得读：可选  
- Relevance Score：4  
- Link：https://arxiv.org/abs/2607.25650

### 3. LLM Agents

**【Title】** Speculate While You Reason: Teaching Agents to Predict Their Next Tool Call via Joint Agent-Speculator RL  
- 一句话总结：把 agent 与 next-tool-call 投机器统一到同一模型，用 joint RL 消除 gap 并复用 prefix KV。  
- 核心贡献：  
  1. 自投机 agent（同一模型双模式）。  
  2. 从自身 rollout 提取 speculation target，交替更新。  
  3. 完全复用 prefix KV cache。  
- 工程价值：直接降低 tool-call 等待延迟。Qwen3-4B Hit@1 从 44.1→61.2，任务成功率不降。适合高延迟工具场景的 agent serving。  
- 是否值得读：强烈推荐  
- Relevance Score：5  
- Link：https://arxiv.org/abs/2607.25816

**【Title】** Tools Are Not Islands: Set-Level Tool Retrieval for LLM Agents via Query-Conditioned Hyperedge Prediction  
- 一句话总结：把工具检索建模为 query-conditioned hyperedge 预测，直接评分工具集合而非单工具。  
- 核心贡献：  
  1. 超图视角统一现有检索范式。  
  2. 基数感知的交互建模。  
  3. 纯 pre-selection 模块，无需改 agent。  
- 工程价值：ToolBench 上检索与端到端成功率均超 SOTA，支持 zero/few-shot 迁移。可插拔进现有 agent pipeline。  
- 是否值得读：可选  
- Relevance Score：4  
- Link：https://arxiv.org/abs/2607.25718

### 4. SFT / Alignment / RLHF

**【Title】** MemSFT: Mitigating Alignment Tax with an External Parametric Memory  
- 一句话总结：用可插拔 parametric memory 解耦领域专精与 backbone 更新，消除 alignment tax。  
- 核心贡献：  
  1. memory 模仿非参数检索行为，记忆领域模式。  
  2. 同一 memory 可跨不同尺寸 LLM 复用。  
  3. 学习 router 在每步动态融合 memory 与 backbone 分布。  
- 工程价值：生物/地学/法律领域实验（Qwen3-8B 到 235B）显示领域性能提升、通用性能几乎不掉。比 full SFT 更实用的领域适配路径。  
- 是否值得读：强烈推荐  
- Relevance Score：4  
- Link：https://arxiv.org/abs/2607.25614

**【Title】** Pass the Baton: Trajectory-Relayed On-Policy Distillation  
- 一句话总结：在 OPD 中引入 teacher 短暂接管失败前缀的 relay 机制，解决 prefix failure 问题。  
- 核心贡献：  
  1. 检测 teacher-student 延续不对称作为触发。  
  2. 有限 budget 的 relay trajectory 构造。  
  3. 学生在 teacher leg 后继续并优化。  
- 工程价值：数学推理 8 个 benchmark 上全面领先标准 OPD（+5.73%）与 FastOPD，训练轨迹长度减半。已开源。  
- 是否值得读：可选  
- Relevance Score：4  
- Link：https://arxiv.org/abs/2607.26057

### 【额外输出】

**1. 今日最值得读 Top 3**  
1. **AngelSpec** —— 投机解码从“学术 demo”真正走向生产异构 workload，数据-结构-在线调度三位一体，数字扎实且开源。  
2. **SpecBox** —— agent serving 的系统瓶颈（沙箱冷启动+内存）被精准击中，投机预热+缓存+零拷贝组合工程味极浓。  
3. **Speculate While You Reason** —— 把 tool-call 投机内化到 agent 自身，KV 复用+joint RL，直接解决 agent 墙钟时间最大痛点。

**2. 今日趋势观察**  
- Inference 与 Agent 交叉明显增强：投机解码不再只服务纯 LLM 生成，而是进入 tool-call 与 sandbox 调度。  
- Agent 系统论文增多（服务、检索、skill graph），且更关注延迟/资源而非单纯成功率。  
- 纯 scaling/对齐论文占比下降，工程可落地性成为筛选门槛。

**3. 值得跟进的潜在方向**  
- **Self-speculating Agent**：把“下一动作预测”与主 agent 统一，复用 KV，可能成为 agent 推理加速的标准范式。  
- **Budget Allocation for Multi-modal Tokens**：OmniLLM 的 token 预算从固定 ratio 转向 skill/intent 驱动，值得扩展到更复杂动态场景。  
- **Hierarchical Skill Graphs + Symbolic State**：把技能从扁平文本集合升级为可执行图，配合状态机，可能显著降低长程 agent 的 token 消耗与错误率。
