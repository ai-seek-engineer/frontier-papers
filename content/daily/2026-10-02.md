## 1. Model Inference / 推理优化

【Title】SEED: Self-Speculative Decoding via Implicit Encoder-Decoder

- 一句话总结：把 decoder-only 拆成“深层 encoder 建上下文 + 末几层当轻量 decoder 起草”，验证时算出的表示直接复用，避免每次 draft 再跑完整 forward。
- 核心贡献（2-3点）：
  - 编码和验证合并成一步，draft 只跑末层自回归，成本低于 early-exit 的质量损失，也低于 MTP 每步全前向。
  - 4B 量级平均最高约 2.7×，比 EAGLE-3 快约 28%，质量不低于标准自回归微调。
  - NeurIPS 2026，公开代码。
- 工程价值：可直接嵌进现有 speculative decoding 栈，不需要额外 draft 模型，也不需要维护 drafter 侧 KV。适合 batch=1 和中小模型 serving；大模型上接受长度是否还能打过 EAGLE-3 需要自己复测。
- 是否值得读：强烈推荐
- Relevance Score：5
- Link：https://arxiv.org/abs/2609.36590

【Title】Taming Speculative Search for Test-Time Scaling in LLM Serving（SpecScale）

- 一句话总结：推理时多路径搜索不是“多开几个 beam”就行，候选爆炸和细粒度 verify 会把 serving 打穿；SpecScale 用早剪枝、路径去重、延迟 verify 把 speculative search 收成可调度的任务。
- 核心贡献（2-3点）：
  - 明确两类系统问题：搜索空间膨胀、verify 粒度太细导致调度碎片。
  - 三件套：低质量路径早停、跨路径计算去重、把细粒度校验推迟到可批处理窗口。
  - 在 MATH / Olympiad 上相对非投机和已有投机方案同时改善吞吐与延迟，答案质量保持。
- 工程价值：面向 reasoning / TTS 服务，而不是单请求加速。可插在 continuous batching 之上，优先看 KV 共享和 verify batch 的实现，而不是算法公式。论文未强调开源，落地前要核对调度接口。
- 是否值得读：强烈推荐
- Relevance Score：5
- Link：https://arxiv.org/abs/2609.39334

## 2. AI Infra / 分布式训练与系统

【Title】Cobalt: Leveraging Expert Co-activation for Efficient Distributed MoE Training

- 一句话总结：MoE 训练的跨节点流量不是均匀 all-to-all，常共激活的 expert 应放在同一节点；Cobalt 用两阶段布局 + 通信感知路由把 token 尽量留在本地。
- 核心贡献（2-3点）：
  - 周期性地把共激活 expert 共置，再做步内节点内再平衡。
  - 按当前布局把 token 路由到更少远程节点。
  - 32×B200 上相对现有 MoE 训练框架平均 1.28–1.89×（峰值 1.53–2.41×），跨节点 token 流量降 75.74%–99.26%。
- 工程价值：直接打 EP 训练的通信和负载不均，硬件是当前主力 B200。前提是共激活模式足够稳定；如果数据分布漂移很快，重规划频率会吃掉收益。值得对照 Megatron / DeepSpeed-MoE 的 expert placement。
- 是否值得读：强烈推荐
- Relevance Score：5
- Link：https://arxiv.org/abs/2609.36959

【Title】ThunderEP: Efficient Expert-Parallel Communication on PCIe-Connected Consumer GPUs

- 一句话总结：消费级多卡没有 NVLink 时，MoE 的 dispatch/combine 被 PCIe ring 中继和 CPU flag 轮询拖死；ThunderEP 去掉 relay hop，用 DMA 搬数据，并压缩完成标志的轮询。
- 核心贡献（2-3点）：
  - 通信路径绕开计算 SM，避免和 GEMM 抢资源。
  - 已接入 vLLM，在 RTX 4090 / 5090 的 PCIe 系统上测三个常用 MoE。
  - dispatch / combine 相对 NCCL 平均 2.00× / 1.53×，端到端相对现有 MoE 推理框架最高 1.66×。
- 工程价值：对私有化、多 4090/5090 的推理集群比论文标题看起来更有用。数据中心 NVLink 机内收益会小很多，不要外推到 HGX。优先看 vLLM 集成点和与现有 all-to-all kernel 的兼容。
- 是否值得读：强烈推荐
- Relevance Score：4
- Link：https://arxiv.org/abs/2609.40093

（同日 HAPMoE 做异构集群上 MoE 六维并行搜索，计划可直接下到 Megatron-LM，端到端最高约 3.2×，搜索 <1 分钟。和 Cobalt 互补：Cobalt 改布局与流量，HAPMoE 改并行计划。链接：https://arxiv.org/abs/2609.39350）

## 3. LLM Agents

【Title】Persistent Context Graphs for Efficient Memory Compaction in LLM Agents（ReCAP）

- 一句话总结：agent 压缩历史不该每次再叫一次模型做摘要；把历史注意力重要性和依赖边存成持久图，新请求来时沿边选取，不再额外推理。
- 核心贡献（2-3点）：
  - 节点是历史块，边上是依赖，分数来自已有 attention，不另训选择器。
  - 相对 Codex 默认摘要压缩，压缩和冷恢复延迟估计降约 95%（Qwen3-Coder、gpt-oss）。
  - SWE-Together 上历史上下文大约减半且任务质量相当；Lost-in-Conversation 代码任务相对全历史 +19.8 / +41.2 点。
- 工程价值：直接砍长轨迹 agent 的 prefill。实现成本主要在“从哪一层、哪次 forward 抽 attention 并持久化”，要处理 prefix cache 失效。比重摘要更适合在线 coding agent。
- 是否值得读：强烈推荐
- Relevance Score：4
- Link：https://arxiv.org/abs/2609.40118

【Title】Mid-Harness: Scaling Actions Between Model and Harness for Terminal Agents

- 一句话总结：终端 agent 的失败经常不是不会生成动作，而是错误命令一旦执行就污染环境；在 model–harness 边界对候选动作做采样+校验，再放行一条。
- 核心贡献（2-3点）：
  - 生成器和 harness 都不改，只在边界插入 verifier。
  - TerminalBench-Lite 上，TMAX-9B 生成 + GPT-5.6 Sol 校验、8 个候选，Pass@1 从 50.00% 到 68.03%。
  - 弱校验几乎没用；同模型做 pairwise verify 最好。动作级扩展比单纯多开轨迹更省 token。
- 工程价值：这是 serving/agent runtime 的插入点，不是再训一个 planner。成本在 verifier token，收益取决于环境是否可回滚。不可回滚的 shell 场景优先看这篇。项目页：https://byungkwanlee.github.io/MidHarness-page/
- 是否值得读：可选
- Relevance Score：4
- Link：https://arxiv.org/abs/2609.39982

## 4. SFT / Alignment / RLHF

【Title】RLTL;DR: Self-improvement by Internalizing Self-generated Feedback

- 一句话总结：Pass@128=0 的任务上 GRPO 没有正样本可学；让策略在失败后自己写一条 TL;DR，下一轮带上这些洞察，并把“任务→洞察”反传进权重，评测时不再需要洞察上下文。
- 核心贡献（2-3点）：
  - 在工具调用和代码集上，Qwen 3.5 9B Thinking 的 GRPO 停在 Pass@1 0–1%；RLTL;DR 评测无洞察时到 12–13%（训练时带洞察 14–31%）。
  - 消融指出关键是任务到洞察的内化，不是更长的 rollout。
  - 只 SFT 4k 条 (task, insight) 几乎追平完整 RLTL;DR 和全 rollout SFT。
- 工程价值：难任务 RL 的数据效率路径。训练侧可把长轨迹蒸馏成短洞察，省 rollout 存储和上下文。Apple 工作，许可是 CC BY-NC-ND，复现和商用要单独看。
- 是否值得读：强烈推荐
- Relevance Score：4
- Link：https://arxiv.org/abs/2609.37633

## 额外输出

1. 今日最值得读 Top 3
   - SEED：推理侧最容易变成吞吐的一篇。无额外 draft 模型，有代码，对照是 EAGLE-3 而不是自造弱基线。
   - Cobalt：训练侧数字干净（32×B200、跨节点流量降一个数量级）。MoE 通信仍是集群账单大头。
   - SpecScale：把 test-time scaling 从算法问题收成 serving 调度问题。做 reasoning API 的人应先看剪枝和 verify 批处理，而不是再堆搜索宽度。

2. 今日趋势观察
   - 推理优化没有停在 KV 压缩，重心转到两处：自投机解码（SEED），以及 TTS 搜索的服务化（SpecScale）。
   - MoE 通信同时出现在训练（Cobalt、HAPMoE）和消费级推理（ThunderEP），说明 expert placement 正在从研究点变成默认系统问题。
   - Agent 论文里工程含量高的，几乎都在减上下文或拦错误动作（ReCAP、Mid-Harness），而不是再加一个 agent 角色。

3. 值得跟进的潜在方向
   - Agent KV / 历史的分层介质。同日 *Characterizing High Bandwidth Flash for LLM Serving*（https://arxiv.org/abs/2609.39131）用 HBM–HBF–host，配合 cache-aware 调度，完成时间相对纯 HBM 降 36.1–87.0%，并把 HBF 写入寿命从约 4.77 年抬到约 14.82 年。和 ReCAP 的“少往上下文里塞历史”是同一压力的两侧：容量墙 + 写寿命。
   - 动作级校验而不是轨迹级重采样。Mid-Harness 说明 verifier 质量决定 test-time compute 是否值得花，弱校验等于白烧 token。
   - 难任务对齐不必存全 rollout。RLTL;DR 的 SFTL;DR 变体暗示：内化短洞察可能替代大部分 GRPO 轨迹存储。
