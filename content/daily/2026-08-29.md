【Title】Launch-Bound and Substitutable: Why Three Inference Optimizations Fail to Pay Off in Mixture-of-Experts Models

- 一句话总结：在真实 MoE 上把 fused kernel / INT4 / CUDA Graph 拆开测完，结论是多数“教科书优化”端到端几乎不赚钱。
- 核心贡献（2-3点）：
  - OLMoE / DeepSeek-V2-Lite / Qwen3-30B-A3B 上，Triton fused kernel 单算子 5.6–9.0×，端到端只有 ~0.999×（上限约 1.07×），瓶颈是每 step ~1000 次 kernel launch，不是算术。
  - INT4 会改平均 0.53/8 个被选 expert，但把改道后的路由用 FP 权重重放，只解释 2.7% 的质量损失 → expert 可替换，不是高度特化。
  - 路由器留 FP16 可降 20% route drift，但 loss 上升：路由保真与输出质量可分离。
- 工程价值：直接改 serving 优先级——MoE 先砍 launch / 合并 dispatch，别先卷 kernel 与盲目 INT4；量化质量问题不要默认当成“选错 expert”。
- 是否值得读：强烈推荐
- Relevance Score：5
- Link：https://arxiv.org/abs/2608.26612

【Title】Performance Foundations of Parallel & Distributed Reasoning Language Models

- 一句话总结：把 RLVR/PPO/GRPO 训练当成分布式系统问题，给出 intra/inter-model 并行 taxonomy 和可落地指南。
- 核心贡献（2-3点）：
  - 用 work-depth 模型分析 PPO/GRPO 及其变体的计算结构（多模型、长 rollout、tight coupling）。
  - 覆盖 DP/TP/PP/SP/CP/EP，以及 disaggregated placement、stage fusion、hybrid parallelism、async execution。
  - 对现有 RLM 框架做对照，列出可扩展、低成本训练的开放问题。
- 工程价值：做 RL post-training infra 的必读地图；决定 actor/critic/reward 是否拆分、rollout 与 update 是否解耦时直接有用。无新 kernel，但是系统设计基准。
- 是否值得读：强烈推荐
- Relevance Score：5
- Link：https://arxiv.org/abs/2608.27046

【Title】psRL: Efficient Training for Agentic AI via Training-Time Prefix Sharing

- 一句话总结：agentic RL 的瓶颈从 rollout 转到 update 后，用训练期 prefix sharing 把吞吐打到现有系统的 5.2×。
- 核心贡献（2-3点）：
  - 观察：tree / step-wise RL 让样本暴增、边际 rollout 便宜，update 成为主耗时，且样本间 prefix 高度重复。
  - 两种 prefix-sharing 调度：细粒度分片 + 负载均衡，利用 update 阶段全局可见、数据不可变。
  - 自研 KV manager：可变 block size + 动态缓存，兼顾命中率与显存。
- 工程价值：直接可做进 GRPO/agent RL trainer（Megatron/veRL 类）。代码承诺开源。这是“训练侧推理优化”，不是算法论文。
- 是否值得读：强烈推荐
- Relevance Score：5
- Link：https://arxiv.org/abs/2608.25683

【Title】More GPUs or a Smaller Cache? Tensor Parallelism versus KV Compression for Memory-Bound LLM Serving

- 一句话总结：KV 不够时，加卡做 TP 还是压 KV？在成本轴上压缩几乎总是更便宜，但延迟只有 TP 能救。
- 核心贡献（2-3点）：
  - 在 A100/A40/H100、Llama-2 7B/70B 上，把 TP=1–8 与 16/8/4-bit、keep-ratio 到 0.25 放到同一 cost/token–latency 平面。
  - 没找到交叉点：压缩便宜 1.20–2.00×；容量/$ 压缩最高 16.5×，8 卡 TP 只有 1.21×。
  - 决策边界约 36B @ 80GB：之下压 KV，之上权重本身撑爆单卡，TP 是入场券。压缩会把 per-token latency 变差 8–93%。
- 工程价值：容量扩容先压 KV，SLA/延迟扩容才上 TP。避免“显存不够就加卡”。
- 是否值得读：强烈推荐
- Relevance Score：5
- Link：https://arxiv.org/abs/2608.23962

【Title】Minima-KV: Retention-Preserving KV Cache Compression with Mixed-Format Paged Attention

- 一句话总结：同一条请求里 FP8 anchor page + TQ3 旧 page 混排，异构 attention 直接 decode，不需要 dense shadow cache。
- 核心贡献（2-3点）：
  - 近端/保护页留 FP8，旧非 anchor 打成 packed TQ3，页仍可寻址。
  - 分格式 kernel + 全局归一化 online-softmax merge。
  - Qwen3.6-27B @ 96GB Blackwell：18.3 KiB KV/token（相对 BF16 3.50×，相对 FP8 1.75×）；LongBench v2 16/32/64K 掉 0.80/0.60/0.40 pp；59K 双请求 canary 3.625× 压缩、吞吐 0.982×。
- 工程价值：可插 paged attention 路径；关键是“异构 format 不物化全精度副本”。适合长上下文 serving，不是研究 toy。
- 是否值得读：强烈推荐
- Relevance Score：4
- Link：https://arxiv.org/abs/2608.23834

【Title】Elastic KV Cache for LLM Serving: A Working Reclamation Mechanism, and Why Chunked Prefill Already Closes the Gap

- 一句话总结：启动时一次定死的 KV 池可以用 CUDA VMM 在 decode 借、prefill 还；同时证明 chunked prefill 的 TTFT 惩罚很小。
- 核心贡献（2-3点）：
  - 用户态双 physical handle 映射到每层同一虚拟区间，attention kernel 零改、不打驱动。
  - 调度器前瞻下一批次，decode 把 reserve 借给 KV pool。
  - 静态 reserve 遇 prefill burst 会 OOM；弹性可多回收 ~18% KV、decode 吞吐 +~10%。chunk 8K vs 32K 中位 TTFT 差约 1%。
- 工程价值：vLLM 类引擎可直接抄的 allocator 技巧；也纠正“必须巨大 chunk 才能保 TTFT”的直觉。
- 是否值得读：可选（机制短、结论硬）
- Relevance Score：4
- Link：https://arxiv.org/html/2608.23658

【Title】Scheduling Mixed RL Rollouts Beyond Prefix Locality

- 一句话总结：RLVR / RLHF / agent rollout 混跑时，只做 prefix-aware 路由不够，要用 workload-aware 的 KV 准入与驻留记账。
- 核心贡献（2-3点）：
  - 三类 rollout 的序列结构、交互模式、KV 驻留时间差很大，会互相挤爆 cache。
  - MISA-T：自适应 session 准入 + 按负载分 KV 配额 + 按驻留时间记账。
  - vs cache-aware vLLM Router：rollout 吞吐 +53.3% / +43.6%；50-iter 实验吞吐 +35.6%、迭代时间 -22.8%，workload mix 仍贴近 trainer。
- 工程价值：共享推理集群给多团队 RL 用时，这是调度层而不是模型层。可直接对照 vLLM router。
- 是否值得读：可选
- Relevance Score：4
- Link：https://arxiv.org/html/2608.11152v1

【额外输出】

1. 今日最值得读 Top 3
- **Launch-Bound and Substitutable**：少见的负结果+全路径测量。MoE serving 团队读完能立刻停掉无效优化。
- **psRL**：agentic RL 训练的真实瓶颈已经换位；5.2× 来自系统而不是新算法，可跟进实现。
- **Performance Foundations of … RLMs**（Hoefler 组）：RL post-training 的并行/放置设计手册，比再读一篇 GRPO 变体更有杠杆。

2. 今日趋势观察
- Inference / KV 仍然是绝对主场：压缩 vs TP、混合精度 paged attention、弹性分配、MoE 优化失效。
- 第二波是 **RL 训练系统**（不是新 objective）：prefix sharing、混合 rollout 调度、RLM 并行 taxonomy。Agent 论文很多，但有系统设计+吞吐数字的少。
- SFT/Alignment 纯算法稿工程密度偏低，本轮不入选。

3. 值得跟进的潜在方向
- **Update-phase prefix reuse**：tree/step-wise RL 让 trainer 的 KV 语义接近 serving prefix cache，训练引擎会向推理引擎靠拢。
- **MoE 的 launch-bound 服务**：专家可替换 + 路由/质量可分离 → 值得做 route-stable 量化与 launch 合并，而不是继续堆 fused GEMM。
- **异构 KV format 无 shadow**：Minima-KV 路线如果能进 vLLM/SGLang，长上下文单卡容量会再上一个台阶。
- **成本轴而不是加速比轴**：压缩更便宜、TP 更低延迟——容量规划和 SLA 规划应拆开，而不是一张“加速比表”。
