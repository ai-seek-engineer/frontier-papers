## 1. Inference

【Title】Tailoring the Quantization Space for 1-Bit KV Cache Compression (TaSQ)

- 一句话总结：把 1-bit KV 向量量化的误差空间按 query 敏感度、跨头统计和协方差重排，而不是直接量化原始 K/V。
- 核心贡献（2-3点）：
  - RoPE 兼容变换可折进投影权重和 codebook，服务路径仍是普通 VQ lookup。
  - 在通用、长 CoT、长上下文检索上优于现有低比特 KV-VQ，推理稳定性更好。
  - SGLang 实现：单卡 RTX 6000 Ada 上相对 BF16，batch 最大约 14×，峰值吞吐约 1.87×。
- 工程价值（重点分析：是否能用于推理/infra优化）：直接打 decode 带宽墙。变换离线合并后，热路径开销可忽略，适合长上下文、高并发 serving。需核对 codebook 与现有 paged KV 布局是否兼容。
- 是否值得读：强烈推荐
- Relevance Score：5
- Link：https://arxiv.org/abs/2610.03027

【Title】BitNest: Bit-Nested Speculative Decoding for Memory-Efficient LLM Inference Acceleration

- 一句话总结：先训强低比特基座，再用残差恢复高精度目标，draft 与 target 共用一份物理权重。
- 核心贡献（2-3点）：
  - 去掉独立 draft 权重，边端显存不再为投机解码付双份模型。
  - 同一渐进精度思路延伸到长上下文 KV。
  - 7B–8B 上平均接受率 95.2%，端到端相对 FP16 自回归约 1.48–1.61×。
- 工程价值（重点分析：是否能用于推理/infra优化）：适合显存紧的端侧/单卡服务，不适合已经有独立小 draft 且带宽不是权重的云端大 batch。验收点是残差恢复是否破坏现有量化 kernel。
- 是否值得读：可选
- Relevance Score：4
- Link：https://arxiv.org/abs/2610.02800

## 2. AI Infra

【Title】VenusRL: A Fully Disaggregated Agentic RL System with Priority Scheduling and Scalable Interaction

- 一句话总结：agentic RL 的瓶颈不在优化器，而在 rollout 完成顺序和 sandbox 内存；用优先级调度和沙箱去重把训练步解开。
- 核心贡献（2-3点）：
  - 用长度预测把最可能解锁下一步训练的样本组提前，覆盖 admission、KV 驻留和跨 worker 编排。
  - 沙箱不再按声明内存上限静态超配，同 prompt 启动的环境少复制状态。
  - 端到端训练最高约 4.24×，环境成本最多降约 89%。
- 工程价值（重点分析：是否能用于推理/infra优化）：训练侧系统稿，可直接映射到现有 rollout 集群。长度预测调度与 serving 的 SJF 是同一类问题，误判会饿死长轨迹，需要和 credit/超时策略一起看。
- 是否值得读：强烈推荐
- Relevance Score：5
- Link：https://arxiv.org/abs/2610.03286

【Title】Jumping the Line: Exploiting Length Predictions in LLM Scheduling

- 一句话总结：基于预测长度的 SJF/类 SJF 调度可被对抗后缀骗过，短预测换到更高优先级。
- 核心贡献（2-3点）：
  - 以 TRAIL 为案例，优化后缀让轻量长度探针低估输出长度，最多低估约 83.4%。
  - 端到端对抗请求平均完成时间最多快约 1.53×，真实长度变化远小于预测变化。
  - 防御：把长度预测收成粗区间，可削弱插队并减轻对正常请求的拖累。
- 工程价值（重点分析：是否能用于推理/infra优化）：不是加速器，是调度器的攻击面说明。凡是用预测长度做抢占、KV admission 或 agentic RL 优先级的系统都应读。
- 是否值得读：强烈推荐
- Relevance Score：4
- Link：https://arxiv.org/abs/2610.03430

## 3. LLM Agents

【Title】LEAP: Learning Efficient Action Proposals For LLM Agents

- 一句话总结：把投机解码从 token 提到 action：小模型提案、大模型验证，agent 步间串行被并行掉。
- 核心贡献（2-3点）：
  - 0.6B drafter 在目标动作序列上训练，多数决策与 target 一致。
  - 端到端墙钟最多快约 60%，任务成功率无系统性变化。
  - drafter 可在线训，不必先收离线 trace。
- 工程价值（重点分析：是否能用于推理/infra优化）：对 coding/tool agent 的延迟比再压一层 token 投机更直接。成本在 draft、验证等待和工具执行三段，框架把加速拆开了，便于接到现有 agent runtime。
- 是否值得读：强烈推荐
- Relevance Score：5
- Link：https://arxiv.org/abs/2610.02670

【Title】Credit Where It Matters: Dependency-Aware Policy Optimization for Terminal Agents

- 一句话总结：终端 agent 的信用不按步均分，而按命令读写依赖图从 verifier 检查的资源往回追。
- 核心贡献（2-3点）：
  - 从执行 trace 建 command dependency graph，只给相关写和支撑读分配优势。
  - 把轨迹级 advantage 重分配到步骤，减少无关 shell 操作吃到梯度。
  - 在复杂终端任务上提高成功率和训练稳定性（文中有对比与消融）。
- 工程价值（重点分析：是否能用于推理/infra优化）：训练信号设计，不直接加速推理。对 Terminal-Bench / SWE 类 RL 有用，依赖图抽取必须便宜且稳，否则图本身成为 rollout 税。
- 是否值得读：可选
- Relevance Score：4
- Link：https://arxiv.org/abs/2610.03634

## 4. SFT / Alignment / RLHF

【Title】Follow the Winners: Conservative Policy Improvement with the Cross-Entropy Method for Critic-Free RFT

- 一句话总结：用 replay buffer 上的序筛选代替 GRPO 的组内重复 rollout，把方差削减从 GPU 生成挪到 CPU 内存。
- 核心贡献（2-3点）：
  - 控制即推理视角下，GRPO、DPO、FTW 是同一族的不同建模；GRPO 风险中性，DPO/FTW 带有界风险寻求偏移。
  - 序统计给出多项式集中，不必每次都采一组新轨迹。
  - Sokoban 与 Search-R1 上对齐 GRPO/PPO，代价换成 buffer 内存。
- 工程价值（重点分析：是否能用于推理/infra优化）：直接砍 agentic RFT 最贵的生成。staleness 与 off-policy 修正是落地门槛，和 experience replay 类工作同一条线。
- 是否值得读：强烈推荐
- Relevance Score：4
- Link：https://arxiv.org/abs/2610.03361

【Title】FrugalEvo: Towards Cost-Aware LLM-Guided Program Evolution

- 一句话总结：进化式程序搜索不按固定步数优化，而按单位成本收益优化：贵模型出策略，便宜模型写代码并迭代。
- 核心贡献（2-3点）：
  - 10 个数学/系统优化任务上质量对齐或超过 OpenEvolve、ShinkaEvolve 等，9 个任务 BA-AUC 更高。
  - circle packing：GPT-5.6 Terra/Luna 约 1.68 USD，GLM-5.3/Flash 约 0.55 USD 打到或超过平均约 50 USD 的多 agent 基线。
- 工程价值（重点分析：是否能用于推理/infra优化）：不是推理内核，是 agent 搜索的成本调度。适合内部程序优化/算子搜索，不适合在线 serving。
- 是否值得读：可选
- Relevance Score：3
- Link：https://arxiv.org/abs/2610.03675

## 5. Reinforcement Learning

本窗口内通用 RL 多是 workshop/机器人稿，工程信号弱于上面的 LLM-RFT。不单列，避免灌水。DepGPO 与 FTW 已覆盖 agent RL 训练。

---

### 今日最值得读 Top 3

1. VenusRL：少数把 agentic RL 当成分布式系统来做的稿，4.24× 和 89% 环境成本是可执行指标，不是又一个 advantage 变体。
2. TaSQ：1-bit KV 仍能保持 VQ lookup，并给出 SGLang 吞吐/batch 数字。长上下文 serving 能直接试。
3. LEAP：把投机从 token 抬到 action，并支持在线训 drafter。agent 产品的墙钟延迟比再抠 5% 接受率更值钱。

### 今日趋势观察

这一波不是新的注意力变体。可见增量集中在两处：KV 仍是推理主线（1-bit VQ、比特嵌套 draft），以及 agent 从“会用工具”转到“rollout 怎么调度、动作怎么投机、信用怎么沿依赖图走”。长度预测同时出现在训练调度（VenusRL）和 serving 攻击（JIL），说明预测长度已经是控制面的关键信号。

### 值得跟进的潜在方向

Agent 推理与训练共设计。同一条轨迹同时受三件事约束：动作级投机（LEAP）、完成顺序/沙箱内存（VenusRL）、依赖图信用（DepGPO）。谁先把这三件接到一个 runtime（共享 KV、可抢占 sandbox、可解释的 advantage），谁就更接近可规模化的 coding-agent 训练，而不是再堆一个 GRPO 变体。长度预测调度的安全边界（JIL）应和这套控制面一起做，否则优先级系统可被后缀操纵。
