【Title】AgentKV: Phase-Aware KV Eviction for Agentic LLMs  
arXiv:2609.14872（2026-09-14）

- 一句话总结：Agent 轨迹里 think/act/tool 的 query 子空间不同，用分阶段 query buffer 做 KV eviction，而不是用最近 token 当代表。
- 核心贡献（2-3点）：
  - 用 principal-angle 证明 agent 未来 query 是 phase mixture，recency-based eviction 系统性丢掉下一阶段要用的 key。
  - 每 phase 维护小 query buffer，对 union 打分；多轮 serving 路径上跨 turn 携带压缩 KV 并在线 compact page。
  - Qwen3-32B / Nemotron，6 域 × 3 budget：相对 R-KV / Tri-attention 任务分 +5.3~5.5；相对 full-KV SGLang 输出吞吐最高 1.80×。代码开源。
- 工程价值：可直接替换 SGLang/vLLM 一类 eviction 规则，不改权重。Agent 流量 KV 带宽才是瓶颈时，这是少有的“对着真实 phase 结构”而不是 chatbot recency 的方案。
- 是否值得读：强烈推荐
- Relevance Score：5
- Link：https://arxiv.org/abs/2609.14872

【Title】BOOST: Concurrent Access to Host Memory and HBM to Accelerate LLM Inference  
arXiv:2609.13592（2026-09-11）

- 一句话总结：不改 kernel，让 decode 同时按比例吃 HBM + host memory 带宽。
- 核心贡献（2-3点）：
  - wave-aware 分页：静态权重用 modulo placement 消掉 access-ratio 方差；动态 KV 的 free page pool 也按 wave 管理。
  - 接入 vLLM，Grace Hopper 实测：同 batch TPOT +4.3%（prefetch 反而 -6%）；高吞吐场景平均 +31%，优于 prefetch 15 个点。
- 工程价值：Grace/GH200 类统一内存机器上，比“prefetch KV 到 HBM”更符合真实 decode 访存。可当 vLLM 内存层补丁评估。
- 是否值得读：强烈推荐（有这类硬件才必读）
- Relevance Score：4
- Link：https://arxiv.org/abs/2609.13592

【Title】OpWeave: Flexible Operator Disaggregation for Heterogeneous LLM Serving  
arXiv:2609.14237（2026-09-13）

- 一句话总结：把 PD 拆分再往下拆一层——attention / FFN / MoE 可独立放到异构设备上，并用 cost model 决定拆不拆、怎么拆。
- 核心贡献（2-3点）：
  - 给出 homogeneous / heterogeneous operator-level disaggregation 相对 colocate 的收益上界。
  - regularity-aware planner，hybrid-attention 也能搜。
  - vLLM runtime 执行计划；相对最强可行 baseline，同构最多 1.78×、异构 1.89× 降 serving cost，且保 SLO。
- 工程价值：集群已混 H100/B200/便宜卡时，比“整段 prefill/decode 拆开”更贴近真实异构利用率。Jia 组系统文，实现路径清楚。
- 是否值得读：强烈推荐
- Relevance Score：5
- Link：https://arxiv.org/abs/2609.14237

【Title】Flattening Every Memory Peak in Long-Context Mixture-of-Experts Training  
arXiv:2609.14306（2026-09-13）

- 一句话总结：长上下文 MoE 训练不是压平均显存，是同时压死 4 个峰值：dispatch、vocab proj、checkpoint、optimizer。
- 核心贡献（2-3点）：
  - PipelinedLLEP 限源 token 进 dispatch chunk；Ring-DTP 对 vocab 做环形分片 + online LSE；SCO 把 checkpoint 长寿命张量放到 CPU；OffloadStreamAdamW 把 CPU Adam 做成 bucket pipeline。
  - 只改顺序/粒度，梯度精确。分项：dispatch peak -59.3%，vocab peak -86.6%，offload optimizer 2.05×。
  - 120B–667B MoE，1M context，相对调过的 FSDP2：可达 8–32× 上下文、最高 10.4× 吞吐。
- 工程价值：直接服务长上下文 MoE 预训练/续训。FSDP2 在 128k+ 撞墙时值得对照实现。
- 是否值得读：强烈推荐（做训练 infra）
- Relevance Score：5
- Link：https://arxiv.org/abs/2609.14306

arXiv:2609.11744（2026-09-10）

- 一句话总结：把“磁盘 prefix cache 何时比重算更快”测清楚，再做成 scheduler-aware 预取的 vLLM connector。
- 核心贡献（2-3点）：

【Title】T1: Terminal Agent Reinforcement Learning for Long-Horizon Tasks  
arXiv:2609.11042（2026-09-10）

- 一句话总结：122B MoE 在真实 shell 里跑 300+ tool-call，用可执行 verifier 做 RL，Terminal-Bench 2.1 从 43.8% 拉到 64.0%。
- 核心贡献（2-3点）：
  - 工程配方完整：critic warm-up、按通过 verifier 数的 dense process reward、TITO（按采样 token id 训 + turn 边界 drift repair）、MoE routing replay。
  - 训练语料与 Terminal-Bench 隔离，减少刷榜。
  - TITO+R3 把 train–infer logprob gap 从 0.021 压到 0.013，loss 区 token drift 为 0。RL 贡献约 14.6pt，SFT 仅 5.6pt。
- 工程价值：长程 agent RL 的稳定性问题（token drift、MoE routing 不一致）写得很落地，比“又一个 agent framework”有用。
- 是否值得读：强烈推荐
- Relevance Score：5
- Link：https://arxiv.org/abs/2609.11042

## 今日最值得读 Top 3

1. **OpWeave** — 异构 serving 从 PD 拆分进入 operator 拆分，有 cost model + planner + vLLM 实现，直接对应混部集群的钱。  
2. **AgentKV** — agent 流量已不是 chatbot，KV eviction 假设错了；有 SGLang 路径和吞吐数字。  
3. **Flattening Every Memory Peak** — 长上下文 MoE 训练的真实 blocker 是 4 个峰值而不是平均显存；1M ctx、百 B–六百 B 量级，infra 团队该对表。

（若你只做 agent 产品：用 T1 替换第 3。）

## 今日趋势观察

- **Inference / KV 仍是主航道**：eviction、offload、HBM+host 并发、NVMe prefix cache 同时出现；重点从“压缩算法”转到 **serving 路径 + 调度时机**。
- **Agent 与 inference 合流**：AgentKV、T1 都把长轨迹 KV/token-drift/MoE routing 当一等系统问题，而不是 prompt 工程。
- **训练侧 MoE + 长上下文** 重新抬头（Flattening peaks），和 serving 侧 ODS（OpWeave）形成对称：训练压峰值，推理拆算子。
- Alignment 本窗口偏安全分段，工程增量弱于系统和 agent RL。

## 值得跟进的潜在方向

1. **Phase-aware / intent-aware KV**（AgentKV，此前还有 IntentKV）：agent 的 eviction 不应再复用 chatbot recency。下一步是和 speculative decoding、prefix cache 组合。  
2. **Operator-level disaggregation**：PD 拆分之后的下一层；异构卡 + hybrid attention / MoE 是自然战场。  
3. **Train–infer 一致性作为一等约束**：T1 的 TITO + routing replay，以及 RL rollout 上的 speculative draft co-training（稍早的 2609.07108）。长程 RL 不先修这条，吞吐优化会被 off-policy 噪声吃掉。  
4. **峰值显存调度而非平均显存**：MoE 长上下文训练和 decode KV 分层其实是同一套“哪个峰值先爆”的问题。
