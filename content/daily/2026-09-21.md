【Title】ASPIRE: Asynchronous Batched Self-Speculative Decoding for Long-Context LLM Inference  
- 一句话总结：把 self-speculative 从「整 batch 同步 draft/verify」改成单步 mixed forward + 每请求独立何时 verify。  
- 核心贡献（2-3点）：  
  1. unified mixed forward：同一 batched forward 里 draft 请求和 verify 请求共存。  
  2. 在线 scheduler：用 per-request acceptance 估计 + batch cost model 决定各自 verify 时机。  
  3. intra-draft 单层 full attention refresh，减轻稀疏 draft 的 stale context。  
- 工程价值：直接打 long-context decode 的 memory-bound attention；相对 AR **1.70–4.58×** decode throughput，相对最强 self-spec baseline 平均再快约 **27%**。作者承认与 chunked prefill / 通用 continuous batching 的集成还是 future work。代码承诺 acceptance 后放。  
- 是否值得读：强烈推荐  
- Relevance Score：5  
- Link：https://arxiv.org/abs/2609.17943  

【Title】D-Quant: Driftable Entropy Coding for KV Cache Quantization  
- 一句话总结：用 entropy coding 吃 KV 非均匀分布，再用 drift 把变长码塞进固定 bit 容器，保证 attention kernel 能规则访存。  
- 核心贡献：  
  1. 解耦「量化档位数」和「存储 bit 宽」，K/V 可配不同 budget（文中约 2.68/1.84 bit）。  
  2. 旋转+归一化后近似正态，概率模型直接用标准正态，**无需校准集**。  
  3. 报 **~2.26 bit/element** 接近 BF16；KV 内存最高约 **7×**，decode throughput 约 **3.5×**。  
- 工程价值：方向对（变长压缩 vs 并行 kernel），但落地取决于是否有 fused dequant kernel、是否能塞进 vLLM/SGLang paged layout。Tencent 出品，未见公开实现。  
- 是否值得读：强烈推荐（量化/serving 内核同学）  
- Relevance Score：5  
- Link：https://arxiv.org/abs/2609.19880  

【Title】On-Demand Attention: Language Models Know When to Recall  
- 一句话总结：只训一个轻量 recall head，用当前 decode state 决定这一步要不要打 global attention；KV 全留着，随时可召回。  
- 核心贡献：  
  1. 预训练权重不动，只训 recall head。  
  2. vLLM 里做 GPU-side conditional execution。  
  3. RULER-16K：local 19.23 → ODA 81.17（full 81.94），约 41.6% step 走 full；128K 控制实验约 **1.98×** 单请求 decode。  
- 工程价值：比「永远 sparse」更像可上线的 hybrid attention 控制面；质量是 trade-off 不是 lossless verify。适合长上下文 agent/推理。  
- 是否值得读：强烈推荐  
- Relevance Score：5  
- Link：https://arxiv.org/abs/2609.20734  

【Title】PipeSwift: Revisiting Pipeline Parallelism for Large-Scale Completion-Oriented Agentic LLM Serving  
- 一句话总结：Agent 优化目标应从 TTFT/吞吐改成 **Job Completion Time**；PP 在 prefill–decode 平衡上反而更适合 completion-oriented 工作流。  
- 核心贡献：  
  1. 调度策略空间里 JCT 可差 **1.40×**，纯 prefill-first 不是最优。  
  2. JCT-aware scheduler + pipeline 内 MTP。  
  3. 64×H800、两个 360B+ MoE、真实 coding/web-search replay：相对 SGLang wide-EP **1.45×** JCT，相对 vLLM PP2 **2.33×**，相对开源 PD-disagg SOTA **1.54×**。  
- 工程价值：直接打「大 MoE + agent 长轨迹」集群调度；和「warm prefix 下 PP 有气泡」的常识对着干，读的时候要对齐 workload（cold vs warm turn）。声称开源 runtime。  
- 是否值得读：强烈推荐（infra）  
- Relevance Score：5  
- Link：https://arxiv.org/abs/2609.16491  

【Title】AgentKV: Phase-Aware KV Eviction for Agentic LLMs  
- 一句话总结：Agent 的 think/act/tool 相位占用不同 query 子空间，用「最近 token」打分会系统性丢掉下一相位还要用的 KV。  
- 核心贡献：  
  1. 每相位维护小 query buffer，对并集打分。  
  2. 接到多轮 persistent serving：跨 turn 带压缩 KV + 在线 compact page。  
  3. 相对 R-KV / Tri-attention 任务分平均 **+5.5 / +5.3**；相对 full-KV SGLang 输出吞吐最高 **1.80×**。有代码链接。  
- 工程价值：这是少数把 eviction 假设按 agent 相位拆开的工作；可直接对比你们现在的 R-KV/H2O/SnapKV 策略。  
- 是否值得读：强烈推荐（agent serving）  
- Relevance Score：5  
- Link：https://arxiv.org/abs/2609.14872  

【Title】Ask the Tool, Don't Guess: Agent Tool Calls Hold Their Progress  
- 一句话总结：tool 等待期间 KV 占着 HBM，系统在猜 tool 多久结束；让 tool **运行中上报进度** 比任何先验估计都准。  
- 核心贡献：  
  1. 四个公开 agent corpus：多数 tool 时间里其实有可读进度（剩余比例 / 即将结束）。  
  2. 接到生产引擎几个 hint：相对 LRU，tool 返回后 p90 TTFT 约 **-20.7%**（HBM）/ **-20.8%**（HBM+DRAM），接近 oracle。  
- 工程价值：协议层改动小、收益清楚；适合 vLLM/SGLang + tool runtime 的产品化。不是模型论文，是 serving 控制面论文。  
- 是否值得读：可选（做 agent 网关/调度必读）  
- Relevance Score：4  
- Link：https://arxiv.org/abs/2609.18849  

【Title】Fathom: Per-Query Read Depth for Sparse Decoding over Offloaded KV Caches  
- 一句话总结：offload 到 host 的 4-bit K 按 bit-plane 存，每个 query 按 channel 重要性决定读几层 bit，而不是扫固定宽度。  
- 核心贡献：  
  1. reverse water-filling 分配 per-query bit budget。  
  2. 1M token、Qwen3-8B：相对 Double Sparsity/Loki/SparQ r=32 的 136-bit scan，GPU decode step **1.67×**。  
  3. 强调：index 已在 GPU 时它并不更快——场景是 **host 侧 KV + 多 session agent**。  
- 工程价值：对「百万 token agent session、KV 在 CPU」这条路径很具体；和 GPU-resident sparse attention 不是同一产品。  
- 是否值得读：可选  
- Relevance Score：4  
- Link：https://arxiv.org/abs/2609.17652  

【Title】PrefixBench-H100: Characterizing Prefix Reuse and TTFT on H100  
- 一句话总结：不发明新算法，把 vLLM / TensorRT-LLM 的 prefix reuse 在 H100 上测出「什么时候真有用」。  
- 核心贡献：  
  1. 控制 prefix 长、suffix 多样性、到达过程、并发、输出长、cache 配置。  
  2. 结论：reuse 有效区间清楚；cache 效果对并发/输出长不敏感；runtime 差异主要在 **调度层** 而不是 cache 本身。  
- 工程价值：排障/容量规划比再读一篇 eviction 论文更有用。可复现 benchmark。  
- 是否值得读：可选（serving 性能同学）  
- Relevance Score：3  
- Link：https://arxiv.org/abs/2609.19657  

【Title】Block Parallelism For Efficient Distributed Long-Context Diffusion Language Model Training  
- 一句话总结：给 diffusion LM 加一维 block parallelism（+ context-sharded 变体），专打超长 context 训练。  
- 核心贡献：  
  1. CSBP：corrupted K/V 本地，clean sequence 分片，避免复制 clean prefix。  
  2. 16×H200 @256K：SFT **1.18–1.45×**，AR→BDLM 转换 **1.27–1.33×**；512K full-model **1.61×**。  
  3. 8×H100 上 DFlash2 spec-decoder 训练：512K **2.48×**，1M **7.59×**。有代码。  
- 工程价值：若你在训/转 diffusion LM 或超长 context SFT，这是本窗口里最硬的并行策略文；对标准 AR serving 间接。  
- 是否值得读：可选（训练 infra）  
- Relevance Score：4  
- Link：https://arxiv.org/abs/2609.19242

### 1. 今日最值得读 Top 3

1. **ASPIRE** — 解决的是真实 serving 痛点：batch 内请求的最优 draft 长度根本不同步。数字硬，且指出了和 continuous batching 的缝，读完能判断能不能进引擎。  
2. **PipeSwift** — 把优化目标从 token 指标改成 agent JCT，并用 360B+ MoE / 64 GPU / 真实轨迹说话。这会直接影响「PD-disagg vs PP vs EP」选型。  
3. **D-Quant 或 ODA（并列第三，看岗位）** — 做 KV/kernel 读 D-Quant；做长上下文策略读 ODA（vLLM 条件执行 + 质量几乎回到 full attention）。

### 2. 今日趋势观察

Inference / KV 明显过密：self-spec、entropy KV quant、on-demand / sparse attention、offload bit-plane scan、prefix reuse 实测，全部围着 **decode 带宽和长上下文 KV**。  
第二密的是 **agent serving 系统**：相位感知 eviction、tool 进度信号、JCT 调度、CPU–LLM 交织，不再是 prompt 工程。  
分布式训练本窗口只有 diffusion-LM block parallel 较硬，经典 Megatron 增量少。

### 3. 值得跟进的潜在方向

- **非同步 speculation + continuous batching**：ASPIRE 自己把这块标成未完成，谁先接到 vLLM/SGLang 谁有产品差。  
- **Agent 相位 / tool 生命周期进入 KV 与调度**：AgentKV + Ask the Tool 说明「chatbot 假设」（recency、固定 tool latency）已经系统性错了。  
- **Entropy-coded 但固定 stride 的 KV**：D-Quant 的 drift 若能做成可融合 kernel，会比再砍 0.5 bit 的标量量化更有系统意义。  
- **优化目标从 TTFT/TPS 切到 JCT / 任务分**：PipeSwift 和 AgentKV 都在用任务级指标，集群 benchmark 会跟着变。
