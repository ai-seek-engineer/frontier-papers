### 【LLM Agents（有实际落地或系统设计）】
**【Title】**  
AtomMem: Building Simple and Effective Memory System for LLM Agents via Atomic Facts

- **一句话总结**：提出基于原子事实（atomic facts）的长期记忆系统，通过 Fact Executor 提取高价值事实 + 分层事件/时序结构 + 关联图检索，解决多轮/多会话代理的上下文积累问题。
- **核心贡献（2-3点）**：
  1. 原子事实提取与分层组织，实现高效、稳定内存演化（避免粗粒度/不稳定更新）。
  2. 关联记忆图支持碎片化回忆，适用于个性化长期代理。
  3. 在 LoCoMo 等基准上 SOTA，强调可扩展与经济性。
- **工程价值（重点分析：是否能用于推理/infra优化）**：高。直接提升代理长期推理效率（减少重复上下文膨胀），内存管理优化对 inference 成本和多会话部署有实际落地价值；可与现有 KV cache 系统结合，降低 token 消耗。
- **是否值得读**：**强烈推荐**（简单有效，易集成）。
- **Relevance Score**：5
- **Link**：https://arxiv.org/abs/2606.19847

**【Title】**  
Beyond Global Replanning: Hierarchical Recovery for Cross-Device Agent Systems (H-RePlan)

- **一句话总结**：针对跨设备代理的故障恢复，引入分层重规划（设备本地策略恢复 + 全局编排），配以 HeraBench 故障注入基准，支持统一 API/CLI/GUI 执行。
- **核心贡献（2-3点）**：
  1. 设备级策略抽象与跨层故障建模，区分本地可修复 vs. 全局重规划。
  2. 新基准 HeraBench 测试跨 Linux/Android 工作流。
  3. 显著提升完成率、指令遵循和完美通过率，同时降低 token 成本。
- **工程价值（重点分析：是否能用于推理/infra优化）**：高。真实多设备/异构环境下的鲁棒性优化，直接适用于生产级代理系统；分层设计减少不必要全局推理开销，利于 infra 可靠性。
- **是否值得读**：**强烈推荐**（系统性强，有基准支撑）。
- **Relevance Score**：5
- **Link**：https://arxiv.org/abs/2606.20487

**【Title】**  
LedgerAgent: Structured State for Policy-Adherent Tool-Calling Agents

- **一句话总结**：为客服等领域工具调用代理引入独立“账本”（ledger）维护任务状态，并在 prompt 中渲染 + 执行前策略检查，解决隐式状态导致的 stale info 和策略违规。
- **核心贡献（2-3点）**：
  1. 推理时结构化状态管理 + 策略约束预检查。
  2. 多领域、多模型实验（open/closed-weight），pass@k 提升，尤其在严格一致性指标下。
  3. 缓解 prompt 重建状态的常见失败模式。
- **工程价值（重点分析：是否能用于推理/infra优化）**：高。提升工具调用代理可靠性与合规性，减少 hallucinated 决策；结构化状态对长会话 inference 内存/一致性优化有借鉴价值，易集成到现有框架。
- **是否值得读**：**强烈推荐**（实用，policy-adherent 场景落地强）。
- **Relevance Score**：4.5
- **Link**：https://arxiv.org/abs/2606.20529
