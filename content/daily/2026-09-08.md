## 1. Model Inference / 推理优化

【Title】BeaconKV: Key-Value Cache Compression Guided by Beacon Queries for Efficient Large Reasoning Model Inference  
- 一句话总结：针对长 CoT 推理中“回头看早期计划”的注意力模式，用少量 beacon query 代替全量 query 历史来压缩 KV。  
- 核心贡献：  
  1. 指出 LRM 里存在 Thought Revisiting Tokens，近期 query 不能当未来注意力的可靠代理。  
  2. 用 query embedding 聚类的 compact beacon 预测会被 revisit 的 KV。  
  3. 训练无关；报告最高约 5.8× 显存下降、4.3×+ throughput，精度接近 full cache。  
- 工程价值：直接可插推理栈（长推理 / 长 decode）。比通用 SnapKV 类更贴 reasoning 负载。落地成本低（training-free）。  
- 是否值得读：强烈推荐  
- Relevance Score：5  
- Link：https://arxiv.org/abs/2609.04971

【Title】Same Request, Different Answer: Quantization Amplifies Cache-Induced Divergence in LLM Serving  
- 一句话总结：prefix cache 不是透明优化——量化后同一请求轨迹会系统性分叉，4-bit 比 16-bit 更严重。  
- 核心贡献：  
  1. 多轮 tool-use 上，开 cache 改变轨迹：16-bit 36%、4-bit 75%。  
  2. 关 cache 时 800 episode 全 bit-identical，排除采样噪声。  
  3. 定位到 server-level prompt-cache 配置 + cache vs recompute 路径不一致。  
- 工程价值：对 serving 确定性、评测复现、agent 轨迹稳定性是硬问题。任何开 prefix cache + 量化的线上系统都该看。  
- 是否值得读：强烈推荐  
- Relevance Score：5  
- Link：https://arxiv.org/abs/2609.04748

## 2. AI Infra / 分布式 / 系统优化

【Title】AInfer-PD: Communication-Safe In-Place Prefill-Decode Multiplexing for Distributed MoE Rollouts  
- 一句话总结：在分布式 MoE RL rollout 上做 in-place P/D 复用，并修集体通信交叉导致的不安全。  
- 核心贡献：  
  1. 指出 P/D 交叉 collective + DeepEP 共享可变协议状态会出错。  
  2. 给 communication-safe 的 in-place multiplexing。  
  3. 相对关 multiplexing / SGLang，单节点完成时间降 7–33%，两节点最高约 35%。  
- 工程价值：RL 训练墙钟几乎被 rollout 吃掉；这是直接能进 MoE RL infra 的改法。  
- 是否值得读：强烈推荐  
- Relevance Score：5  
- Link：https://arxiv.org/abs/2609.00993

【Title】Quality Recovery for Quantized KV Caches via Low-Rank Attention Adaptation  
- 一句话总结：量化器固定，只训低秩 Q/K/V 投影适配，在 packed incremental cache 上把质量缺口捞回来。  
- 核心贡献：  
  1. 4-bit 上 TinyLlama / Gemma 分别回收约 54% / 76% PPL gap。  
  2. 强调 PPL 恢复 ≠ 长上下文 retrieval 恢复（2-bit 尤其明显）。  
- 工程价值：部署侧可叠加现有 KIVI/NF4，不必换量化格式。但规模偏小、偏研究，infra 优先级低于 AInfer-PD。  
- 是否值得读：可选  
- Relevance Score：3  
- Link：https://arxiv.org/abs/2609.04263

## 3. LLM Agents（系统设计）

【Title】Fresh Memory, Stale Plans: Dependency-Scoped Validation for Distributed LLM-Agent Memory  
- 一句话总结：共享内存“新鲜”不等于计划仍有效；用依赖范围校验挡住 stale-plan 执行。  
- 核心贡献：  
  1. 形式化 stale-plan execution。  
  2. PlanFence：计划引用具体 public records，执行前只校验会影响外部动作的记录。  
  3. 30 个受控 live workflow：freshness-only 全踩旧计划，PlanFence 零无效动作。  
- 工程价值：多 agent + 共享 store 的正确性协议，比再堆一个 planner 有用。注意这是安全/系统成本结果，不是任务准确率 paper。  
- 是否值得读：强烈推荐  
- Relevance Score：4  
- Link：https://arxiv.org/abs/2609.03340

【Title】Explore More, Drift Less: Outcome-Only Reinforcement Learning Can Suffice for Long-Horizon Interactive Agents  
- 一句话总结：小模型上 outcome-only RL 的天花板主要来自探索不足 + policy drift；用 CANOPY 协议就能把能力内化进权重。  
- 核心贡献：  
  1. 同任务放大探索、全程 on-policy + KL、只更新 agent action token。  
  2. Qwen3-14B 仅环境交互上 AppWorld 登顶；SWE-bench Verified +16.6。  
  3. 承诺开训练栈。  
- 工程价值：agent 训练配方极简、可复现；对“必须过程奖励/复杂 scaffolding”是反证。  
- 是否值得读：强烈推荐  
- Relevance Score：5  
- Link：https://arxiv.org/abs/2609.01245

## 4. SFT / Alignment / RLHF

【Title】From Rollouts to Recipes: Self-Contained Post-Training for LLMs  
- 一句话总结：用 rollout 对错和置信度给每个样本路由不同优化器（GRPO / on-policy distill / 正则 / skip）。  
- 核心贡献：  
  1. 无外部教师、无额外采样。  
  2. 均匀 GRPO/OPSD 和固定混合都更差；路由分布随训练变化。  
- 工程价值：降低无效 update、省 rollout 预算。EMNLP’26，方法可直接接到现有 RLVR 管线。  
- 是否值得读：可选  
- Relevance Score：4  
- Link：https://arxiv.org/abs/2609.01422

## 5. Reinforcement Learning

【Title】When Do Larger Batches Help Scale LLM Reinforcement Learning?  
- 一句话总结：大批次只在“吞吐增益 > samples-to-target 惩罚”时缩短墙钟；不调 LR 反而更慢。  
- 核心贡献：  
  1. 把算法样本效率 vs 系统吞吐拆开。  
  2. Adam + √LR 在一定 batch 范围学习曲线近似不变。  
  3. GRPO 上重调 LR 后 time-to-target 最多 -29%；吞吐最高 2.29×。  
- 工程价值：RL 集群排程的决策规则，不是又一个算法变体。  
- 是否值得读：强烈推荐（若你在跑大规模 GRPO/PPO）  
- Relevance Score：4  
- Link：https://arxiv.org/abs/2608.29296

【Title】Random Attention: Rethinking KV Cache Eviction for Efficient Reasoning  
- 一句话总结：推理轨迹上，prompt 保住后，头内随机驱逐 ≈ 最强 scorer，且 vLLM 吞吐更高。  
- 核心贡献：  
  1. 选择信号几乎不贡献；prompt 才是脆弱段。  
  2. 文本复述 + 多头冗余保护 reasoning trace。  
  3. 相对最强 evictor +32–43% throughput。  
- 工程价值：驱逐逻辑可大幅简化（少算 attention score）。对推理 serving 是反直觉但可落地的结论。  
- 是否值得读：可选（和 BeaconKV 对照着读更有价值）  
- Relevance Score：4  
- Link：https://arxiv.org/abs/2609.03430

## 额外输出

### 1. 今日最值得读 Top 3
1. **Same Request, Different Answer** — 线上 prefix cache + 量化的确定性坑，评测和 agent 轨迹都会被静默污染。  
2. **BeaconKV** — LRM 长 decode 的 KV 瓶颈是当前 serving 主痛点，方法 training-free、数字完整。  
3. **AInfer-PD** — 直接打 RL/MoE rollout 墙钟，属于少数“能进生产训练栈”的系统文。

（若做 agent 训练：用 CANOPY 替换第 3 名。）

### 2. 今日趋势观察
- **Inference / KV cache 明显过密**：驱逐、量化、reasoning-aware 压缩、cache 数值非确定性同时出现。战场从“再发明一个 scorer”转到 **时间聚合规则、prompt 保护、确定性、推理特有 revisit 模式**。  
- **Agent 从脚手架转向协议 + 训练配方**：PlanFence（一致性协议）、CANOPY（极简 outcome RL）。  
- **Infra 焦点在 RL rollout 的 P/D 与 MoE 通信**，纯大模型预训练并行文较少。

### 3. 值得跟进的潜在方向
1. **量化 × prefix cache 的可复现 serving**：需要 cache 路径与 recompute 路径的数值契约，而不是只报吞吐。  
2. **Reasoning-trace 感知的 KV 管理**：BeaconKV vs Random Attention 结论部分冲突（要不要智能选 token），值得在同一 vLLM 栈上打对照。  
3. **Agent 共享状态的依赖校验**：比再加 memory 模块更接近分布式系统问题。  
4. **RL 训练的 batch/LR/吞吐联合调度**：大批次不是免费加速。
