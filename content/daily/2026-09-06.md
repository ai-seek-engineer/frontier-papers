### 1. Inference

**【Title】Margins, Not Windows: Training-Free Per-Step Lossy Speculative Decoding (AdaptiveSpec)**  
- 一句话总结：在 EAGLE-3 树上，用每步概率 margin + 动态树形，替代固定严格验收和固定 draft tree。  
- 核心贡献：  
  1. 训练无关的 lossy 验收：draft token 与 target top-1 概率比过阈值即可接受，不依赖 draft 长度。  
  2. 每步按 draft 置信度 + 滚动接受率调树深/宽/节点数，draft token 预算可变。  
  3. 接到 **SGLang**；相对 EAGLE-3 吞吐最高 +56%，GSM8K/MATH-500/HumanEval 保真约 93%～无损。  
- 工程价值：可直接叠在现有投机解码栈上，不重训 draft。适合低并发、长 CoT；大 batch 是否仍赚带宽要自己压测。  
- 是否值得读：**强烈推荐**  
- Relevance Score：5  
- Link：https://arxiv.org/abs/2609.02897  

**【Title】Random Attention: Rethinking KV Cache Eviction for Efficient Reasoning**  
- 一句话总结：推理长 CoT 场景里，复杂 importance score 几乎没用；保住 prompt + 每 head 随机丢掉 reasoning KV 就够。  
- 核心贡献：  
  1. 4 模型 × 6 reasoning 任务，随机驱逐 ≈ 最强 evictor。  
  2. 机制：prompt 脆弱；trace 有文本复述 + 跨 head 冗余。  
  3. vLLM 部署吞吐比“打分驱逐”高 **32–43%**（省 scoring 开销）。有代码。  
- 工程价值：立刻可砍 eviction 复杂度。只对 **reasoning decode** 成立，RAG/多轮对话不要照搬。  
- 是否值得读：**强烈推荐**  
- Relevance Score：5  
- Link：https://arxiv.org/abs/2609.03430

### 2. AI Infra / 分布式训练

**【Title】BASP: Communication-Efficient Batch-Aware Sequence Parallelism for LLM Training**  
- 一句话总结：SP 不要对所有 batch 用同一套切分；按 micro-batch 把 GPU 划成更小的 SP 组，缩小 all-to-all。  
- 核心贡献：  
  1. 指出现有 SP 对 batch 结构不敏感，通信过度全局化。  
  2. 按 micro-batch 划分 disjoint SP group，通信局部化。  
  3. A1[O00 上 Llama/Qwen 端到端 **1.17–1.31×**，精度与显存不变。HPEC 2026。  
- 工程价值：长上下文训练里 SP 通信是真瓶颈；改 group 拓扑比改算法便宜。幅度不大，但是可落地的调度层改动。  
- 是否值得读：**可选**  
- Relevance Score：4  
- Link：https://arxiv.org/abs/2609.03151  

**【Title】Characterizing the Scalability and Performance of Large-Scale AI Training Under Multi-Tenancy**  
- 一句话总结：到 2400 GPU、多集群（Alps/LUMI/JUPITER/NVL72 等），把并行策略 × 互连 × 多租户干扰测清楚。  
- 核心贡献：  
  1. 五套并行策略 × 多种 scale-up/out/rack 配置。  
  2. 真实噪声模型刻画 job 间干扰。  
  3. 面向 SC26 的系统测量，不是新算法。  
- 工程价值：排障/容量规划/选并行组合的参考，本身不能直接加速一次训练。  
- 是否值得读：**可选**  
- Relevance Score：3  
- Link：https://arxiv.org/abs/2609.00817

### 3. LLM Agents（偏系统设计）

**【Title】Where Does Harness-Optimization Value Live? (HARNESSEVO)**  
- 一句话总结：冻住 7B，只进化 harness 时，价值几乎全在 reflection/control 槽，平均拆预算会把搜索饿死。  
- 核心贡献：  
  1. harness 拆成 role / strategy / format / control 四槽 + leave-one-in/out。  
  2. ALFWorld：整体成功率几乎不动（0.657 vs 0.642），但 control 槽单独 +0.119。  
  3. 64 rollout 均分到 4 槽 → 每槽 16 次低于搜索下限，全部冻在空种子；预算集中到 control → 0.761。WebShop 上全槽无增益。  
- 工程价值：别再对 prompt 做“均匀进化”。先做 credit assignment，再砸 rollout。Agent 平台的预算调度直接可用。  
- 是否值得读：**强烈推荐**（做 agent infra 的人）  
- Relevance Score：4  
- Link：https://arxiv.org/abs/2609.02889  

**【Title】R²Adapter: A Routing and Rewriting Adapter for Efficient Hybrid RAG**  
- 一句话总结：轻量路由+改写，只把真正需要多跳的 query 打到 Graph-RAG，图检索用量最多降 59%，准确率基本持平。  
- 核心贡献：插件式，不绑死底层 LLM；不确定 query 改写以暴露多跳结构。  
- 工程价值：混合 RAG 成本控制，不是新检索算法。线上可当 router。  
- 是否值得读：**可选**  
- Relevance Score：3  
- Link：https://arxiv.org/abs/2609.02894

### 4. SFT / Alignment / RLHF

**【Title】From Production Traffic to Post-Training: Building a Self-Hosted LLM That Covers the Corporate Request Mix**  
- 一句话总结：用线上错误分析驱动 post-training，把 200+ 内部应用压到一个自托管模型，吃掉约 50% 平台流量（1.16 亿请求/月）。  
- 核心贡献：  
  1. 三条轴：instruction following / function-calling / 内部任务分布。  
  2. 多 expert reward 对应语义崩、over-calling、verbosity hacking，各自修。  
  3. 非 reasoning 模式在内部 Arena 超过约 7× 参数量的基线（69.6 vs 65.8）。  
- 工程价值：企业模型收敛路径：流量 → 失败模式 → 分 reward → 减 serving 碎片。方法可复用，代码大概率没有。  
- 是否值得读：**强烈推荐**（做内部 LLM 平台）  
- Relevance Score：4  
- Link：https://arxiv.org/abs/2609.01572

### 5. Reinforcement Learning

**【Title】Tail-Likelihood Reinforcement Learning (TailRL)**  
- 一句话总结：不优化平均奖励，优化“超过随机阈值”的 log 概率，把梯度压到稀有高分 rollout 上。  
- 核心贡献：只改 advantage，兼容现有 RL 管线；解释成 Best-of-k 梯度混合；GUI/code/导航上更吃 inference-time sampling。  
- 工程价值：对 Best-of-N / 测试时采样有效的策略训练有用；不是系统论文，但改动面小。  
- 是否值得读：**可选**  
- Relevance Score：3  
- Link：https://arxiv.org/abs/2609.02987

## 今日最值得读 Top 3

1. **Random Attention** — 直接打掉一类 KV eviction 论文的前提；vLLM 吞吐数字清楚，实现成本极低。先读这个再决定还要不要上 SnapKV/H2O 类打分。  
2. **AdaptiveSpec** — 投机解码从“固定树 + 严格 match”改成逐步自适应，且进了 SGLang，是本周最接近可上线的推理优化。  
3. **HARNESSEVO** 或 **Production Traffic → Post-Training**（看你岗位）：前者改 agent 进化预算分配，后者改企业对齐数据闭环。两者都是“别平均撒资源”。

## 今日趋势观察

- **推理侧仍最密**：投机解码从静态树走向 per-step 控制；KV 驱逐从“打分”转向“结构冗余 + 保 prompt”。Reasoning 长 decode 把 KV 重新变成一等公民。  
- **Agent 论文开始谈预算与信用分配**，不再只堆工具调用。  
- **训练通信** 有小幅 SP 优化，但没有新的万卡级算法突破；多租户测量论文增多。  
- Alignment 有一篇真正的生产闭环，比实验室 RLHF 更稀缺。

## 值得跟进的潜在方向

1. **Reasoning-specific KV 策略**：prompt 保真 + trace 随机/稀疏；和投机解码 lookahead prefetch（OasisKV 一类，稍早）可能正交可叠加。  
2. **投机解码的双自适应**：验收规则 × 树形 × 服务引擎调度（batch 变大后收益如何掉）。  
3. **Harness credit assignment**：agent 优化对象从“整段 prompt”变成可计量的 control 槽。  
4. **跨模型 KV 翻译**（8/31 的 Universal Context-Reuse Layer，略超 48h）：路由/级联 serving 的 prefill 成本可能被改写，值得盯下一波实现。
