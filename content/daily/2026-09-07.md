【Title】Unlocking Lossless Speedups in LLMs via Discrete Diffusion (Uno)

- 一句话总结：在保持原 AR 分布的前提下，用轻量 diffusion 头并行出多 token，做成不需要独立 draft 模型的无损加速。
- 核心贡献（2-3点）：
  - AR 权重继续 NTP；另训一组 diffusion 权重做并行采样，蒸馏开销声称可嵌进现有训练。
  - Ψ-Spec sampler：固定上下文长度下可无损加速，也可做 test-time scaling；不另起 draft model。
  - 8B Uno 吞吐高于主流 speculative decoding；相对基座最高约 3×，大批次仍有效；有代码和 checkpoint。
- 工程价值：直接打 serving decode 路径。比 EAGLE/MTP 更省一套 draft 生命周期；关键要验证 vLLM/SGLang 接入成本和 acceptance 在真实 batch 下是否掉。
- 是否值得读：强烈推荐
- Relevance Score：5
- Link：https://arxiv.org/abs/2609.04010

【Title】Hardware-Aware FP4 FlashAttention-4

- 一句话总结：Blackwell FP4 Tensor Core 不会自动让 Attention 变快；softmax 和片上依赖才是瓶颈，论文给出推理/训练两条可落地路径。
- 核心贡献（2-3点）：
  - Direct-P：非因果推理把 score 直接映到 FP4 概率，GB200 上 forward 最高 2.13× BF16。
  - 因果路径把前向量化直接喂 backward，8B 单卡更新最高 1.14×。
  - 明确负结果：匹配的分布式训练里 MXFP4 概率/value 轨迹会发散，需留 FP8。
- 工程价值：对正在上 Blackwell 的团队是必看 kernel 级材料。负结果比正结果更值钱：别盲目把训练 Attention 压到 MXFP4。
- 是否值得读：强烈推荐
- Relevance Score：5
- Link：https://arxiv.org/abs/2609.04105

【Title】Every Kernel Is a Join: Automatic Multi-GPU Parallelism in Einsummable

- 一句话总结：把每个算子当成 join+agg，自动搜索切分并合成通信，不写 sharding / collective。
- 核心贡献（2-3点）：
  - 用 join-agg spec 暴露可分解方式，按通信代价全局选 plan，能搜到 mesh auto-parallel 菜单外的方案。
  - 通信不是 NCCL canned collective，而是 compile-time 特化的 exchange program。
  - 8×A100 上 LLaMA block：几何平均 8.97ms，对比手写 PyTorch 13.80ms、vLLM 15.90ms。
- 工程价值：思路可吃，落地要谨慎。原型对单机多卡有意义；生产还要看和 Megatron/vLLM paged attention 的集成深度。数字是 block 级，不是端到端 serving。
- 是否值得读：强烈推荐
- Relevance Score：4
- Link：https://arxiv.org/abs/2609.03905

【Title】BASP: Batch-Aware Sequence Parallelism for LLM Training

- 一句话总结：现有 SP 对 batch 一刀切；按 micro-batch 切 SP group，缩小 all-to-all 域。
- 核心贡献（2-3点）：
  - 指出 USP/Ring 等对 batch size 不敏感，小 batch 时通信组过大。
  - 按 micro-batch 划 disjoint SP group，通信局部化。
  - Llama/Qwen + A100：端到端 1.17–1.31×，精度和显存不变。
- 工程价值：改动面小，适合长上下文训练栈。加速幅度一般，但实现成本低，值得对一下自己的 SP 配置。
- 是否值得读：可选
- Relevance Score：3
- Link：https://arxiv.org/abs/2609.03151

【Title】Latency-Aware Orchestration for Multi-Agent LLM Workflows on Heterogeneous GPUs

- 一句话总结：把 multi-agent DAG 的逻辑依赖映射成异构 GPU 上的模型加载/放置/融合调度。
- 核心贡献（2-3点）：
  - Predictor 估设备激活延迟、峰值显存、load 成本，沿 DAG 传播就绪时间。
  - Constructor 生成可融合与生命周期方案；Scheduler 联合选放置和顺序。
  - 三类 workflow：makespan 最高降 36.8%，p95 降 25.9%，每 session 最高省 24.63 GPU-s。
- 工程价值：这才是 agent 的系统论文，不是 prompt 编排。对多模型共存、冷启动、异构卡池有直接参考。缺开源代码会削弱可复现。
- 是否值得读：强烈推荐
- Relevance Score：4
- Link：https://arxiv.org/abs/2609.03335

【Title】Headroom-Drift Replay: Principled Replay Control in GRPO

- 一句话总结：Agentic RL 的墙钟被 fresh rollout 吃掉；只改 replay 选择，不改训练器，就能省环境交互。
- 核心贡献（2-3点）：
  - Headroom 排剩余学习价值；Drift 卡与当前策略的兼容性。
  - on-policy 流不动，无额外生成器。
  - 数学 / 多模态 / Agentic Search 上打赢 naive replay，质量对齐更重的 replay 管线，Search 场景墙钟明显下降。
- 工程价值：GRPO/agent RL 训练栈可直接插一层 buffer policy。比再造一套 off-policy 算法便宜。
- 是否值得读：强烈推荐
- Relevance Score：4
- Link：https://arxiv.org/abs/2609.03941

【Title】Tail-Likelihood Reinforcement Learning (TailRL)

- 一句话总结：优化的不是平均奖励，而是“超过随机阈值”的对数概率，让 Best-of-N 在推理时更值钱。
- 核心贡献（2-3点）：
  - 把连续奖励拆成一族尾部成功事件，梯度更偏稀有高分 rollout。
  - 实现上只改 advantage，兼容现有 RL 管线。
  - GUI / code / maze 等任务上，训练时吃到稀有高分样本，推理加采样更有效。
- 工程价值：对 BoN、pass@k、agent 重试预算有直接含义。不是 serving kernel，但是 post-training 目标函数的工程旋钮。
- 是否值得读：可选
- Relevance Score：3
- Link：https://arxiv.org/abs/2609.02987

**1. 今日最值得读 Top 3**

1. **Uno (Discrete Diffusion)**  
   解码加速赛道里少见的“无损 + 无独立 draft + 有权重发布”。如果 acceptance 和 kernel 融合过关，会冲击 EAGLE/MTP 的默认方案。

2. **FP4 FlashAttention-4**  
   Blackwell 落地必读。把“FP4 不等于更快 Attention”说清楚，并给出训练发散的硬边界。

3. **Einsummable 或 Agent GPU Orchestration（并列第三，看岗位）**  
   训练/编译栈看 Einsummable；做 agent 平台看异构 GPU 编排。两者都是系统问题，不是算法小修。

**2. 今日趋势观察**

- Inference 仍是主场：并行解码（diffusion 当 draft）、FP4 Attention、KV eviction 同时出现。
- Infra 从“再写一个 collective”转向自动切分和 batch-aware 通信域。
- Agent 论文开始真正碰调度、加载、异构资源，而不只是 tool-calling prompt。
- RL/Alignment 重心从新算法转向 **rollout 成本**：replay 门控、尾部似然，都在省环境交互。

**3. 值得跟进的潜在方向**

- **AR 分布 + 并行采样头**（Uno 类）：draft 从“另一个模型”变成“同模型轻量子模块”，serving 内存模型会变。
- **量化负结果进训练稳定性合同**：MXFP4 Attention 发散说明推理量化 ≠ 训练量化。
- **Agent serving = 模型生命周期调度**：多 agent 的瓶颈经常是 load/resident/placement，不是 token/s。
- **GRPO replay 作为一等公民**：agentic RL 墙钟优化会比再调 KL 系数更有杠杆。
