## 1. Inference / 推理优化

【Title】ASPIRE: Asynchronous Batched Self-Speculative Decoding for Long-Context LLM Inference  
https://arxiv.org/abs/2609.17943

- 一句话总结：把 batched self-speculative decoding 从“全 batch 同步 draft/verify”改成请求级异步调度。
- 核心贡献：
  - mixed forward：同一 batch 里 draft 请求和 verify 请求共存，不再切全局阶段。
  - 在线 scheduler：用 per-request acceptance rate + batch 代价模型决定何时 verify。
  - intra-draft refresh：draft 时只在指定一层做 full attention，压 draft 上下文过期。
- 工程价值：直接打长上下文 decode 的 memory-bound 点。报告相对自回归 1.70–4.58× decode throughput，相对最强 self-spec 基线平均再快约 27%。可嵌入现有 spec decode 调度器，不必换模型。
- 是否值得读：强烈推荐
- Relevance Score：5
- Link：https://arxiv.org/abs/2609.17943

【Title】D-Quant: Driftable Entropy Coding for KV Cache Quantization  
https://arxiv.org/abs/2609.19880

- 一句话总结：用熵编码压 KV，再用 “drift” 把变长码流拧成定长 bitstream，好进并行 attention kernel。
- 核心贡献：
  - 指出固定 bit-width 量化浪费非均匀分布。
  - entropy coding + drift：保留压缩率，同时保证规则内存布局和并行 dequant。
  - 目标就是能塞进现有 attention kernel，而不是只报压缩比。
- 工程价值：KV 容量/带宽是 serving 第一瓶颈。可变长编码一直卡在 kernel 不规则访问；这篇专门补这块。适合评估是否能接到 vLLM/SGLang paged KV。
- 是否值得读：强烈推荐
- Relevance Score：5
- Link：https://arxiv.org/abs/2609.19880

## 2. AI Infra / 分布式 / 系统

【Title】PipeSwift: Revisiting Pipeline Parallelism for Large-Scale Completion-Oriented Agentic LLM Serving  
https://arxiv.org/abs/2609.16491

- 一句话总结：Agent 工作负载优化目标从 TTFT/TPOT 换成 job completion time，并据此重做 PP + 调度。
- 核心贡献：
  - 实证：chat 的 token SLO 不适合长程 agent；PP 在 JCT 上反而有 prefill–decode 折中优势。
  - JCT-aware 调度 + pipeline 内 multi-token prediction。
  - 64×H800、两个 360B+ MoE、真实 coding/web-search replay。
- 工程价值：相对 SGLang wide-EP 最高 1.45× JCT，相对 vLLM PP2 2.33×，相对开源 PD-disagg SOTA 1.54×。Agent 集群不该继续按 chatbot SLO 配并行。
- 是否值得读：强烈推荐
- Relevance Score：5
- Link：https://arxiv.org/abs/2609.16491

【Title】Block Parallelism For Efficient Distributed Long-Context Diffusion Language Model Training  
https://arxiv.org/abs/2609.19242

- 一句话总结：给 block diffusion LM 加一维并行：每个 corrupted block 一个 rank，再对 clean 序列做 context shard。
- 核心贡献：
  - BP / CSBP：corrupted K/V 与梯度本地化，避免 clean prefix 复制。
  - 16×H200、256K：SFT 吞吐 1.18–1.45×；512K full-model 1.61×。
  - 8×H100 上 DFlash2 spec-decoder 训练：512K 2.48×，1M 7.59×。
- 工程价值：如果你在训长上下文 diffusion/block LM 或 spec decoder，这是可落地的并行维度，不是再叠一层 TP。
- 是否值得读：可选（栈里有 BDLM/超长训才必读）
- Relevance Score：4
- Link：https://arxiv.org/abs/2609.19242

## 3. LLM Agents（系统设计向）

【Title】An Architecture for Long-Horizon Agents: Levels, Ticks and Cascaded Intelligence  
https://arxiv.org/abs/2609.19519

- 一句话总结：用层级摘要、clocked tick、按失败升级模型，撑住跨天/跨周的 agent 会话。
- 核心贡献：
  - 从 7 个长程瓶颈反推架构：level（有界文件摘要下层）、tick（自治动作单元）、cascaded intelligence（review 失败才升模型）。
  - 10 天实验：复现一篇已发表 RL 结果，人每天只介入一次；跨 context reset 不断线。
  - 结论：continual learning 的载体应是 harness 里已有的检查点，而不是权重。
- 工程价值：可直接改 agent harness：分层记忆、固定节拍、贵模型当 fallback。没有吞吐数字，但是生产级长程 agent 的系统设计稿。
- 是否值得读：强烈推荐（做 agent 产品/平台）
- Relevance Score：4
- Link：https://arxiv.org/abs/2609.19519

【Title】UnifiedPlayers: Enhance Tool-Integrated Reasoning in Agentic Reinforcement Learning  
https://arxiv.org/abs/2609.20089

- 一句话总结：把任务生成、带工具执行、可执行 verifier 做成三个互相训练的 Player，用 GRPO 协同。
- 核心贡献：
  - 不再用静态 verifier / 自洽信号，三者一起进化。
  - role-specific reward 对齐共享目标。
  - 2 个 backbone、12 个 reasoning bench：数学至少 +3.5%，通用推理至少 +3.9%。
- 工程价值：给 tool-use agent 的自演进数据管线一个可抄结构。注意协调开销和训练稳定性，不是即插 serving 优化。
- 是否值得读：可选
- Relevance Score：4
- Link：https://arxiv.org/abs/2609.20089

## 4. SFT / Alignment / RLHF

【Title】STRETCH the Boundaries: A Unified Self-Taught Framework for Progressive LLM Evolution  
https://arxiv.org/abs/2609.18642

- 一句话总结：同一套参数里轮换 Scaffolder（造刚好超当前能力的题）和 Learner（RL 解题），避免自改进平台期。
- 核心贡献：
  - Stretch Zone：难度跟着能力走。
  - 双环共进化，声称能压 reward hacking。
- 工程价值：思路可接到现有 GRPO/自进化管线（动态题库难度）。缺公开大规模 infra 数字，先当方法论文。
- 是否值得读：可选
- Relevance Score：3
- Link：https://arxiv.org/abs/2609.18642

## 5. 额外一篇（测量，跨推理优化）

【Title】A Calibrated Instrument for Measuring How Inference Optimizations Affect Output Quality  
https://arxiv.org/abs/2609.18005

- 一句话总结：给量化 / early-exit / spec decode 做可校准的质量尺，而不是各用各的 bench。
- 核心贡献：
  - LLM-as-judge 先用两次独立满精度 run 校准偏差和噪声。
  - 质量损失强依赖领域：4-bit 英文/中文散文几乎无损；3-bit 和 early-exit 在多步数学掉得更狠。
  - token confidence 能预测“会不会换 token”，不能预测“换了伤不伤质量”。
- 工程价值：上线量化/early-exit/spec 前应用这套协议，避免“吞吐好看、数学崩了”。有 code/prompts。
- 是否值得读：强烈推荐（做 serving 质量门禁）
- Relevance Score：4
- Link：https://arxiv.org/abs/2609.18005

## 额外输出

### 1. 今日最值得读 Top 3

1. **ASPIRE** — 长上下文 serving 最痛的是 batched spec 被最慢请求拖死。异步 mixed forward + 请求级 verify 是立刻能改调度器的东西，加速幅度也够大。  
2. **PipeSwift** — Agent 流量已经不是 chatbot。用真实 360B+ MoE、64 卡、真实轨迹证明 PP+JCT 调度能打过 PD-disagg。集群拓扑决策该读这篇。  
3. **D-Quant** — KV 量化论文很多，能把熵编码做成定长、可进 kernel 的很少。这是压缩率能落到带宽的关键一步。

### 2. 今日趋势观察

Inference / KV / spec decode 明显占主导：ASPIRE、D-Quant、Fathom、质量测量仪都挤在同一窗口。第二波是 **agent serving 目标函数切换**（完成时间、跨 session KV、层级记忆），不再把 agent 当“更长的 chat”。纯 SFT/RLHF 方法文偏少，RL 多和 tool-use / 自进化绑在一起。

### 3. 值得跟进的潜在方向

- **请求级异构 spec 调度**：batch 内 draft 长度、verify 时机、稀疏/全注意力混合，会变成默认 serving 原语。  
- **Agent-aware 并行与 KV 生命周期**：JCT 而非 TPOT；跨 turn 压缩 KV；按 agent phase 驱逐（同期还有 AgentKV，略早于本窗口）。  
- **可 kernel 化的变长 KV 编码**：熵编码/bit-plane/per-query bit budget，前提是 dequant 不打乱 attention 访存。  
- **优化上线的质量协议**：同一套量化在散文无损、数学崩盘——需要领域分桶的质量门，而不是单一 GSM8K。
