【Title】Fathom: Per-Query Read Depth for Sparse Decoding over Offloaded KV Caches  
- 一句话总结：把 4-bit K 按 bit-plane 存，每个 query 按通道重要性决定读多少 bit，专门打 offload 场景下的 top-k scan 带宽。  
- 核心贡献（2-3点）：  
  - 通道主序 bit-plane：读前 t 个 plane 就是 t-bit 量化，无需另建索引。  
  - 按 query 通道方差做 reverse water-filling 分配 bit budget。  
  - 百万 token / Qwen3-8B：GPU 时间比 136-bit scan（Double Sparsity/Loki/SparQ r=32）快 1.67×；同等 GPU 时间比 SparQ r=16 少读 18% 字节。  
- 工程价值：直接吃现有量化 serving 已有的 4-bit K；对 **host offload + 长 session/agent** 有用。索引已在 GPU 时无加速。有代码线索。  
- 是否值得读：强烈推荐  
- Relevance Score：5  
- Link：https://arxiv.org/abs/2609.17652

【Title】FlexEE: Self-Speculative and KV-Compatible Early Exiting for Offloading-Aware LLM Inference  
- 一句话总结：offload 下用层间监督 + 局部词表自投机决定提前退出，并保证 KV 正确。  
- 核心贡献：  
  - 层间 exit supervision，中间层预测更稳。  
  - Top-K 局部词表上做自投机，exit 判定成本低。  
  - 动态 hidden-state 管理，early-exit 与 KV 兼容、可感知内存。  
  - Llama2-7B / Llama3-8B，0%/50% weight offload：端到端最高约 1.27×/3.16× 与 1.25×/2.83×。  
- 工程价值：针对 **权重跨层级搬运** 的真实约束，不是实验室 full-HBM 设定。可与现有 decode 栈组合，需改层调度和 KV 写入路径。  
- 是否值得读：强烈推荐  
- Relevance Score：5  
- Link：https://arxiv.org/abs/2609.17008

【Title】D-Quant: Driftable Entropy Coding for KV Cache Quantization  
- 一句话总结：熵编码 KV 量化加上 drift，把变长码流变成定长 bitstream，方便 kernel 规则访存和并行反量化。  
- 核心贡献：  
  - 突破固定 bit-width 的 \(2^b\) 档位数限制。  
  - drift 机制把熵编码结果对齐成固定大小，适配 attention kernel。  
- 工程价值：量化论文里少见地正面处理 **kernel 对齐/并行反量化**，比“再压 0.5 bit”更接近能进 vLLM/SGLang。需看实现是否开源、吞吐数字是否端到端。  
- 是否值得读：可选  
- Relevance Score：4  
- Link：https://arxiv.org/abs/2609.19880

【Title】SSD-LLaMA: SSD-Native Inference for Trillion-Parameter MoE at 1+ Token/s on a Consumer PC  
- 一句话总结：把 SSD 当一等存储做 MoE 专家投递，三层存储 + CPU-GPU 混跑，消费级卡上跑万亿 MoE。  
- 核心贡献：  
  - SSD I/O 管线按 expert 投递，而不是整模 swap。  
  - SSD/RAM/VRAM 三层动态驻留，选中的 expert 全执行、不剪枝替换。  
  - 相对基线 prefill 1.52–4.19×、decode 2.10–15.58×；RTX 5090 + ≤32GB RAM，万亿级 Q4 decode >1 tok/s。  
- 工程价值：本地/边缘 MoE 的完整系统方案；数据中心侧可借鉴 expert prefetch 与层级调度。注意 license（CC BY-NC-ND）。  
- 是否值得读：强烈推荐  
- Relevance Score：5  
- Link：https://arxiv.org/abs/2609.18110

【Title】Where Should the KV Cache Live? Placement Policies Across GPU, CPU, and SSD for Long-Lived Sessions  
- 一句话总结：用校准过的离散事件仿真比较 GPU/CPU/SSD 上 KV 放置策略，结论偏“容量比策略重要”。  
- 核心贡献：  
  - 覆盖 recency / reuse / 预测 reuse / EWMA+prefetch。  
  - 分层容量 1+8+64 带来约 73× 并发 session、62× 更低 per-session 成本。  
  - batch=1 时 decode 算力受限，放置几乎不影响吞吐，主要改 PCIe 迁移和 TTFT。  
- 工程价值：给 **Mooncake/LMCache 类分层** 定调：先堆容量，再抠策略。是设计决策论文，不是可 drop-in 实现。  
- 是否值得读：可选  
- Relevance Score：4  
- Link：https://arxiv.org/abs/2609.16215

【Title】Ask the Tool, Don't Guess: Agent Tool Calls Hold Their Progress, and the Serving System Should Read It  
- 一句话总结：agent 等 tool 时 KV 占着 GPU，系统不该猜 tool 时长，应让 tool 上报进度。  
- 核心贡献：  
  - 证明调用前估计无法可靠预测甚至无法排序时长。  
  - 四个公开 agent 语料：多数 tool 时间存在可读进度（剩余比例或“快结束”）。  
  - 接到生产引擎：tool 返回后 p90 TTFT 相对 LRU 降约 20.7–20.8%，接近 oracle。  
- 工程价值：直接改 **KV 驻留/换出策略与调度 hint**，agent serving 少有的系统接口论文。  
- 是否值得读：强烈推荐  
- Relevance Score：5  
- Link：https://arxiv.org/abs/2609.18849

【Title】AgentKV: Phase-Aware KV Eviction for Agentic LLMs  
- 一句话总结：按 agent 阶段维护 query buffer，对阶段 union 打分驱逐，并做成跨 turn 的压缩 KV serving。  
- 核心贡献：  
  - 打破“未来注意力 ≈ 最近 token”假设。  
  - 多 turn 路径上在线 compact retained pages。  
  - 相对 R-KV / Tri-attention 任务分平均 +5.5 / +5.3；相对 full-KV SGLang 输出吞吐最高 1.80×。有代码。  
- 工程价值：面向 **长 agent session** 的 eviction，可对标 SGLang。与 Random Attention（推理链随机驱逐）形成对照。  
- 是否值得读：可选（略超 48h，但工程完整）  
- Relevance Score：4  
- Link：https://arxiv.org/abs/2609.14872

【Title】UnifiedPlayers: Enhance Tool-Integrated Reasoning in Agentic Reinforcement Learning  
- 一句话总结：规划/执行/可执行 verifier 三个 player 用 GRPO 协同，做自演进 tool-use RL。  
- 核心贡献：  
  - 三个角色各自有 reward，避免静态 verifier 与自洽误差放大。  
  - 12 个推理基准：数学 ≥+3.5%、通用 ≥+3.9%。  
  - 学到的 verifier 对抗检测 84.2%，reward 方差是自洽基线的 2.03×。  
- 工程价值：训练配方与多角色协调可复用；落地成本在 rollout/verifier 基础设施，不直接加速推理。  
- 是否值得读：可选  
- Relevance Score：3  
- Link：https://arxiv.org/abs/2609.20089

【Title】Reach or Solve? Attributing Agentic RL Gains with Checkpoint Handoffs  
- 一句话总结：用 SFT/RL 的 reacher×solver 交叉，把 agent RL 增益拆成 REACH 与 SOLVE。  
- 核心贡献：  
  - REACH：到达“离成功固定步数”的状态频率；SOLVE：同一克隆状态上能否收尾。  
  - 两套独立管线、五个条件：reacher×solver 交互均为正；RL 历史对 RL solver 更值钱。  
  - ALFWorld 上 RL 同时抬两项，SFT solver 没有“RL 失败而自己成功”的案例。  
- 工程价值：给 agent RL 实验设计提供归因协议，减少“分数涨了但不知道涨在哪”的调参。  
- 是否值得读：可选  
- Relevance Score：3  
- Link：https://arxiv.org/abs/2609.19636

【Title】Rollback the World, Keep the Reflection: Rollback-Induced Reflection for Long-Horizon LLM Agents  
- 一句话总结：回滚环境到先前状态，但把失败轨迹蒸馏成可复用记忆再决策。

- 是否值得读：可选

### 1. 今日最值得读 Top 3

1. **Fathom** — 百万 token offload 下的 scan 是真实瓶颈；方法吃现成 4-bit K，数字具体，agent 长会话可直接对标。  
2. **SSD-LLaMA** — 完整把 SSD 做成 MoE 执行层级，消费级万亿 decode >1 tok/s，是本窗口最完整的 infra 系统稿。  
3. **Ask the Tool, Don't Guess** — 指出 serving 在猜 tool 时长是错接口；加进度 hint 就能把 tool 返回后 p90 TTFT 打到接近 oracle。Agent 上线团队应先读这篇。

### 2. 今日趋势观察

Inference / KV 仍占主导，且从“再发明一个打分器”转向三类更硬的问题：  
- **offload 带宽**（Fathom、FlexEE）  
- **分层放置与容量**（Where Should KV Live、SSD-LLaMA）  
- **agent 生命周期里的 KV**（Ask the Tool、AgentKV）  

Agent 论文明显增多，但真正有 serving/系统接口的仍少，多数还是 RL 配方。分布式训练大论文本窗口偏少。

### 3. 值得跟进的潜在方向

- **Tool 进度作为一等调度信号**：KV pin/swap、prefetch、连续 batch 的空档都应读 tool progress，而不是历史均值。  
- **Bit-plane / 变长量化 + 定长 kernel 契约**：Fathom 的 plane 扫描与 D-Quant 的 drift 是同一类问题——压缩格式必须对 GPU kernel 友好。  
- **Reasoning vs Agent 的 eviction 假设可能相反**：推理链可随机丢（近期 Random Attention），agent 多阶段则要 phase-aware。不要一套 eviction 打所有 workload。  
- **Agent RL 归因拆解（REACH/SOLVE）**：训练资源应分给“到得了关键状态”还是“到了会收尾”，比只看终局成功率更可操作。
