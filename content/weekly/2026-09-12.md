## 1. 本周趋势总结

**论文最多、最吵的方向：Agent + Agentic RL。**  
Terminal / SWE / 长程交互任务上的 RL 后训练、harness / loop engineering、agent memory 与 incident 记录，占本周可见产出的大头。典型信号：`T1` 把 10B active 的开源 MoE 打到 Terminal-Bench 第一梯队；同时出现「Agent Incident Registry」「Grounding Agent Memory」「Ecdysis / LoopArena」这类**平台化、可审计、可复用 harness** 的工作，而不是再发一篇 ReAct 变体。

**升温最快、对你最相关的方向：推理系统与 RL 训练系统的耦合。**  
不再是单独加速 decode，而是：

- speculative decoding 进入 **大规模、长上下文 RL rollout**（draft 在线共训 + CP/PP 改造）；
- MoE 推理从固定 top-k 走向 **动态稀疏 + 分布对齐 / expert cache 作为算法问题**；
- KV 从“张量缓冲”变成 **跨节点共享内存对象**（CXL + K8s DRA + vLLM connector）。

**明显降温或已经商品化、再发论文边际收益低的方向：**  
纯 prompt 级 multi-agent 拓扑搜索、又一篇 heuristic KV pruning、又一篇 DPO/GRPO 小改、以及“frozen LLM + 外环进化搜索”的包装论文。社区已经把 moat 从模型权重挪到 **harness / loop / serving stack**。

**活跃度粗排（本周，工程师视角）：**  
1. LLM Agents + Agentic RL（量最大）  
2. Inference / Serving（MoE 动态路由、KV 分层、speculative × RL）  
3. Alignment / iterative RLHF（有理论，工程闭环少）  
4. 经典分布式训练并行（增量论文，少突破）  
5. 纯 SFT recipe（被 RL + harness 盖过）

## 2. 重点论文（Top List）

按“该不该花时间”排序，不是按 hype。

### 1) T1: Terminal Agent Reinforcement Learning for Long-Horizon Tasks  
`arXiv:2609.11042`（2026-09-10）

- **一句话：** 用 PPO + 长上下文 + routing replay，把 Qwen3.5-122B-A10B 从 SFT 49.4 打到 Terminal-Bench 2.1 **64.0**（10B active）。  
- **核心贡献：** 生产级长程 terminal agent 的 RL recipe：Critic Warm-Up、84k context、dense reward、routing replay；明确拆出 SFT +14.6pt RL 的增益结构。  
- **工程价值：** 高。这是可对照的后训练管线，不是玩具环境。  
- **是否精读：** **值得精读训练系统部分**（replay、context、critic 初始化），不必精读所有 bench 表。

### 2) Online Draft Co-Training for Speculative Decoding in Large-Scale, Long-Context RL Post-Training  
`arXiv:2609.07108`（2026-09-07）

- **一句话：** 把 speculative decoding 做成 **RL rollout 的一等公民**：在线共训 draft，并改 packed zigzag ring attention / pipeline 中间特征旁路。  
- **核心贡献：** 针对 RL 长上下文的 CP/PP 工程：branch attention 与因果主序列合并；TapChannel 跨 stage 传 target 中间特征；到 122B、256K。  
- **工程价值：** **本周对 Infra 工程师最高。** rollout 才是 RL 账单。  
- **是否精读：** **必读 + 跟源码。** 宣称有 code。

### 3) Composable CXL Memory as a Kubernetes-Native Shared Memory for LLM Serving  
`arXiv:2609.10790`（2026-09-09）

- **一句话：** 把可组合 CXL 做成 K8s DRA 可调度资源，vLLM/llm-d 用共享段做跨节点 prefix KV，目录嵌在介质里，不要外部 metadata 服务。  
- **核心贡献：** 系统路径完整：DRA driver → DAX → CDI → 共享 KV connector；两节点 512GiB CXL + Qwen2.5-7B，外部命中 95%+ 时 TTFT 降 5.5–36.6×。作者自己标成 feasibility。  
- **工程价值：** 高（方向），落地取决于你有没有 CXL 池。想法可迁移到 RDMA KV pool。  
- **是否精读：** 值得读 **资源模型与 connector 设计**，数字别当 SLA。

### 4) Epoch: Compiling Diffusion Blocks for Sparse MoE Serving  
`arXiv:2609.09748`（2026-09-09）

- **一句话：** 扩散语言模型的“块时钟”和现有 LLM serving 的“一次 forward = 一个执行单元”不匹配，把 diffusion block 编译成 block plan。  
- **核心贡献：** 8×H100 上 LLaDA-MoE 系列（7B–100B），相对最强存活 baseline 端到端最高 2.7×，大批次下别人 OOM 它还能跑。  
- **工程价值：** 中高。如果你只做自回归，可暂缓；如果团队看 dLLM / block diffusion，这是 serving 编译器问题的正确抽象。  
- **是否精读：** 做 serving compiler / scheduler 的人精读。

### 5) Distribution-Consistent Inference for Dynamic Sparse MoE  
`arXiv:2609.09241`（2026-09-08，EMNLP Findings）

- **一句话：** 推理期动态减小 top-k 会引入相对训练路由的分布偏移；用层内校准统计做轻量对齐（LDA），几乎零开销把精度捞回来。  
- **核心贡献：** 把“少激活几个 expert”从启发式改成 **可校正的分布偏移问题**。  
- **工程价值：** 高且便宜。比再训一个 router 更接近生产开关。  
- **是否精读：** 值得读方法 + 校准流程，实现量不大。

### 6) Cache-Aware Joint Router Adaptation for Memory-Efficient MoE Inference  
`arXiv:2609.04895`（v2 2026-09-10）

- **一句话：** Expert cache 命中率不要只靠 LRU；用后训练同时改 backbone + 轻量时空 router，推理仍走原生 Top-K。  
- **核心贡献：** Temporal / Spatio-Temporal Router；相对最强 prefetch baseline，流量可降数个百分点到 50%+（任务相关）。  
- **工程价值：** 中高。和动态 top-k、Least-Stale 类 eviction 是同一战场。  
- **是否精读：** 做 MoE serving 的人读；不要当通用 serving 银弹。

### 7) BeaconKV: KV Compression Guided by Beacon Queries for LRMs  
`arXiv:2609.04971`（2026-09-04，本周仍在扩散）

- **一句话：** 长 CoT 会回看早期 plan（Thought Revisiting Tokens）；用少量 beacon query 代表全局 query 簇，而不是用“最近 query”估重要性。  
- **核心贡献：** 打到现有压缩方法的错误假设；最高约 5.8× 显存、4.3× throughput，精度接近满缓存。  
- **工程价值：** 中。对 **推理模型长 decode** 比普通 RAG 长上下文更对口。  
- **是否精读：** 做 reasoning serving / KV eviction 的人精读分析部分。

### 8) Explore More, Drift Less (CANOPY)：Outcome-Only RL for Long-Horizon Agents  
`arXiv:2609.01245`（2026-09-01）

- **一句话：** 小开源模型上，纯 outcome RL + 正确探索，不必逐步奖励也能把 AppWorld / SWE 打上去，并计划开训全栈。  
- **核心贡献：** 反击“outcome-only 对小模型立刻撞墙”的教条；强调探索与漂移控制。  
- **工程价值：** 中。价值在 **奖励设计哲学与训练栈**，不在新算法名。  
- **是否精读：** 等正式 code；先读实验设置，别复现论文口号。

### 9) OmniKVQuant：Omni-LLM 的 2-bit KV  
`arXiv:2609.11582`（2026-09-10）

- **一句话：** 多模态 KV 不能直接套文本 TurboQuant：有 temporal key drift 和模态间 value 几何差异；窗口化 key range + 分模态旋转，配 fused 2-bit decode kernel。  
- **工程价值：** 做 Omni / 音视频 serving 值得看 kernel；纯文本团队可跳过。  
- **是否精读：** 按产品线决定。

### 10) 一组“平台信号”论文（合并看，不要逐篇精读）

- Grounding Agent Memory / Agent Incident Registry（9-10）：生产 agent 缺的是 **可检索失败机制** 和 **环境探测式记忆策展**，不是更大 context。  
- Ecdysis / LoopArena：从 harness engineering 转到 **loop engineering**（谁调度、何时验、何时停）。  
- Inference-Time Graph Engineering (ReActNet)：训练免费、把 MAS 编成可执行时序图。  

对 Infra：**读结论当产品 backlog，不要复现实验。**

## 3. 关键趋势判断

**有没有新范式？有，但是“系统范式”，不是新 loss。**

1. **Rollout 系统 = 新训练系统。** RL 后训练的瓶颈从“算法稳不稳”变成“inference engine 与 training engine 概率不一致、draft 过时、长上下文 CP/PP、MoE routing replay”。MIPI/MIPU 那类“优化 inference 侧策略而非 training 侧概率”的思路会继续渗进工程。  
2. **Harness / Loop 是 moat。** 模型发布已按 agent bench（Terminal-Bench、SWE、tau）叙事；论文在问：loop 谁写、能否进化、失败如何登记。  
3. **KV / Expert 都变成可调度的集群对象。** CXL DRA、共享目录内嵌、动态 top-k + 分布校准、cache-aware router——同一句话：把缓存策略从 kernel 细节提升到 **集群 API**。  
4. **Alignment 理论在补“迭代闭环”的洞。** iterative RLHF 的 alignment collapse、FPO 等说明：静态 RM 假设已经不够。但本周这类工作离 vLLM/K8s 还远，别过早投入实现。

**研究 → 工程的信号（真的）：**

- 论文直接改 vLLM / SGLang / K8s DRA / 给出 122B、256K、8×H100 数字；  
- “feasibility study” 自己降调，但接口设计可抄；  
- GitHub 侧 agent ADE、skills、sglang 仍在涨——论文和代码仓库在同一条产品线上。

**1–3 个月可能爆发：**

- RL post-training 的 speculative + 训练/推理一致性；  
- MoE 动态稀疏的 **可上线开关**（校准、cache-aware router，而不是新架构）；  
- Agent serving 的 KV 共享 / 分支前缀（agent 工作负载让 vLLM vs SGLang 差距被测到 3–4× 的那类观察，会倒逼 scheduler）；  
- dLLM / block-diffusion serving，若权重继续开源。

## 4. 工程师行动建议（重点）

假设你做 **推理优化 / AI Infra / 分布式系统**。

### 本周最值得深入的 3 个方向

1. **RL Rollout 加速与训推一致性**  
   读并拆 `2609.07108`。问自己的栈：draft 是否随 policy 漂？256K 时 ring attention 的 packed/load-balance 怎么做？PP 中间激活要不要旁路？这会直接决定下一代内部 RL 集群的利用率。

2. **MoE 推理的“可变计算 + 缓存当算法”**  
   LDA 动态 top-k 校准 + cache-aware router。这是能在现网模型上做 A/B 的方向，不需要等新基座。

3. **把 KV 当集群资源，而不是 GPU 上的 tensor**  
   CXL 论文提供资源模型；即便没有 CXL，也应把 prefix/KV pool、跨 PD 传输精度分配、agent 分支复用写进 roadmap。Agent 流量会放大 prefix 命中和错误隔离问题。

### 值得复现 / 读源码

| 优先级 | 对象 | 原因 |
|---|---|---|
| P0 | Online Draft Co-Training（07108） | 直接对应你的 GPU 小时账单 |
| P0 | 你们正在用的引擎里 MoE expert cache / 动态 top-k | 把 LDA、cache-aware router 当 patch 评估 |
| P1 | T1 训练栈中与 serving 相关的部分（长 context rollout、routing replay） | 为内部 agent RL 平台对表 |
| P1 | CXL+K8s DRA 的 **接口与故障模型**（不必买硬件） | 抄调度语义到 RDMA KV |
| P2 | Epoch（若团队碰 dLLM） | serving 编译单元换了 |

### 短期内不值得投入

- 再造一套 multi-agent 对话拓扑搜索 / textual gradient prompt opt（ReASearch 一类：研究问题清楚，对 serving 团队 ROI 低）。  
- 新的 token-heuristic KV 压缩，若假设仍是“最近 query ≈ 未来重要性”——BeaconKV 已经指出 LRM 上这假设坏了，没有分析就不要实装。  
- 从零实现又一个 GRPO 变体；用现成后训练框架，把时间留给 rollout 系统。  
- 把 CXL 数字当容量规划依据（作者已声明 feasibility）。  
- Omni / 扩散 serving，若路线图里没有对应模型。

## 5. 风险与噪音分析

**本周最大噪音方向：**  
“Agent 能自我进化 harness / 自己当 optimizer”的论文海。数量多、demo 好看、可复现差、对线上 SLA 几乎无增量。同一周真正值钱的是：**失败登记、记忆策展、loop 评测（LoopArena 全任务 Strict Success ~25%）**——说明天花板在控制回路，不在又一个 planner prompt。

**论文多但价值低的次级噪音：**  
迭代 RLHF 的博弈论分解、offline RL 最优值推断。理论正确，但 1–3 个月进不了你的 oncall。

**论文不多但更有潜力：**

- **训推概率不一致作为一等优化目标**（MIPI 思路 + 本周 draft 共训）；  
- **共享 KV 的隔离 / 故障 / 目录内嵌**（CXL 文提出了问题，生态几乎没人做对）；  
- **Agent 工作负载特有的调度**（分支、工具调用、非自回归块、expert 抖动），而不是再优化 GSM8K 单请求 decode。

---

**本周决策一句话：**  
不要再追“新 agent 算法名”。把时间压在三件事上——**RL rollout 的 speculative/并行、MoE 可变计算的可上线校准、KV/expert 的集群化资源模型**。这三件会在下个季度直接出现在你的延迟曲线和 GPU 账单上。
