## 1. 本周趋势总结

**论文最多的方向**
- **LLM Agents + Agentic RL**：bench、轨迹合成、harness×task、长程 credit assignment、agent 自己做 optimizer，数量明显压过纯算法论文。
- **RL post-training（GRPO / off-policy / 无标注 RL）**：仍是默认训练范式。pass@k 目标、off-policy 校正、label-free / peer reward 一周内反复出现。
- **推理侧 KV / 长 CoT 服务**：还在出，但题目已经从「再做一个量化器」变成「reasoning trace 该怎么 evict / 怎么跨 PD 传」。

**升温**
- **训练系统与推理系统合流**：partial rollout、online speculative decoding、async generation/training decoupling、PD 解耦上的 KV 传输精度。这是从「训一个 reasoning 模型」转向「把 RL 流水线跑满 GPU」。
- **把搜索控制器吃进 agent**：ReASearch 这类工作明确问「外层进化/bandit 还要不要」。
- **无 verifier / 弱标签长程 agent**：DRACO、RESTRAIN、Co-RL。工程上对应「生产环境没有 unit test」。

**降温（相对）**
- 新的 PPO vs DPO 叙事论文。
- 再发一篇「通用 mixed-precision KV + 重要性分数」且不碰 reasoning / PD 解耦的工作——边际价值在下降。
- 纯对齐理论、alignment collapse 机制，实验室有用，infra 团队本周不是主战场。

活跃度粗判：**Agents/Agentic RL ≫ RL 训练系统 ≈ KV-for-reasoning > 经典 RLHF 理论**。

## 2. 重点论文（Top List）

### 1) Random Attention: Rethinking KV Cache Eviction for Efficient Reasoning  
`arXiv:2609.03430`（9/3）  
**一句话**：reasoning 场景下，prompt 保住、trace 随机丢，就能打平最强 selector，吞吐还更高。  
**贡献**：打穿「必须打分再 evict」的默认假设；解释 redundancy 在文本复述和多头两层。vLLM 部署吞吐 +32–43%。  
**工程价值**：高。可直接改 eviction policy，几乎零训练。  
**精读**：是。本周 inference 第一优先。

### 2) SemKV: Semantic Mixed-Precision KV Quantization  
`arXiv:2608.28911`（8/28）  
**一句话**：先测 quality cliff（约 2.0–2.32 bit），再在 cliff **上方**做 mixed precision，6.0×–7.9× 存储、统计上无损。  
**贡献**：把 mixed-precision 从启发式变成「测 cliff + 插值」的部署配方。  
**工程价值**：高，可进 serving 配置手册。  
**精读**：读方法+实验协议即可，不必抠理论。

### 3) Intern-S2-Preview: Scientific Agentic Foundation Model  
`arXiv:2608.13505`  
**一句话**：科学 agent 基座，真正值钱的是 post-training 系统：partial rollout + off-policy 校正、online speculative decoding（rollout ~2×，端到端 RL ~1.7×）、harness×task 的黑/白盒 agentic RL。  
**贡献**：把「能训长程 tool agent」写成可复用流水线，不是再刷一个科学 QA 分。  
**工程价值**：极高（系统部分）。XTuner/LMDeploy 路径可对照。  
**精读**：系统章节值得精读；模型榜单可扫。

### 4) The Optimizer Is the Agent (ReASearch)  
`arXiv:2608.06714`（v2 ~8/31）  
**一句话**：同一套 tool-using agent loop 优化 prompt / program / ML workflow，多数任务超过专用外环控制器。  
**贡献**：搜索策略内化；失败诊断 + memory，而不是只当 proposal generator。  
**工程价值**：中高。适合 AutoML / 编译优化 / 实验平台，不适合当 serving 核心。  
**精读**：值得读实验与 ablation（memory vs python_exec）。

### 5) OAPL: Off-policy RL with Lagged Inference Policy  
`arXiv:2602.19362`（本周仍在被讨论）  
**一句话**：承认分布式 RL 天然 off-policy，不改 inference engine，也能扛 400+ step lag。  
**贡献**：少 sample 对齐 LiveCodeBench；pass@k 更好。  
**工程价值**：高。任何 disagg / async RL 栈都该对照。  
**精读**：是（算法+和 vLLM 策略不一致的部分）。

### 6) LoPT: Cheaper/Faster Local Learning for LLM Post-Training  
`arXiv:2605.04913`  
**一句话**：截断 task 反向路径，SFT 省 23–36% peak mem，GRPO 更新阶段再省 21–24% mem、7–21% step time，能力不明显掉。  
**贡献**：post-training 不必全程 E2E backward。  
**工程价值**：高，改训练图就能吃。  
**精读**：实现细节值得对照自己的 trainer。

### 7) DRACO: Fine-Grained Credit Assignment with Dynamic Rubrics  
（HF Daily，约 9/4）  
**一句话**：无 verifier 的长程 agent，用动态 rubric 把轨迹级分数闭式拆到逐步，AppWorld 上甚至超过带 GT 的 GRPO。  
**贡献**：生产 agent 最痛的 credit assignment，不训额外归因网络。  
**工程价值**：中高。有环境、无单测时优先试。  
**精读**：公式短，值得复现实验设置。

### 8) RESTRAIN: Self-Driven RL with Self-Penalization  
`arXiv:2510.02172`  
**一句话**：无 gold label，把「没有标签」变成惩罚信号，AIME25 等上接近有标训练。  
**贡献**：label-free reasoning RL 的一条可跑路径。  
**工程价值**：中。数据贵时有用；稳定性要自己验。  
**精读**：扫方法，不必深挖 unless 你在做无标 math/code RL。

### 9) FlexMARL / AReaL / OpenRLHF 一线（本周仍是 infra 参照系）  
**一句话**：MARL 编排最高 7.3×；全异步 RL 最高 2.57×；OpenRLHF 继续打 vLLM+Ray 的 CoT RL 推理瓶颈。  
**贡献**：问题已经从算法换成 **generation/training 解耦、长度调度、权重同步**。  
**工程价值**：极高。  
**精读**：对照自己集群的 bubble / 权重同步，不必三篇全读。优先 AReaL + 你正在用的框架 release notes。

### 10) Meta: RL for Code Optimization（略早，7/29，但方向未过期）  
**一句话**：正确性 RL 之后，把 **运行时间**做成可学 reward（DMC-Optim）。  
**贡献**：sandbox + 速度奖励 + 改 GRPO。  
**工程价值**：中。编译器/代码 infra 团队该看；通用 chat 不必。  
**精读**：环境与 reward 设计，算法本身次要。

未进 Top 10 但可备案：OasisKV / SpectrumKV（PD 解耦 KV 传输）、SortedRL（按长度调度减 bubble）、Co-RL（多模型互为奖励）。

## 3. 关键趋势判断

**有没有新范式？**  
有，但是工程范式，不是新 loss：
1. **Agent = optimizer / trainer**：外环搜索、甚至 alignment 修补开始被 agent 内化（ReASearch；Anthropic 侧 automated alignment 报道同期出现）。
2. **RL 系统默认异步 + 承认 off-policy**：再假装 on-policy 是在跟自己的 serving 栈作对。
3. **推理优化从「压缩一切」变成「保护 prompt / 尊重 reasoning 冗余」**：Random Attention 是这个转向的标志性结果。

**研究 → 工程的信号**  
- 数字开始带 **vLLM 吞吐、PD 解耦 TTFT、512 GPU 线性度、rollout 2×**，而不是只报 AIME。  
- 开源落点集中在 XTuner、LMDeploy、vLLM connector、LMCache 这类已经在用的组件。  
- 「测 quality cliff 再选 bit」这种话术已经是 SRE/serving 语言。

**1–3 个月可能爆发**
- Reasoning-aware KV（随机/分层，而不是更复杂的 importance net）
- RL trainer 的 spec-decode + partial rollout 成为标配
- 无 verifier 长程 credit assignment（rubric / peer / self-penalty）
- Agent 优化 ML/serving 配置本身（InferenceBench 类任务会倒逼）

## 4. 工程师行动建议（重点）

假设你做 **推理优化 / AI Infra / 分布式系统**。

### 本周最值得深入研究的 3 个方向

1. **Reasoning workload 的 KV 生命周期**  
   Random Attention + SemKV cliff +（若你做 PD）SpectrumKV。  
   投入产出：改 eviction/quant 策略，不改模型。

2. **RL/Agent 训练时的推理栈，而不是离线 serving 栈**  
   Intern-S2 的 partial rollout / online SD；OAPL 的 lag；AReaL 异步。  
   你的瓶颈已经是 rollout bubble、策略版本差、超长 CoT，不是再抠 3% decode kernel。

3. **Agent runtime 与训练协议对齐（harness×task）**  
   同一套轨迹既给环境 verifier 又给 token-level RL。这是未来 3 个月 agent 产品能不能「在线强化学习」的分水岭。

### 值得复现 / 读源码

| 优先级 | 做什么 | 为什么 |
|---|---|---|
| P0 | Random Attention 接到现有 vLLM/SGLang eviction | 实现短，结论可证伪，立刻有吞吐数字 |
| P0 | 对照 Intern-S2 / XTuner 的 partial-rollout + in-flight prefix | 这是大规模 agentic RL 的真实工程 |
| P1 | SemKV：在你的模型和 max-len 上复测 cliff | cliff 会随模型/量化器变，论文数字不能直接抄 |
| P1 | OAPL 或你当前框架的 off-policy 校正 | 只要 generation 和 trainer 不是锁步，你已经 off-policy |
| P2 | LoPT 截断 backward | 训练集群内存墙明显时再做 |

### 短期内不值得投入

- 再发明一个「更准的 token importance 网络」去做 KV eviction（本周论文已经打脸）。
- 从零写一套新的 RLHF 框架（OpenRLHF / veRL / AReaL / LlamaRL 差的是集成，不是概念）。
- 无环境、无轨迹日志的「通用 agent 规划理论」。
- Emergent misalignment / 集体conformity 类安全论文：重要，但不是本周 infra 排期。
- 把 ReASearch 当核心 serving 组件——它是优化器，不是推理引擎。

## 5. 风险与噪音分析

**本周最大噪音**  
- **Agent 包装纸**：大量 “agentic foundation / trajectory engine / skill wiki” 论文，贡献是数据叙事和 bench，系统不可复用。  
- **label-free RL 数字竞赛**：+140% Pass@1 很好看，缺失败模式、reward hacking、多 seed。跟进算法可以，当 roadmap 不行。  
- **KV 论文数量 ≠ KV 价值**：多数仍在重复 importance scoring；真正增量是 Random Attention 这种负结果 + 可部署吞吐。

**本周最有潜力、论文还不多**  
- **训练期 speculative decoding 的 accept rate 随 policy 演化不塌**（Intern-S2 点到了，缺通用库）。  
- **PD 解耦下的 per-token 精度谱，而不是 drop-or-keep**（SpectrumKV 一类）。  
- **闭式、无额外网络的长程 credit assignment**（DRACO）——论文少，但每个做 agent 产品的人都会撞墙。  
- **Inference 优化任务本身交给 agent**（InferenceBench 苗头）：未来评估 infra 工程师的方式可能变成「agent 两小时内能把 vLLM 调到多快」。

---

**本周决策一句话**：把时间花在 **reasoning KV 策略** 和 **RL rollout 系统（异步、partial、spec-decode、off-policy）** 上；agent 论文只读带训练系统或可复现 credit assignment 的；不要被「又一个 agent framework」带跑。
