## 1. 本周趋势总结

**论文最多的方向：LLM Agents，而且几乎全部在围着 “Harness” 转。**  
不是新写一个 ReAct 变体，而是把 **deploy-time harness（工具循环、上下文管理、控制流、sandbox）直接拉进 RL / SFT 闭环**。代表：Agent Lightning v1.0、JIT-Agent、各类 skill/harness 演化。这是本周唯一可以叫“范式级升温”的信号。

**明显升温：**
- **Harnessed Agentic RL**：训练时不再重写一套 gym，而是 proxy 进真实 harness。verl / AReaL / slime / Polar 已经跟进同类架构，说明这不是单篇论文。
- **Agent-aware Inference**：投机解码、KV reuse 开始针对 *tool schema 乱序、多 turn、动态 batch*，而不是普通 chatbot prefix cache。AgentSpec、ReCache 是这一周最硬的系统论文。
- **RL rollout 系统加速**：投机解码进 RL 训练环（NVIDIA / NeMo-RL），HF Daily 本周还在推。这是把 inference 优化反哺 post-training 的明确路径。

**相对降温：**
- 经典 **preference RLHF / Mixture-of-Judges** 这类多目标对齐理论：还在出，但对本周工程社区几乎无增量。
- 又一个 GRPO 改 advantage 的小论文：数量仍高，边际收益在变薄（SALT 这类除外，它至少对准了 rollout 浪费）。
- 纯 agent “新框架 + 新 bench” 没有系统数字的：噪音最大。

**按工程密度排序（不是按发文量）：**  
`Agent serving / KV / spec decode` > `Harnessed RL infra` > `RLVR 算法修补` > `Alignment 理论` > `Skill 包装论文`。

## 2. 重点论文（Top List）

只列对推理 / Infra / Agent / RL 有决策价值的。超过 10 篇就不列。

### T1. Agent Lightning v1.0: Towards Harnessed Agentic RL  
**一句话：** 用 ~3500 行 proxy，把任意真实 harness 接到 RL，不重写环境。  
**贡献：** 把 “harnessed agentic RL” 说清楚：harness 拥有交互环，trainer 只看见 request/response。点名真实痛点——**retokenization、变长 sample merge、advantage、loss norm、动态 batch 调度**。Qwen3.5-9B + 6K 样本，SWE-bench Verified **41.8 → 56.4**。有完整 coding-agent pipeline。  
**工程价值：** 高。这是你下周就可以 fork 的训练架构，不是算法玩具。  
**精读：** **必须精读 + 读源码。** 尤其是 loss / advantage 在变长 multi-turn 下怎么归一。

### T2. AgentSpec: Speculative Decoding for Batch Inference of LLM Agents  
**一句话：** 给 agent 批推理做投机解码，专门打“大 batch 加速崩掉”这个问题。  
**贡献：** 诊断两个死因：投机 token 拒收率高、动态 token budget 用不满。方法：结构隔离 drafting（只在语义连贯的 agent 段上投机）+ 冗余感知 budget。在 vLLM、5 种 workload、4 个模型族上测。  
**工程价值：** 高。agent serving 的真实瓶颈就是 tool 间等待 + 大 batch 投机失效。  
**精读：** 值得。重点看他们如何切 “structure-isolated draft”，这比再训一个 draft model 更可落地。

### T3. ReCache: Efficient KV Cache Reuse and Compression for Tool-Augmented LLM Agents  
**一句话：** Tool/skill schema 每次组合顺序不同，标准 prefix cache 全废；把资源表示做成可组合、可独立缓存的 KV block。  
**贡献：** Resource-wise attention 去掉 cross-resource 交互，得到组合不变 KV。报告 TTFT **3.66×**，KV 内存 **-92%**，attention **1.42×**，调用质量几乎不掉。  
**工程价值：** 很高，且是 agent 特有问题（chatbot 没有这么碎的 schema 拼接）。  
**精读：** 值得。评估要带着怀疑看——resource-wise attention 改了注意力语义，上线前必须在你们自己的 tool 集上复测。

### T4. PuzzleKV: Page-Wise Low-Rank Decomposition for KV Cache Compression  
**一句话：** 按 page 做低秩分解压缩 KV，免训练免校准。  
**贡献：** 约 60% 存储保留 >96% Full-KV；叠量化可到 18.7% 存储、>93% 性能。比 Global SVD 更稳。  
**工程价值：** 中高。page 粒度更容易塞进 paged attention。  
**精读：** 扫一遍方法 + 延迟开销表即可。没有 kernel 数字就先不要排进 Q4 roadmap。

### T5. Elastic KV Cache for LLM Serving  
**一句话：** Prefill 预留内存在 decode 阶段其实闲着，用户态 CUDA VA 把它借给 KV pool，chunked prefill 已经吃掉大部分收益。  
**贡献：** 机制能 work（约 +18% KV 容量、+10% decode throughput），但作者自己说 **chunked prefill 已经把缺口补上大半**。这是少见的“负结果也写清楚”的系统文。  
**工程价值：** 高——不是因为要抄机制，而是帮你 **别浪费一个月去做弹性 KV**。  
**精读：** 结论段必读，实现细节可选。

### T6. Accelerating RL Post-Training Rollouts via System-Integrated Speculative Decoding（NVIDIA / NeMo-RL）  
**一句话：** 投机解码作为 **无损** RL rollout 加速，进生产级 RL 框架。  
**贡献：** 8B 同步 RL rollout **1.8×**；模拟器估 235B + 异步 RL **端到端 2.5×**。MTP / 外部 draft / EAGLE-3 都能接。分布不变，不引入 off-policy。本周 HF Daily 仍在推。  
**工程价值：** 极高，如果你在做 RL infra。  
**精读：** **值得复现到自己的 rollout worker。** 关注 draft 过时（policy 在变）和 async pipeline 的 acceptance 漂移。

### T7. JIT-Agent: Scaling Harness Intelligence via Just-in-Time Harness Evolution  
**一句话：** 另训一个小模型，现场给任意 off-the-shelf LLM 生成 / 修复 harness。  
**贡献：** 把 harness 形式化成四模块协议；DeepSeek-V4-Flash 在部分 bench 超过 GPT-5.6；GLM-5.2 最高 +20.2。有代码和数据集。  
**工程价值：** 中。方向对，数字要打折——harness 增益高度依赖评测 harness 本身。  
**精读：** 读协议设计和失败修复回路，不必迷信分数。

### T8. Demystifying Reinforcement Learning Post-Training of Language Models  
**一句话：** 把 RLVR 拆开，说明 RL 成功强烈依赖 base 模型先验是否已经覆盖目标行为。  
**贡献：** 伪奖励是否有害取决于 prompt 分布；把“探索”拉回经典 RL 语言。有配套站点和代码。  
**工程价值：** 中。不改代码，但能防止你在“base 根本不会”的任务上烧 GPU。  
**精读：** 作为内部培训材料值得，不当成算法论文。

### T9. Progress Advantage for LLM Agents（post-training 的免费 step signal）  
**一句话：** RL 后的 π 与 ref 的 logprob 比就是 step-level advantage，不必再训 PRM。  
**贡献：** 用于 test-time scaling、不确定度、失败归因；号称打过专门训的 RM。  
**工程价值：** 中高——agent 轨迹打点成本极高，这个信号几乎零成本。  
**精读：** 值得小规模验证；别一上来替换线上 reward。

### T10. Optimizing / Online Scheduling for LLM Inference with KV Constraints（WAIT / MC-SF 系列本周仍在被引用和更新讨论）  
**一句话：** 把 decode 中内生增长的 KV 当成调度约束，而不是 FCFS + paged 碰运气。  
**贡献：** 流体近似 + 在线算法，接近过载时比默认 vLLM/Sarathi 配置更稳。  
**工程价值：** 中。理论干净，进生产还差真实异构到达 + 抢占实现。  
**精读：** 只读问题建模，实现优先级低于 T2/T3/T6。

## 3. 关键趋势判断

**有没有新范式？有，而且已经过了口号期。**

1. **Harness 成为一等公民。**  
   训练对象不再只是 π(token | context)，而是 `π × harness × env`。Proxy-based RL（Lightning / Uni-Agent / AReaL / slime）正在变成默认。训练-部署 gap 从“prompt 不一致”升级为“工具循环不一致”。

2. **Inference 优化的主战场从 chatbot 切到 agent / RL rollout。**  
   普通 prefix cache、通用投机解码在 **大 batch + 工具交错 + schema 乱序** 下会失效。本周硬论文都在修这个失效模式，而不是再报一个 GSM8K 的 1.1×。

3. **“从研究走向工程”的信号是明确的：**
   - 有可跑的小框架（3500 行）而不是 20 个 abstraction layer。
   - 有生产 RL 框架接入（NeMo-RL + vLLM）。
   - 有负结果（Elastic KV vs chunked prefill），说明系统圈开始做减法。
   - SWE-bench 上 6K 样本 +14.6pt，说明 **数据效率已经够做内部试点**，不必等百万轨迹。

**未来 1–3 个月可能爆发：**
- vLLM/SGLang 上的 **agent-structure speculative decoding** 和 **schema-invariant KV**
- RL 训练环标配 **spec decode + async rollout**
- 内部平台出现 “Harness-as-artifact”：版本化、可 RL、可 JIT 生成
- 小模型 agent（4B–9B）靠 cached rollout / hybrid reward 接近大模型工具调用

不太可能爆发：又一个通用 PRM、又一个 multi-judge RLHF、又一个“agent skill 包装格式”。

## 4. 工程师行动建议（重点）

假设你做 **推理优化 / AI Infra / 分布式系统**。

### 本周最值得深入研究的 3 个方向

1. **Agent 工作负载的 Serving 语义（不是通用 LLM serving）**  
   优先：结构感知投机解码、tool-schema KV 可组合缓存、session/agent 级调度（SMetric / CacheSage 一类）。  
   原因：你们现有 prefix cache + continuous batching 的假设（共享前缀、稳定 decode）在 agent 上系统性失效。这是 1–3 个月能出线上收益的点。

2. **把 Inference 原语嵌进 RL 训练环**  
   优先：NeMo-RL 式 spec decode rollout、变长 multi-turn 的 advantage/loss 归一、动态 batch 调度。  
   原因：agentic RL 的墙钟时间 60%+ 在 rollout。加速 rollout 比再发明一个 GRPO variant 对集群利用率更直接。

3. **Harnessed RL 的系统契约**  
   优先：Lightning 的 proxy 协议——retokenize、sample merge、token-faithful 轨迹、k8s job 级 sandbox。  
   原因：这会决定你明年训练平台的 API。现在不读，三个月后会被业务方用“我们要在 Claude Code / 内部 harness 上做 RL”倒逼。

### 值得复现 / 读源码

| 优先级 | 对象 | 你要验证的东西 |
|---|---|---|
| P0 | Agent Lightning v1.0 + coding pipeline | 变长轨迹 advantage、reward hacking 防护、和现有 verl/sglang 的对接成本 |
| P0 | NeMo-RL speculative rollout | acceptance vs policy drift、同步/异步下的真实加速比 |
| P1 | AgentSpec（vLLM 实现） | 大 batch 下拒收率、和 EAGLE-3/MTP 谁叠得上 |
| P1 | ReCache | resource-wise attention 对质量的真实损伤、能否做成 serving 可选路径 |
| P2 | PuzzleKV | page-SVD 的 encode 开销是否吃掉带宽收益 |
| P2 | Progress Advantage | 用你们已有 RL checkpoint 抽 step score，看能否当 test-time / 归因信号 |

### 短期内不值得投入

- **再写一套 agent 框架 / 新 Skill 文件格式。** 评测不可比，线上没人换。
- **弹性 KV / 动态回收 prefill reserve。** 本周论文已经提示：chunked prefill 把大部分红利拿走了。
- **非可验证领域的 Reasoning-LLM-as-Judge 训练闭环。** 有论文明确说静态评测好看、进 policy 训练就不稳。
- **多目标 RLHF + Mixture of Judges 的理论变体。** 你们的生产问题是 rollout 成本和 harness gap，不是 judge 混合权重。
- **软 token / continuous CoT 推理。** 本周相关实验甚至显示 hard inference 仍然更好。别为这个改 kernel。

## 5. 风险与噪音分析

**本周最大噪音：Agent Skills / Harness 包装文。**  
论文多、图好看、bench 分数跳 10–20 分，但变量全搅在一起（模型、工具集、步数、评测 harness）。对 Infra 工程师几乎没有可迁移的接口或 kernel。JIT-Agent 是这个池子里少数有协议定义的，其余当新闻看。

**第二噪音：GRPO/DAPO 的局部修补。**  
SALT 这类“同样 rollout 数如何更有信息量”还可以看一眼；只改 baseline / clip 系数的，性价比低。

**最有潜力但论文还不多：**
- **Agent 批推理的投机解码**（AgentSpec 几乎是本周唯一硬做的）
- **RL 训练中的无损加速**（spec decode、cached tool rollout、acceptance 随 policy 在线适配）
- **组合不变的 KV / 资源级缓存**（ReCache 刚冒头，serving 引擎还没标准化）
- **负结果系统论文**（Elastic KV）：能帮你砍项目，比再多一篇 +3% 更值钱

**决策一句话：**  
这周不要去追“更聪明的 agent 算法”，去追 **harness 进训练环** 和 **agent 负载下 cache/speculate/schedule 假设的破产修复**。前者决定你的训练平台 API，后者决定你的 GPU 利用率。其余大部分是可延迟阅读的噪音。
