## 1. 本周趋势总结

**论文最多的方向：Agent + Agentic RL，而不是纯 chat 推理。**  
本周高密度题目集中在：long-horizon agent RL 的 credit assignment、tool-integrated RL、coding-agent harness、KV 在 agent 负载下的失效。ALFWorld / WebShop / SearchQA / EdgeBench 反复出现，说明社区默认评测已经从 GSM8K 挪到多步环境。

**明显升温**

1. **Agentic serving，而不是 generic LLM serving**  
   核心问题从 “prefix cache + paged attention” 变成：tool wait 时 KV 占 HBM、phase 切换破坏 recency eviction、跨 turn 压缩态如何持久化。AgentKV、Ask the Tool、edge scheduling 都在打同一块骨头。

2. **Agentic RL 的“信号拆解”，而不是再发一篇 GRPO 变体**  
   BATON / UnifiedPlayers / Reach-or-Solve / GACA / RetireOPD：都在拆 intra-traj vs inter-traj、reach vs solve、teacher vs environment。这是工程上真正值钱的部分——reward 管线怎么设计，而不是又一个 advantage 公式。

3. **用 agent 去优化 inference 系统本身**  
   RoofLang、SoL-Pi、InferenceBench 一脉：profiling-bound search 不够，要有可验证 mutation space / harness 层递归改进。研究正在把 “optimizer agent” 塞进 serving 架构循环。

**明显降温（对你这个岗位）**

- 再发一遍 “4-bit 量化差不多能用” 的单点论文：本周质量测量论文已经说明 4-bit 在散文上几乎无差、在 math 上差，这个结论足够用，不必再跟。
- 纯 chatbot 前缀缓存 / 通用 speculative decoding 故事：增量小，agent 负载已经把它打穿。
- 哲学化 alignment / “RLHF 是不是 utilitarian”：对本周 infra 决策几乎零接口。

**活跃度粗排序（本周、按与你岗位相关度）**  
LLM Agents ≈ Agentic RL > Inference/KV for agents > AI Infra / scheduling > SFT/Alignment 理论。  
SFT/RLHF 本周不是没论文，而是**工程可执行增量弱**，多数是理论修正或 judge 校准。

## 2. 重点论文（Top List）

按“该不该花工程师时间”排序，不是引用潜力。

### T1. AgentKV: Phase-Aware KV Eviction for Agentic LLMs  
`arXiv:2609.14872` · 2026-09-14

- **一句话**：Agent 的 think/act/tool 查询子空间不同，用最近 token 当 eviction 代表会系统性丢掉下一阶段要用的 KV。
- **核心贡献**：按 phase 维护 query buffer，对 union 打分；落地到跨 turn 持久化 + 在线 compact 的 serving path；相对 R-KV / Tri-attention 任务分 +5.x，相对 full-KV SGLang decode 吞吐最高 **1.80×**。
- **工程价值：高。** 直接挂 SGLang 类引擎。Agent 流量一旦占主，这是本周最该读源码的 KV 工作。
- **精读：是。复现：是（有代码）。**

### T2. Ask the Tool, Don't Guess  
`arXiv:2609.18849` · 2026-09-16

- **一句话**：tool 调用期间 serving 在猜剩余时间来决定 KV 去留，但 tool 自己其实知道进度。
- **核心贡献**：让 tool 上报 progress（剩余比例 / near-end）；harness 层抽取、对 agent 分数无感；p90 post-tool TTFT 相对 LRU 降约 **20.7–20.8%**，接近 oracle。
- **工程价值：很高，改动面小。** 这是 runtime 协议问题，不是模型问题。值得做成内部 RFC：tool schema 加 progress 字段。
- **精读：是。复现：优先读 serving 接入段。**

### T3. RoofLang: AI-Driven Architecting of LLM Inference Systems  
`arXiv:2609.12551` · 2026-09-11（窗口边缘，但本周持续被讨论）

- **一句话**：profiling 只能在现有软件栈里搜；要搜新架构需要 workload DSL + 可验证 mutation + 实现无关 evaluator。
- **核心贡献**：指出 DeepSeek V4 系因紧凑 KV 设计，峰值 decode 可比其它代表模型高 **3.5–39.5×**；optimizer agent 在 B300 上再挖出 **6–50%** 吞吐/交互性架构。
- **工程价值：中高（思想），落地慢。** 立刻能用的是“KV 形态 > 参数量”这个选型结论；DSL 本身要自建评测循环才有意义。
- **精读：读系统假设和 evaluator，不必跟实现。**

### T4. SSD-LLaMA: SSD-Native Inference for Trillion-Param MoE  
`arXiv:2609.18110` · 2026-09-16

- **一句话**：不做 expert 剪枝，用 SSD I/O pipeline + 三层存储 + CPU–GPU hybrid，消费级机跑万亿 MoE 到 **>1 tok/s**（RTX 5090 + ≤32GB RAM）。
- **核心贡献**：expert delivery 的 I/O 调度，而不是又一个 offload 包装。prefill **1.5–4.2×**、decode **2.1–15.6×** vs 评测基线。
- **工程价值：中（产品线相关才高）。** 如果你做边缘/本地 MoE 或冷 expert，值得拆 I/O 队列；集群 HBM serving 优先级低于 T1/T2。
- **精读：只读 I/O 与三级缓存设计。**

### T5. The Inference Engineering Pareto Atlas  
`arXiv:2609.17863` · 2026-09-15

- **一句话**：54 个 Qwen2.5-7B + vLLM 配置锚点校准模拟器，画 cost/quality/latency Pareto，而不是再报一个 isolated speedup。
- **核心贡献**：组合优化上 Pareto 的次数高于单点；AWQ-4bit 在 L4 延迟到 0.34× baseline，但 GSM8K 掉 5.9%，卡在 95% 质量门槛边缘；H100 赢紧延迟，A100 赢吞吐/成本（约 $0.106 / M tok）。
- **工程价值：高（决策工具，不是新算法）。** 内部容量规划应抄这个方法论，不要抄具体数字。
- **精读：方法部分。复现：用你自己的模型和流量重跑，不要信表。**

### T6. A Calibrated Instrument for Measuring Inference Opt Quality  
`arXiv:2609.18005` · 2026-09-16

- **一句话**：用校准过的 LLM-as-judge 测量化/early-exit/spec decode 对质量的真实伤害，精度到 ±0.3。
- **核心贡献**：4-bit 在英/中散文与 16-bit 不可区分；3-bit 和 early-exit 在 math 上崩（27 题对 19 → 6）。token 置信度能预测“会不会和满精度不同”，**不能预测质量伤不伤**。
- **工程价值：高（门禁）。** 立刻改内部 acceptance：别用 token confidence 当质量代理。
- **精读：实验设计。不必复现全部。**

### T7. SoL-Pi: Recursively Scaling Auto-Research Loops for Agent Harness  
`arXiv:2609.20519` · HF #2 of the day · NVIDIA

- **一句话**：在 harness 层做 RSI 式自动研究循环，筛出 4 个可迁移机制（执行、context compaction、observation、delegated reading）。
- **核心贡献**：EdgeBench 51 task，性能贴近 Pi，token 流量 **-44.7–49.0%**，API 成本约 **-1/3**。
- **工程价值：高（coding agent 产品）。** 这是“省 token 的 harness”，比再训一个 7B agent 更接近生产。
- **精读：四个 surviving mechanisms。复现：只迁 compaction / delegated reading。**

### T8. Dual-Axis Policy Optimization (BATON)  
`arXiv:2609.19830` · 2026-09-17

- **一句话**：Agent RL 要同时做 intra-traj 反馈归因 和 inter-traj 目标聚合；两者正交，合在一起最强。
- **核心贡献**：Bayesian Feedback Attribution + Trajectory Mass Normalization；叠在 GRPO / GiGPO 上，在 ALFWorld / WebShop / SearchQA 多尺度都涨。
- **工程价值：中。** 如果你已经在跑 agent GRPO，TMN（每条完整轨迹等优化质量）是最便宜可试的改动；Bayesian 归因实现成本更高。
- **精读：若你维护 RL 训练器。否则读 abstract + TMN 即可。**

### T9. UnifiedPlayers  
`arXiv:2609.20089` · 2026-09-17

- **一句话**：Planning / Execution / Evaluation 三个 player 在 GRPO 下共训，用可执行 verifier 替代静态 verifier 和自洽奖励。
- **核心贡献**：数学 / 通识推理至少 +3.5 / +3.9；学到的 verifier 对抗检测 84.2%，reward 方差是 self-consistency 的 **2.03×**。
- **工程价值：中。** “让 verifier 可执行且跟着失败模式进化” 比三角色叙事更有用。训练协调成本高，不适合小团队从零做。
- **精读：reward 设计，不精读三角色包装。**

### T10. Reach or Solve? Checkpoint Handoffs  
`arXiv:2609.19636` · 2026-09-17

- **一句话**：Agent RL 涨分混了两件事：更能走到近成功态（REACH），以及在同一克隆态上更能收尾（SOLVE）。
- **核心贡献**：SFT/RL 角色交叉；RL 历史对 RL solver 比对 SFT solver 更值钱；ALFWorld 上 SFT solver 从未在 RL solver 失败处成功。
- **工程价值：中高（评测/归因）。** 立刻改你的 agent RL dashboard：不要只报终局 success。
- **精读：实验协议。** 这是诊断工具，不是训练算法。

**本周看到但未进 Top10 的有用信号**

- Sample-count ≠ test-time scaling 成本：同样 N=8，`1×8` batched 比 `8×1` serial 能耗/P95 差 4–6×。调度论文，该进容量手册。
- LAST-CQ：agent 纠错增益主要来自 “失败就重试”，不来自反馈文案精致或并行采样。别在 feedback prompt 上烧预算。
- Paper2Agent（Nature，9/16）：论文→MCP server。对 infra 工程师是生态信号，不是 serving 算法。

## 3. 关键趋势判断

**有没有新范式？有，但是工程范式，不是新模型范式。**

1. **Workload assumption 切换：chatbot → agentic multi-phase + tool-blocked decode。**  
   前缀缓存、recency eviction、固定 tool-latency 估计，三条默认假设本周都被点名打穿。

2. **优化对象上移一层：从 kernel / quant 到 harness + serving policy。**  
   SoL-Pi、Ask the Tool、RoofLang 都在说：下一档收益在控制面（何时 evict、何时 compact、何时重试），不在再写一个 attention kernel。

3. **Agent RL 从“调 advantage”进入“拆增益来源”。**  
   REACH/SOLVE、intra/inter、teacher retire：说明 GRPO 已经够用到必须做因果拆解，否则论文和产线都会把“走到了好状态”误读成“决策变强了”。

**研究 → 工程的信号（本周比较硬）**

- 多篇直接改 **SGLang / vLLM 路径**，给吞吐数字，不只给 benchmark score。
- MLPerf Inference v6.1 首次把 **agentic workload** 放进数据中心提交；开分区已经在用万亿 MoE 跑 agent replay。这是需求侧确认，不是实验室自嗨。
- Coding-agent harness 开始用 token 流量和 API 成本做主指标（SoL-Pi），说明产品约束已经反压研究指标。

**未来 1–3 个月可能爆发**

| 方向 | 为什么会爆 |
|---|---|
| Phase-aware / tool-aware KV | agent QPS 上来就会成为默认必选项 |
| Tool progress 协议 | 改动小、收益实、可标准化进 MCP/OpenAPI |
| Harness 级 context compaction | 比训模型便宜一个数量级 |
| Agent RL 诊断协议（reach/solve） | 训练团队会被“虚高 success”反噬，工具需求刚 |
| Inference 质量门禁（校准 judge） | 量化/early-exit 要进生产必须过这一关 |

不会爆（短期）：新 alignment 损失、又一个 multi-agent 编排框架、Flash/CIM 特种硬件算法（除非你就是做那块硬件）。

## 4. 工程师行动建议（重点）

假设你做 **推理优化 / AI Infra / 分布式系统**。

### 本周最值得深入研究的 3 个方向

1. **Agentic KV 生命周期**  
   相位感知 eviction + tool-wait 期间的 cache 去留 + 跨 turn compact。  
   这是你岗位和本周论文重叠最大的区域，3 个月内会被业务倒逼。

2. **Serving 控制面，而不是算子**  
   tool progress hint、post-tool TTFT、batched vs serial test-time sampling、KV-memory-time 作为负载指标。  
   收益来自调度和协议，不来自再卷 kernel。

3. **把 agent RL 训练负载当成一等 serving workload**  
   多轨迹、长 horizon、tool 密集、reward 稀疏。你的集群很快会同时伺候在线 agent 和离线 GRPO rollout。BATON 的 TMN、Reach/Solve 拆分，决定你怎么做 batch、怎么做 checkpoint eval。

### 值得复现 / 读源码

| 优先级 | 论文 | 读什么 |
|---|---|---|
| P0 | AgentKV | SGLang 持久化路径、phase buffer、page compact |
| P0 | Ask the Tool | tool progress → KV 决策的那几个 hint |
| P1 | SoL-Pi | context compaction + delegated reading（不要复现整个 RSI 循环） |
| P1 | Pareto Atlas | 用自家模型和 GPU 重跑模拟器校准，不要抄表 |
| P2 | BATON | 只实现 Trajectory Mass Normalization |
| P2 | SSD-LLaMA | 仅当你做本地/边缘 MoE |

### 短期内不值得投入

- **再做一个通用 KV eviction scoring**，如果不显式建模 agent phase / tool。会被 AgentKV 这类工作直接盖住。
- **Speculative decoding / 3-bit 极限量化作为主项目**：质量门禁论文已经说明伤害是 domain-dependent，math/agent 工具链上不划算。
- **Multi-agent 编排框架、Paper2Agent 类“论文变 MCP”**：生态热闹，不解决你的 GPU 利用率。
- **RLHF distortion / Bayesian 统一 ICL-SFT-RL 理论**：好看，改不了这季度的 serving SLA。
- **为了发论文去堆 GRPO 变体**：本周真正增量在归因和 verifier，不在 advantage 代数。

### 本周可执行的 3 个内部动作

1. 给线上 agent tool schema 加 **progress / near-complete** 字段，调度先吃 LRU 对照。  
2. KV 评测集从 ShareGPT 换成 **think/act/tool 分段 trace**，否则你在优化错误负载。  
3. 量化/early-exit 门禁按域拆：散文 / 中文 / 多步数学 / agent 工具调用，禁止用单一 MMLU 放行。

## 5. 风险与噪音分析

### 本周最大噪音方向

**“Agent 框架 / 自进化 / 多 player 合作”叙事过多，可迁移增量少。**  
UnifiedPlayers、各类 auto-research loop、computer-use harness 论文数量上来了，但大量工作：

- 评测仍锁在 ALFWorld / WebShop；
- 把编排复杂度包装成方法；
- 没有 serving 数字、没有失败模式、没有和 vLLM/SGLang 的接口。

对 infra 工程师：把这些当 **产品经理通讯稿** 扫标题即可，不要开课题。

次级噪音：**孤立 speedup 数字**（“我们 2.x×”）却不报质量地板、GPU 型号、batch、是否 agent 负载。Pareto Atlas 和校准 judge 两篇存在的意义，就是指出这类数字不可比。

### 本周最有潜力但论文不多的方向

1. **Tool-runtime ↔ serving 的双向协议**（Ask the Tool 几乎是孤例）。标准化后全行业吃同一份红利。  
2. **Agent RL 增益归因协议**（Reach/Solve）。论文少，但每个训练团队都会需要，否则你无法决定“继续 RL 还是补 SFT 覆盖”。  
3. **实现无关的 inference architecture search**（RoofLang）。现在还像研究原型，但这是唯一能跳出 “在 vLLM 里调参” 局部最优的路。  
4. **Test-time scaling 的能量/尾延迟会计**（N=8 的 1×8 vs 8×1）。几乎没人把它写进容量模型，但 agent 并行采样会迅速把它变成账单问题。

---

**一句话决策**：本周不要去追新模型和新 alignment loss。把时间压在 **agent 负载下的 KV 与 tool 等待协议**，以及 **用校准过的质量/成本曲面做上线门禁**。这三件事 1–3 个月就会从论文变成 oncall。
